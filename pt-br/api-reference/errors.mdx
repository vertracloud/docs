## Como é um erro?

Todo erro usa o mesmo envelope, descrito na [introdução da API](/pt-br/api-reference/introduction#como-é-uma-resposta). O status HTTP indica a categoria, `code` é uma string estável, segura para usar em condicionais, e `details` — quando presente — traz os números necessários para agir (um limite, um tempo de espera, o escopo que falta).

```json
{
  "code": "ERROR_CODE",
  "message": "Optional descriptive message",
  "details": { "retry_after": 30 }
}
```

`message` é para humanos e pode mudar; nunca tome decisões no seu código com base nela. Para problemas de deploy e de execução que não vêm da própria API (loops de falha, dependências ausentes, OOMKilled), veja [Erros comuns](/pt-br/common-errors) — esta página cobre apenas os valores `code` estáveis com que a API responde.

<Note>
  `VALIDATION_ERROR` (`400`) cobre problemas de formato da requisição em todas as rotas — um campo obrigatório ausente, o tipo errado, um valor fora da faixa. `details.path` indica o campo com problema, por exemplo
  `"memory"` ou `"user.name"`.
</Note>

## Autenticação e chaves de API

| Status | Código | Significado e correção |
|---|---|---|
| 401 | `AUTH_TOKEN_MISSING` | Nenhum cabeçalho `Authorization` foi enviado. Adicione `Authorization: Bearer <key>`. |
| 401 | `API_KEY_INVALID` | A chave não existe ou o segredo não confere. Verifique o valor da chave ou crie uma nova no dashboard. |
| 401 | `SESSION_REVOKED` | A sessão do dashboard por trás do token expirou ou foi revogada (saiu da conta ou foi encerrada na lista de sessões). Entre de novo. |
| 401 | `USER_NOT_FOUND` | O usuário autenticado não existe mais (raro — geralmente uma conta excluída). |
| 403 | `API_KEY_IP_DENIED` | O IP da requisição não está nos `allowed_ips` da chave. Adicione o IP/CIDR de quem chama à chave, ou limpe a lista para permitir qualquer IP. |
| 403 | `API_KEY_MANAGED` | A chave foi criada pela plataforma para uma stack. Ela não pode ser editada; é revogada junto com a stack. |
| 403 | `API_KEY_SCOPE_DENIED` | A chave não tem o escopo que a rota exige (`details.required`), ou a rota é apenas por sessão do dashboard. Veja [Escopos](/pt-br/api-reference/introduction#escopos). |
| 403 | `WEBSITE_ONLY` | A rota aceita apenas uma sessão do dashboard. Chaves de API normalmente recebem `API_KEY_SCOPE_DENIED` primeiro nessas rotas; `WEBSITE_ONLY` é a segunda verificação, depois dela. Nenhum escopo libera a ação — use o dashboard. |
| 403 | `ACCESS_DENIED` | O recurso existe, mas sua conta não pode agir sobre ele. Confirme que você é o dono do recurso ou que tem a permissão de workspace correta. |
| 403 | `ACCOUNT_BANNED` | A conta foi banida. Entre em contato com o suporte. |
| 403 | `APP_BANNED` | A aplicação foi banida. Entre em contato com o suporte. |
| 403 | `DATABASE_BANNED` | O banco de dados foi banido. Entre em contato com o suporte. |
| 403 | `APP_SHIELD_COOLDOWN` | O Vertra Shield pausou a aplicação após tráfego abusivo; `details` indica o motivo e o fim do cooldown. Aguarde o fim da pausa e corrija a origem do tráfego; start, restart, deploy, configuração e exclusão continuam bloqueados até lá. Veja [Erros comuns](/pt-br/common-errors#proteções-da-plataforma). |
| 404 | `USER_LIMITS_NOT_FOUND` | Não foi possível determinar os limites do plano da conta. Entre em contato com o suporte. |

### Códigos de falha de build

Quando um build ou uma instalação falha, `GET /v1/apps/{id}` retorna o código em `last_build_error` (`null` após um build bem-sucedido); o detalhe está nos logs da aplicação.

| `last_build_error` | O que fazer |
|---|---|
| `INSTALL_OUT_OF_MEMORY` | Aumente a memória da aplicação e tente de novo. |
| `BUILD_FAILED` / `INSTALL_FAILED` | Leia os logs e corrija o projeto. |
| `BUILD_TIMEOUT` / `INSTALL_TIMEOUT` | Deixe o build ou a instalação mais curtos. |
| `BUILD_INTERRUPTED` | Tente de novo. |
| `INSTALL_SHIELD_BLOCKED` | A proteção de rede bloqueou o tráfego durante o build; reduza o tráfego que o build gera. |

## Geral

| Status | Código | Significado e correção |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Um parâmetro, query ou campo do corpo falhou na validação; `details.path` indica o campo. |
| 400 | `INVALID_PARAMS` / `INVALID_PAYLOAD` / `INVALID_RANGE` | O formato da requisição ou um campo específico é inválido para esta rota. |
| 403 | `FORBIDDEN` | A conta não tem permissão para executar esta ação neste recurso. |
| 400 | `MISSING_HEADERS` | Um cabeçalho exigido pela rota não foi enviado. |
| 400 | `INVALID_JSON` | O corpo não é um JSON válido (uma aspa ou vírgula faltando, uma vírgula sobrando, aspas simples). Valide o JSON e envie com `content-type: application/json`. |
| 400 | `EMPTY_BODY` | A requisição tem `content-type: application/json`, mas nenhum corpo. Envie um corpo JSON (`{}` se a rota não tiver campos obrigatórios), ou remova o cabeçalho `content-type` das requisições sem corpo. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | O `content-type` não é aceito pela rota. Envie JSON com `content-type: application/json`; as rotas de upload aceitam `multipart/form-data`. |
| 400 | `BAD_REQUEST` | A própria requisição está malformada de um jeito que nenhum outro código cobre, por exemplo um `Content-Length` que não corresponde ao corpo. Corrija a requisição e tente de novo. |
| 408 | `REQUEST_TIMEOUT` | O corpo da requisição não chegou a tempo. Tente de novo e verifique a conexão se isso se repetir. |
| 500 | `INTERNAL_SERVER_ERROR` | Algo falhou do lado da plataforma. Tente de novo; se persistir, entre em contato com o suporte informando o horário da requisição. |

<Note>
  Este catálogo lista todos os códigos do contrato público da API. Uma rota ainda pode responder outros erros HTTP padrão
  (como um `404` genérico para um caminho desconhecido) que não trazem nenhum destes valores de `code`.
</Note>
