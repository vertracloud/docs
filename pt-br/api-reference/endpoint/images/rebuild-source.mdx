api: POST https://api.vertracloud.app/v1/images/{image_id}/rebuild
authMethod: bearer
description: Constrói a imagem de novo sem enviar nada, a partir do contexto de build guardado ou da branch do GitHub vinculada.
---

{/* @see APICustomImage, RESTPostAPICustomImageRebuildResult — @vertracloud/api-types */}
A requisição não tem corpo. A fonte depende da imagem: uma imagem vinculada ao GitHub é construída a partir da ponta atual da branch vinculada; qualquer outra imagem é construída a partir do contexto do último build, **inclusive de um build que falhou**. Use para repetir um build que falhou sem enviar os arquivos de novo.

A reconstrução mantém o mesmo ID da imagem e, quando dá certo, adiciona uma nova [versão](/pt-br/api-reference/endpoint/images/versions). Ela conta no limite de deploys por hora como qualquer outro build, e uma reconstrução que falha mantém a versão atual. **As aplicações só são reiniciadas se a imagem estiver com `auto_update_apps` ligado**; caso contrário, cada app passa para a nova versão no próximo restart ou deploy que você pedir. Para construir com outros arquivos, use [Reconstruir imagem](/pt-br/api-reference/endpoint/images/rebuild).

Precisa do escopo `images:write` quando chamada com uma chave de API.

<ParamField path="image_id" type="string" required>
  O ID da imagem.
</ParamField>

<ParamField query="workspace_id" type="string">
  Se a imagem pertencer a um workspace, o ID do workspace. Obrigatório para membros do workspace que agem sobre uma imagem que não é deles.
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  A imagem. A resposta é `202 Accepted` com `status: "building"`.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    O ID da imagem.
  </ResponseField>

  <ResponseField name="name" type="string">
    O nome da imagem.
  </ResponseField>

  <ResponseField name="description" type="string | null">
    A descrição da imagem (texto livre, até 128 caracteres), ou `null` quando ela não tem uma.
  </ResponseField>

  <ResponseField name="owner" type="string">
    `account` para as suas imagens, `system` para imagens fornecidas pela plataforma (estas não podem ser alteradas nem apagadas).
  </ResponseField>

  <ResponseField name="status" type="string">
    Estado do build mais recente: `building`, `success` ou `failed`. Uma reconstrução que falha não muda a versão atual: os apps continuam rodando a última versão que deu certo.
  </ResponseField>

  <ResponseField name="error" type="string | null">
    Motivo legível do último build que falhou, ou `null`.
  </ResponseField>

  <ResponseField name="digest" type="string | null">
    Digest (`sha256:...`) da versão atual, ou `null` enquanto nenhum build tiver dado certo.
  </ResponseField>

  <ResponseField name="uncompressed_bytes" type="integer | null">
    Tamanho da versão atual, descompactada, em bytes.
  </ResponseField>

  <ResponseField name="layer_count" type="integer | null">
    Número de camadas da versão atual.
  </ResponseField>

  <ResponseField name="apps" type="object[]">
    Os apps criados a partir desta imagem. Cada um tem `id`, `name`, `version_id` (a versão da imagem que ele executa, ou `null`) e `outdated` (`true` quando a imagem tem uma versão mais nova; o app passa para ela no próximo restart ou deploy que você pedir).
  </ResponseField>

  <ResponseField name="github" type="object | null">
    O repositório e a branch do GitHub vinculados (`repository` no formato `owner/name`, `branch`), ou `null` quando a imagem não está vinculada.
  </ResponseField>

  <ResponseField name="current_version_id" type="string | null">
    A versão atual da imagem, ou `null` enquanto nenhum build tiver dado certo.
  </ResponseField>

  <ResponseField name="created_at" type="string" format="date-time">
    Quando a imagem foi criada.
  </ResponseField>

  <ResponseField name="updated_at" type="string" format="date-time">
    Quando a imagem foi atualizada pela última vez.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `API_KEY_SCOPE_DENIED`: A chave de API não tem o escopo necessário (`403`).
  - `IMAGE_NOT_FOUND`: A imagem não existe (`404`).
  - `ACCESS_DENIED`: A imagem é de outra conta ou é fornecida pela plataforma, ou você é membro do workspace sem direito de reconstruí-la (`403`).
  - `IMAGE_TEMPLATE_ONLY`: A imagem veio de um template e não pode ser reconstruída (`409`).
  - `PLAN_REQUIRED`: O dono da imagem não tem plano ativo (`403`).
  - `PLAN_DOES_NOT_SUPPORT_CUSTOM_IMAGES`: O plano não inclui imagens Docker próprias (`403`).
  - `IMAGE_BUILD_IN_PROGRESS`: A imagem já tem um build em andamento (`409`).
  - `OPERATION_IN_PROGRESS`: A imagem está sendo excluída (`409`).
  - `IMAGE_NOT_READY`: A imagem não tem contexto de build guardado para construir (`409`).
  - `DEPLOY_RATE_LIMITED`: O limite de deploys por hora do dono da imagem foi atingido; `details` traz `limit`, `window_seconds` e `retry_after` (`429`).
  - `INSTALLATION_NOT_FOUND`: O repositório vinculado não está mais em uma instalação do GitHub App do dono da imagem (`404`).
  - `FETCH_ZIP_ERROR`: O GitHub não devolveu o arquivo do repositório, por exemplo porque a branch vinculada não existe mais (`404`), ou o GitHub está indisponível (`502`).
  - `DOCKERFILE_NOT_FOUND`: Não há um arquivo chamado exatamente `Dockerfile` na raiz do contexto (`400`).
  - `DOCKERFILE_REFUSED`: O `Dockerfile` tem uma instrução recusada; `details` lista os achados (`400`).
  - `INVALID_ZIP`: O contexto de build guardado ou o arquivo do repositório não é um ZIP legível (`400`).
  - `IMAGE_CONTEXT_TOO_LARGE`: O contexto de build passou de um limite: mais de 100 MB compactado, mais de 512 MB descompactado, mais de 50.000 entradas ou um `Dockerfile` maior que 1 MB (`413`).
  - `IMAGE_BUILDER_UNAVAILABLE`: Nenhum host pode construir imagens agora; tente de novo mais tarde (`503`). Também é retornado quando o build não pôde ser iniciado (`409`).
  - `INTERNAL_SERVER_ERROR`: Falha inesperada (`500`).
</ResponseField>
