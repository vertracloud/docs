---
title: Vincular imagem ao GitHub
sidebarTitle: Vincular GitHub
api: PUT https://api.vertracloud.app/v1/images/{image_id}/github
authMethod: bearer
description: Vincula uma imagem a um repositório do GitHub, para que um push na branch dele reconstrua a imagem.
---

{/* @see RESTPutAPICustomImageGithubBody, RESTPutAPICustomImageGithubResult — @vertracloud/api-types */}
O repositório precisa estar em uma das suas instalações do GitHub App. Um repositório público fora delas pode ser construído uma vez com [Criar imagem](/pt-br/api-reference/endpoint/images/create), mas só pode ser vinculado depois que você instalar o GitHub App nele. Um push na branch vinculada reconstrói a imagem exatamente como uma reconstrução manual, com o repositório nessa branch como contexto de build. Pushes são ignorados enquanto um build da imagem já estiver em execução. Reconstruções vindas do GitHub nunca reiniciam apps.

Só o dono da imagem pode vinculá-la. Em um workspace, um membro recebe `403` mesmo com permissão para gerenciar os apps do workspace, porque o vínculo usa as instalações do GitHub App do dono.

Precisa do escopo `images:write` quando chamado com uma chave de API.

<ParamField path="image_id" type="string" required>
  O ID da imagem.
</ParamField>

<ParamField query="workspace_id" type="string">
  Se a imagem pertencer a um workspace, o ID do workspace.
</ParamField>

<ParamField body="repository" type="string" required>
  O repositório, no formato `owner/name`.
</ParamField>

<ParamField body="branch" type="string">
  A branch que dispara a reconstrução. Opcional: sem ela, usa-se a branch padrão do repositório (`main`, `master` ou a que o repositório definir).
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  A imagem.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    O ID da imagem.
  </ResponseField>

  <ResponseField name="name" type="string">
    O nome da imagem.
  </ResponseField>

  <ResponseField name="description" type="string | null">
    A descrição da imagem (texto livre, até 128 caracteres), ou `null` quando ela não tem uma.
  </ResponseField>

  <ResponseField name="owner" type="string">
    `account` para as suas imagens, `system` para imagens fornecidas pela plataforma (estas não podem ser alteradas nem apagadas).
  </ResponseField>

  <ResponseField name="status" type="string">
    Estado do build mais recente: `building`, `success` ou `failed`. Uma reconstrução que falha não muda a versão atual: os apps continuam rodando a última versão que deu certo.
  </ResponseField>

  <ResponseField name="error" type="string | null">
    Motivo legível do último build que falhou, ou `null`.
  </ResponseField>

  <ResponseField name="digest" type="string | null">
    Digest (`sha256:...`) da versão atual, ou `null` enquanto nenhum build tiver dado certo.
  </ResponseField>

  <ResponseField name="uncompressed_bytes" type="integer | null">
    Tamanho da versão atual, descompactada, em bytes.
  </ResponseField>

  <ResponseField name="layer_count" type="integer | null">
    Número de camadas da versão atual.
  </ResponseField>

  <ResponseField name="apps" type="object[]">
    Os apps criados a partir desta imagem. Cada um tem `id`, `name`, `version_id` (a versão da imagem que ele executa, ou `null`) e `outdated` (`true` quando a imagem tem uma versão mais nova; o app passa para ela no próximo restart ou deploy que você pedir).
  </ResponseField>

  <ResponseField name="github" type="object | null">
    O repositório e a branch do GitHub vinculados (`repository` no formato `owner/name`, `branch`), ou `null` quando a imagem não está vinculada.
  </ResponseField>

  <ResponseField name="current_version_id" type="string | null">
    A versão atual da imagem, ou `null` enquanto nenhum build tiver dado certo.
  </ResponseField>

  <ResponseField name="created_at" type="string" format="date-time">
    Quando a imagem foi criada.
  </ResponseField>

  <ResponseField name="updated_at" type="string" format="date-time">
    Quando a imagem foi atualizada pela última vez.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `API_KEY_SCOPE_DENIED`: A chave de API não tem o escopo necessário (`403`).
  - `ACCESS_DENIED`: Você não é o dono da imagem, ou ela é uma imagem da plataforma (`403`).
  - `IMAGE_NOT_FOUND`: A imagem não existe ou você não tem acesso a ela (`404`).
  - `VALIDATION_ERROR`: O corpo falhou na validação, por exemplo um `repository` que não está no formato `owner/name` (`400`).
  - `INSTALLATION_NOT_FOUND`: O repositório não está em nenhuma das suas instalações do GitHub App (`404`).
  - `REPO_ALREADY_LINKED`: O repositório já está vinculado a outra imagem ou app (`409`).
  - `FETCH_ZIP_ERROR`: O GitHub não pôde ser acessado, ou estava limitando requisições enquanto o repositório era verificado (`502`). Tente de novo em alguns minutos.
  - `PLAN_DOES_NOT_SUPPORT_CUSTOM_IMAGES`: O plano não inclui imagens Docker personalizadas (`403`).
  - `INTERNAL_SERVER_ERROR`: Falha inesperada (`500`).
</ResponseField>
