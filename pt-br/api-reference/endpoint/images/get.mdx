---
title: Obter imagem
sidebarTitle: Obter imagem
api: GET https://api.vertracloud.app/v1/images/{image_id}
authMethod: bearer
description: Retorna uma imagem Docker personalizada pelo seu ID, com a versão atual e as aplicações que a usam.
---

{/* @see APICustomImage, RESTGetAPICustomImageResult — @vertracloud/api-types */}
Exige o escopo `images:read` quando chamada com uma chave de API.

<ParamField path="image_id" type="string" required>
  O ID da imagem.
</ParamField>

<ParamField query="workspace_id" type="string">
  Se a imagem pertencer a um workspace, o ID do workspace. Obrigatório para membros do workspace que atuam sobre uma imagem que não lhes pertence.
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  A imagem.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    O ID da imagem.
  </ResponseField>

  <ResponseField name="name" type="string">
    O nome da imagem.
  </ResponseField>

  <ResponseField name="description" type="string | null">
    A descrição da imagem (texto livre, de até 128 caracteres), ou `null` quando não tem uma.
  </ResponseField>

  <ResponseField name="owner" type="string">
    `account` para as suas imagens, `system` para imagens fornecidas pela plataforma (estas não podem ser alteradas nem excluídas).
  </ResponseField>

  <ResponseField name="kind" type="string">
    `own` para uma imagem que você criou, ou `template_copy` para a cópia da imagem de um template que [usar um template](/pt-br/templates/use/using-a-template) colocou na sua conta. Uma cópia ocupa um slot de imagem e só pode ser usada por meio do seu template.
  </ResponseField>

  <ResponseField name="origin" type="object | null">
    Para um `template_copy`, o template de origem: `template_id`, `template_name` (por idioma) e `author_display` (`null` para um template da plataforma). `null` para as suas próprias imagens.
  </ResponseField>

  <ResponseField name="status" type="string">
    Estado do build mais recente: `building`, `success` ou `failed`. Um rebuild que falha não altera a versão atual: as aplicações continuam rodando a última versão boa.
  </ResponseField>

  <ResponseField name="error" type="string | null">
    Motivo legível do build mais recente que falhou, ou `null`.
  </ResponseField>

  <ResponseField name="digest" type="string | null">
    Digest (`sha256:...`) da versão atual, ou `null` enquanto nenhum build teve sucesso.
  </ResponseField>

  <ResponseField name="uncompressed_bytes" type="integer | null">
    Tamanho da versão atual, descompactada, em bytes.
  </ResponseField>

  <ResponseField name="layer_count" type="integer | null">
    Número de camadas da versão atual.
  </ResponseField>

  <ResponseField name="suggested_port" type="integer | null">
    Porta sugerida para uma nova aplicação nesta imagem: o primeiro `EXPOSE` do `Dockerfile` do contexto do build mais recente, ou `80`. `null` para uma imagem criada antes deste campo existir.
  </ResponseField>

  <ResponseField name="apps" type="object[]">
    As aplicações criadas a partir desta imagem. Cada uma tem `id`, `name`, `version_id` (a versão da imagem que ela executa, ou `null`) e `outdated` (`true` quando a imagem tem uma versão mais nova; a aplicação passa para ela no próximo restart ou deploy que você pedir).
  </ResponseField>

  <ResponseField name="github" type="object | null">
    O repositório e o branch do GitHub vinculados (`repository` como `owner/name`, `branch`), ou `null` quando a imagem não está vinculada.
  </ResponseField>

  <ResponseField name="current_version_id" type="string | null">
    A versão atual da imagem, ou `null` enquanto nenhum build teve sucesso.
  </ResponseField>

  <ResponseField name="created_at" type="string" format="date-time">
    Quando a imagem foi criada.
  </ResponseField>

  <ResponseField name="updated_at" type="string" format="date-time">
    Quando a imagem foi atualizada pela última vez.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `API_KEY_SCOPE_DENIED`: A chave de API não tem o escopo exigido (`403`).
  - `IMAGE_NOT_FOUND`: A imagem não existe ou você não tem acesso a ela (`404`).
  - `INTERNAL_SERVER_ERROR`: Falha inesperada (`500`).
</ResponseField>

<ResponseExample>

```json Error Response
{
  "code": "IMAGE_NOT_FOUND"
}
```

</ResponseExample>
