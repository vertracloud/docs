api: PUT https://api.vertracloud.app/v1/databases/{id}
authMethod: bearer
description: Atualiza o nome, a descrição ou a RAM de um banco de dados pelo seu ID.
---

{/* @see APIDatabase — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID do banco de dados a atualizar.
</ParamField>


<ParamField query="workspace_id" type="string">
  Se o banco de dados pertencer a um workspace, o ID do workspace.
</ParamField>

<ParamField body="name" type="string">
  O novo nome do banco de dados. De 1 a 50 caracteres.
</ParamField>

<ParamField body="description" type="string | null">
  A nova descrição, de até 128 caracteres. Uma string vazia ou `null` a remove.
</ParamField>

<ParamField body="ram" type="number">
  A nova RAM em MB, um inteiro positivo. Ela precisa caber na memória livre do plano e respeitar o mínimo do motor (512 MB para Redis, 1.024 MB para os demais). Mudar a memória vale na hora, ao subir ou ao baixar. Se o banco estiver usando mais memória do que o novo limite naquele momento, ele é encerrado por falta de memória; o painel avisa e pede confirmação antes de salvar. O armazenamento do banco acompanha a memória, então baixar a memória de um banco que guarda mais dados do que o novo armazenamento comporta é recusado com `409` `STORAGE_ABOVE_NEW_LIMIT`.
</ParamField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `VALIDATION_ERROR`: Um campo do body ou da query falhou na validação (`400`).
  - `INVALID_RAM_LIMIT`: A RAM solicitada está fora do que o motor e o plano permitem (`400`).
  - `MEMORY_LIMIT_EXCEEDED`: O plano não tem memória livre suficiente para a nova RAM (`400`).
  - `ACCESS_DENIED`: Você é membro de um workspace sem a permissão para esta ação, ou não enviou o `workspace_id` (`403`).
  - `DATABASE_NOT_FOUND`: O banco de dados não foi encontrado (`404`).
  - `OPERATION_IN_PROGRESS`: Outra operação de ciclo de vida está em execução neste banco de dados (`409`).
  - `STORAGE_ABOVE_NEW_LIMIT`: O banco guarda mais dados do que o armazenamento que a nova RAM comporta (`409`). Nada foi alterado.
</ResponseField>

<ResponseField name="details" type="object">
  Presente em `STORAGE_ABOVE_NEW_LIMIT`. Traz `used_mb`, `limit_mb` e `free_mb`: quanto o banco guarda, o armazenamento que a RAM solicitada comportaria e quanto é preciso apagar antes que a alteração seja aceita.
</ResponseField>

<ResponseExample>

```json Error Response (404)
{
  "code": "DATABASE_NOT_FOUND"
}
```

```json Error Response (409)
{
  "code": "STORAGE_ABOVE_NEW_LIMIT",
  "details": {
    "used_mb": 9216,
    "limit_mb": 8192,
    "free_mb": 1024
  }
}
```

</ResponseExample>
