<ParamField path="id" type="string" required>
  O ID do banco de dados do qual obter o certificado.
</ParamField>

### Resposta

A resposta é um objeto JSON com os componentes do certificado em PEM para a conexão TLS com o banco de dados, além da CA e de um bundle PKCS#12 quando o banco de dados os tiver.

<ResponseField name="response" type="object">
  Os detalhes do certificado para conexões seguras com o banco de dados.

  <Expandable title="Mostrar objeto">

  <ResponseField name="crt" type="string">
    O certificado do cliente. Use-o com `key` para a autenticação TLS do cliente.
  </ResponseField>

  <ResponseField name="key" type="string">
    A chave privada do certificado do cliente. Use-a com `crt` para a autenticação TLS do cliente.
  </ResponseField>

  <ResponseField name="pem" type="string">
    Um único arquivo PEM com a chave privada do cliente, o certificado do cliente e o certificado da CA, nessa ordem. Use-o quando um driver quiser um único arquivo de cliente combinado; para verificar a cadeia de certificados do servidor, use a parte da CA.
  </ResponseField>

  <ResponseField name="ca" type="string">
    O certificado da CA (PEM) que assina o certificado do servidor do banco de dados, sozinho. Use-o para verificar a cadeia de certificados do servidor. Ausente em bancos de dados mais antigos; a CA continua sendo a última parte de `pem`.
  </ResponseField>

  <ResponseField name="p12" type="string">
    A identidade do cliente em PKCS#12, codificada em base64, com senha vazia. Decodifique-a para um arquivo `.p12` para drivers que aceitam apenas uma identidade PKCS#12, como o Prisma 6. Ausente em bancos de dados mais antigos.
  </ResponseField>

  </Expandable>
</ResponseField>

### Uso

Todos os motores exigem TLS **e** o certificado do cliente. Salve cada campo em um arquivo:

| Campo | Salvar como | Conteúdo |
|---|---|---|
| `crt` | `certificate.crt` | Certificado do cliente |
| `key` | `certificate.key` | Chave privada do cliente |
| `pem` | `certificate.pem` | Chave do cliente + certificado do cliente + a CA que assina o servidor |
| `ca` | `ca.pem` | A CA que assina o servidor (quando presente) |
| `p12` | `certificate.p12` (decodifique o base64 antes) | Identidade do cliente em PKCS#12, senha vazia (quando presente) |

Use `ca.pem` (ou `certificate.pem`, que termina com a mesma CA) como arquivo de CA e, no MongoDB, `certificate.pem` como arquivo de certificado com chave. Use
`certificate.crt` + `certificate.key` como certificado do cliente, ou `certificate.p12` quando o driver aceitar apenas uma identidade PKCS#12 (Prisma 6, com senha vazia). A porta é única por banco de dados — leia-a em [Obter banco de dados](/pt-br/api-reference/endpoint/databases/get). Comandos e exemplos de driver para cada motor estão em [Como me conecto a cada motor?](/pt-br/databases#como-me-conecto-a-cada-motor).

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: O header `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: A chave de API é usada a partir de um IP fora da sua lista de IPs permitidos, ou não tem o escopo que a rota exige (`403`).
  - `ACCESS_DENIED`: O recurso pertence a outra conta, ou você não tem a permissão de workspace para ele (`403`).
  - `DATABASE_NOT_FOUND_OR_FORBIDDEN`: O banco de dados informado não existe ou o usuário não tem acesso.
  - `FAILED_TO_GET_CERTIFICATE`: Falha ao obter o certificado.
</ResponseField>

<ResponseField name="message" type="string">
  Uma mensagem descritiva com detalhes adicionais sobre o erro.
</ResponseField>
