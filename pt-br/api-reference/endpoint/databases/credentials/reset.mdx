---
title: Redefinir certificados do banco de dados
sidebarTitle: Redefinir certificados
api: POST https://api.vertracloud.app/v1/databases/{id}/credentials/certificate/reset
authMethod: bearer
description: Redefine os certificados de um banco de dados específico pelo seu ID.
---

{/* @see success — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID do banco de dados cujos certificados serão redefinidos.
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  Os novos detalhes do certificado do banco de dados.

  <Expandable title="Mostrar objeto">

  <ResponseField name="pem" type="string">
    O novo certificado PEM.
  </ResponseField>

  <ResponseField name="crt" type="string">
    O novo certificado CRT.
  </ResponseField>

  <ResponseField name="key" type="string">
    A nova chave privada do certificado.
  </ResponseField>

  <ResponseField name="ca" type="string">
    O certificado da CA (PEM) que assina o certificado do servidor do banco de dados. Ausente em bancos de dados mais antigos.
  </ResponseField>

  <ResponseField name="p12" type="string">
    A nova identidade do cliente em PKCS#12, codificada em base64, com senha vazia. Ausente em bancos de dados mais antigos.
  </ResponseField>

  <ResponseField name="restart_required" type="boolean">
    `true` quando pelo menos uma aplicação de uma stack conectada precisa reiniciar para ler os novos certificados.
  </ResponseField>

  <ResponseField name="apps_to_restart" type="string[]">
    Os IDs dessas aplicações. Vazio quando `restart_required` é `false`.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "pem": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "crt": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "key": "-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----",
    "ca": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "p12": "MIIJqQIBAzCCCW8GCSqGSIb3DQEHAaCCCWAEgglc...",
    "restart_required": false,
    "apps_to_restart": []
  }
}
```

</ResponseExample>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: O header `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: A chave de API é usada a partir de um IP fora da sua lista de IPs permitidos, ou não tem o escopo que a rota exige (`403`).
  - `ACCESS_DENIED`: O recurso pertence a outra conta, ou você não tem a permissão de workspace para ele (`403`).
  - `DATABASE_NOT_FOUND_OR_FORBIDDEN`: O banco de dados informado não existe ou o usuário não tem acesso.
  - `FAILED_TO_RESET_CERTIFICATES`: Falha ao redefinir os certificados.
</ResponseField>

<ResponseField name="message" type="string">
  Uma mensagem descritiva com detalhes adicionais sobre o erro.
</ResponseField>

<ResponseExample>

```json Error Response (403)
{
  "code": "ACCESS_DENIED"
}
```

```json Error Response (404)
{
  "code": "DATABASE_NOT_FOUND_OR_FORBIDDEN"
}
```

```json Error Response (500)
{
  "code": "FAILED_TO_RESET_CERTIFICATES"
}
```

</ResponseExample>
