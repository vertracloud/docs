---
title: Obter conteúdo de arquivo da aplicação
sidebarTitle: Obter conteúdo do arquivo
api: GET https://api.vertracloud.app/v1/apps/{id}/files/content
authMethod: bearer
description: Retorna o conteúdo de um arquivo específico de uma aplicação pelo seu ID.
---

{/* @see APIApplicationFileContent — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID da aplicação da qual o conteúdo do arquivo será obtido. Se a aplicação pertencer a um workspace, informe o ID dele no parâmetro de query `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Se a aplicação pertencer a um workspace, o ID do workspace. Membros com papel de Owner, Admin ou Developer podem usar o gerenciador de arquivos em uma aplicação do workspace que não é deles; sem isso, somente o dono da aplicação pode.
</ParamField>

<ParamField query="path" type="string" required>
  O caminho do arquivo cujo conteúdo será obtido.
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  O conteúdo do arquivo solicitado.

  <Expandable title="Mostrar objeto">

  <ResponseField name="type" type="string">
    Sempre `"base64"`.
  </ResponseField>

  <ResponseField name="data" type="string">
    O conteúdo do arquivo, codificado em base64 padrão (com padding).
  </ResponseField>

  <ResponseField name="size" type="number">
    O tamanho do arquivo em bytes. É o tamanho real do arquivo, não o comprimento da string base64.
  </ResponseField>

  <ResponseField name="last_modified" type="string" format="date-time">
    A data de modificação (mtime) do arquivo. Envie este valor de volta no corpo de [`PUT /files`](/pt-br/api-reference/endpoint/apps/filemanager/save) como `last_modified` para detectar conflitos de edição.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "type": "base64",
    "data": "SGVsbG8gV29ybGQ=",
    "size": 11,
    "last_modified": "2026-03-14T19:58:00Z"
  }
}
```

</ResponseExample>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: o cabeçalho `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: a chave de API está sendo usada a partir de um IP fora da sua lista de permissões, ou não tem o escopo que a rota exige (`403`).
  - `FORBIDDEN` / `ACCESS_DENIED`: o usuário não tem permissão para acessar a aplicação.
  - `APP_NOT_FOUND`: a aplicação especificada não existe.
  - `PLAN_RESTRICTED_FEATURE`: o plano do usuário não oferece suporte ao acesso ao gerenciador de arquivos.
  - `MISSING_PATH`: o parâmetro de query `path` não foi informado.
  - `FILE_NOT_FOUND`: o arquivo solicitado não existe.
  - `FILE_TOO_LARGE`: o arquivo ultrapassa o limite de 10 MB para obtenção de conteúdo.
  - `FILE_CONTENT_ERROR`: falha ao obter o conteúdo do arquivo.
</ResponseField>

<ResponseField name="message" type="string">
  Uma mensagem descritiva com detalhes adicionais sobre o erro.
</ResponseField>

<ResponseExample>

```json Error Response (403)
{
  "code": "API_KEY_SCOPE_DENIED"
}
```

```json Error Response (404)
{
  "code": "FILE_NOT_FOUND"
}
```

```json Error Response (400)
{
  "code": "FILE_TOO_LARGE",
  "message": "File exceeds the 10 MB limit for content retrieval"
}
```

```json Error Response (400)
{
  "code": "MISSING_PATH",
  "message": "Path query parameter is required"
}
```

</ResponseExample>
