api: GET https://api.vertracloud.app/v1/users/{id}/snapshots/{snapshot_id}/download
authMethod: bearer
description: Baixa o arquivo ZIP de um snapshot específico de uma aplicação ou banco de dados. Responde com um redirecionamento para um link temporário, ou devolve o link em JSON.
---

{/* @see binary — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID da aplicação ou do banco de dados.
</ParamField>

<ParamField path="snapshot_id" type="string" required>
  O ID do snapshot a baixar.
</ParamField>

<ParamField query="scope" type="string" required>
  O tipo do recurso. Valores possíveis: `applications`, `databases`.
</ParamField>

<ParamField query="redirect" type="boolean" default="true">
  Com `true` (padrão), a resposta é o ZIP, entregue diretamente ou por um redirecionamento `302 Found` conforme o tamanho. Envie `false` para receber sempre o link temporário em JSON, qualquer que seja o tamanho.
</ParamField>

### Resposta

A resposta é o arquivo ZIP. Snapshots de até 100 MB são entregues diretamente (`200` com o ZIP); os maiores respondem `302 Found` com um header `Location` que aponta para um link temporário que serve o ZIP. O link vale por alguns minutos e não precisa do header `Authorization`. Siga os redirecionamentos (navegadores, `fetch`, os SDKs oficiais e `curl -L` seguem), e snapshots de qualquer tamanho podem ser baixados. O `curl` sem `-L` para no `302` nos snapshots maiores.

```bash
curl -L -o snapshot.zip \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  "https://api.vertracloud.app/v1/users/{id}/snapshots/{snapshot_id}/download?scope=applications"
```

Com `redirect=false` a rota responde `200` com o link e a validade dele:

<ResponseField name="response.url" type="string">
  O link temporário de download.
</ResponseField>

<ResponseField name="response.expires_at" type="string">
  Quando o link expira, como data ISO 8601.
</ResponseField>

<ResponseField name="response.filename" type="string">
  O nome de arquivo sugerido, no formato `snapshot-<nome>-<id>.zip`.
</ResponseField>

```json Response (redirect=false)
{
  "response": {
    "url": "https://...",
    "expires_at": "2026-11-07T15:00:00.000Z",
    "filename": "snapshot-my-app-1a2b3c.zip"
  }
}
```

Exige o escopo `snapshots:read`.

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: o header `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: a chave de API é usada a partir de um IP fora da sua allowlist, ou não tem o escopo que a rota exige (`403`).
  - `USER_NOT_FOUND`: o usuário autenticado não foi encontrado.
  - `ACCESS_DENIED`: o snapshot não pertence ao usuário autenticado.
  - `TEMPLATE_CLOSED`: o snapshot é de uma aplicação de um [template fechado](/pt-br/templates/use/closed-templates) e não pode ser baixado (`403`).
  - `SNAPSHOT_TYPE_MISMATCH`: o tipo de recurso do snapshot não corresponde ao `scope` pedido (`400`).
  - `SNAPSHOT_NOT_FOUND`: o snapshot informado não existe.
  - `INTERNAL_SERVER_ERROR`: ocorreu um erro inesperado no servidor.
</ResponseField>
