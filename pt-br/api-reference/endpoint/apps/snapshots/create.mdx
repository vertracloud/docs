---
title: Criar snapshot da aplicação
sidebarTitle: Criar snapshot
api: POST https://api.vertracloud.app/v1/users/{id}/snapshots
authMethod: bearer
description: Faz um snapshot de uma aplicação ou do volume de um banco de dados agora. O snapshot aparece na lista e pode ser restaurado ou baixado como qualquer outro.
---

{/* @see success/error — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID da aplicação ou do banco de dados a ser salvo em snapshot.
</ParamField>

<ParamField query="scope" type="string" required>
  O tipo do recurso. Valores possíveis: `applications`, `databases`.
</ParamField>

<Note>
  **Dois limites se aplicam aos snapshots manuais, além das 5 requisições por minuto da rota.** O mesmo
  recurso pode receber um snapshot a cada **5 minutos**, e uma conta pode criar no máximo **10
  snapshots por hora** somando todos os seus recursos. Ao ultrapassar qualquer um dos limites, a API responde
  `429 SNAPSHOT_RATE_LIMITED` com `details.scope` (`resource` ou `account`) e
  `details.retry_after` em segundos. Os snapshots que a plataforma faz por conta própria (antes de um delete ou de um
  reset) não contam. Veja [Limite de requisições](/pt-br/api-reference/introduction#como-a-api-tem-limite-de-taxa).
</Note>

### Resposta

<ResponseField name="response" type="object">
  O snapshot criado.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    O ID do snapshot. Use-o com [restaurar](/pt-br/api-reference/endpoint/apps/snapshots/restore) e
    [baixar](/pt-br/api-reference/endpoint/apps/snapshots/download).
  </ResponseField>

  <ResponseField name="resource_id" type="string">
    O ID do recurso ao qual este snapshot pertence.
  </ResponseField>

  <ResponseField name="type" type="number">
    `1` para uma aplicação, `2` para um banco de dados.
  </ResponseField>

  <ResponseField name="size" type="number">
    Tamanho em kilobytes.
  </ResponseField>

  <ResponseField name="resource_name" type="string | null">
    O nome que o recurso tinha no momento em que o snapshot foi feito.
  </ResponseField>

  <ResponseField name="created_at" type="string">
    Quando o snapshot foi feito.
  </ResponseField>

  <ResponseField name="expires_at" type="string">
    Quando o snapshot será apagado automaticamente.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: o header `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: a chave de API é usada a partir de um IP fora da sua allowlist, ou não tem o escopo que a rota exige (`403`).
  - `USER_NOT_FOUND`: o usuário autenticado não foi encontrado.
  - `APP_NOT_FOUND`: a aplicação informada não existe.
  - `DATABASE_NOT_FOUND`: o banco de dados informado não existe.
  - `ACCESS_DENIED`: o usuário não é dono do recurso.
  - `PLAN_NOT_ALLOWED`: o plano da conta não inclui snapshots manuais (`403`).
  - `DATABASE_NOT_RUNNING`: o banco de dados precisa estar em execução para gerar um snapshot (`409`). O Redis não tem essa exigência.
  - `SNAPSHOT_RATE_LIMITED`: o recurso recebeu um snapshot há menos de 5 minutos, ou a conta já criou 10 snapshots nesta hora (`429`). Vem com `details.scope` e `details.retry_after`.
  - `OPERATION_IN_PROGRESS`: outra operação de ciclo de vida no mesmo recurso já está em execução (`409`). Nenhum snapshot foi feito — aguarde alguns segundos e tente de novo.
  - `INTERNAL_SERVER_ERROR`: o snapshot não pôde ser armazenado, ou ocorreu uma falha inesperada (`500`). Tente de novo mais tarde.
</ResponseField>
