---
title: Restaurar snapshot da aplicação
sidebarTitle: Restaurar snapshot
api: POST https://api.vertracloud.app/v1/users/{id}/snapshots/{snapshot_id}/restore
authMethod: bearer
description: Inicia a restauração de um snapshot em uma aplicação ou banco de dados. A restauração roda em segundo plano e responde 202 com um job para acompanhar.
---

{/* @see success/error — @vertracloud/api-types */}
Restaurar substitui o conteúdo atual do recurso pelo do snapshot. A requisição responde **`202`** assim que a
restauração é aceita; o recurso **ainda não** foi restaurado. Acompanhe `response.job_id` em
[Obter job de snapshot](/pt-br/api-reference/endpoint/apps/snapshots/jobs/get) até o `status` ser `ready` ou `failed`. Quando a restauração termina, o recurso fica
como estava antes: o que estava ligado volta a rodar, o que estava desligado continua desligado.

A restauração começa na hora e substitui os dados atuais do destino de forma definitiva: não há como desfazer, então
[crie um snapshot](/pt-br/api-reference/endpoint/apps/snapshots/create) do destino antes se puder precisar dos dados dele de novo. Um snapshot de qualquer tamanho pode ser
restaurado, desde que o conteúdo caiba no armazenamento do destino.

<ParamField path="id" type="string" required>
  O ID da aplicação ou do banco de dados para o qual o snapshot será restaurado.
</ParamField>

<ParamField path="snapshot_id" type="string" required>
  O ID do snapshot a restaurar.
</ParamField>

<ParamField query="scope" type="string" required>
  O tipo do recurso. Valores possíveis: `applications`, `databases`.
</ParamField>

<ParamField body="resource_id" type="string">
  Opcional. Substitui o recurso de destino para restauração entre recursos. Se omitido, restaura no recurso informado em `id`.
</ParamField>

<ParamField body="restore_image_version" type="boolean">
  Somente para uma aplicação que roda uma imagem Docker personalizada. Quando `true`, a restauração também volta para a versão da imagem que a aplicação rodava no momento do snapshot, se ela ainda existir. Padrão `false`: só os dados são restaurados e a aplicação mantém a versão atual da imagem.
</ParamField>

<Note>
  Enquanto uma restauração roda, toda escrita no recurso responde `409 RESTORE_IN_PROGRESS` (inclusive a aba Dados do banco),
  e outra restauração nele é recusada da mesma forma. Ler e excluir a aplicação ou o banco continuam permitidos.
  Uma restauração precisa de 60 segundos entre duas restaurações da mesma aplicação e, em um banco, de 60 segundos para quem pede e 120
  segundos por banco (`429 RESTORE_COOLDOWN`, com `details.retry_after`).
</Note>

### Resposta

<ResponseField name="response" type="object">
  Confirmação de que a restauração foi aceita.

  <Expandable title="Mostrar objeto">

  <ResponseField name="job_id" type="string">
    O job de restauração. Acompanhe-o em [Obter job de snapshot](/pt-br/api-reference/endpoint/apps/snapshots/jobs/get), onde `{id}` é o recurso que está sendo restaurado.
  </ResponseField>

  <ResponseField name="warning" type="string">
    Presente quando `restore_image_version` era `true`, mas a versão da imagem registrada no snapshot não existe mais: `IMAGE_VERSION_NOT_FOUND`. Só os dados são restaurados e a aplicação continua na versão atual.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: o header `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: a chave de API é usada a partir de um IP fora da sua allowlist, ou não tem o escopo que a rota exige (`403`).
  - `USER_NOT_FOUND`: o usuário autenticado não foi encontrado.
  - `APP_NOT_FOUND`: a aplicação informada não foi encontrada.
  - `DATABASE_NOT_FOUND`: o banco de dados informado não foi encontrado.
  - `ACCESS_DENIED`: você é membro de um workspace sem a permissão para esta ação (ou não enviou o `workspace_id`) (`403`).
  - `PLAN_REQUIRED`: a conta da aplicação não tem plano ativo, então a aplicação não poderia ser iniciada de novo depois da restauração (`403`). Nada foi alterado.
  - `RESTORE_COOLDOWN`: uma restauração foi pedida cedo demais depois de outra: 60 segundos na mesma aplicação e, em um banco, 60 segundos para quem pede e 120 segundos por banco (`429`). `details.retry_after` diz quantos segundos esperar, e o header `Retry-After` traz o mesmo número.
  - `RESTORE_IN_PROGRESS`: já há uma restauração em andamento neste recurso (`409`).
  - `APP_BUILDING`: a aplicação está em build ou deploy (`409`). Tente de novo quando terminar.
  - `TYPE_MISMATCH`: o tipo do recurso do snapshot não corresponde ao tipo do recurso de destino.
  - `SNAPSHOT_TYPE_MISMATCH`: o snapshot é de uma aplicação e o destino é um banco, ou o contrário (`400`).
  - `SNAPSHOT_ENGINE_MISMATCH`: o snapshot pertence a um motor de banco de dados diferente do de destino (`400`).
  - `SNAPSHOT_VERSION_NEWER`: o snapshot foi feito em uma versão principal mais nova do que a do banco de dados de destino; nada é alterado (`400`).
  - `SNAPSHOT_EXCEEDS_STORAGE`: o conteúdo do snapshot não cabe no armazenamento do destino (`400`). `details` traz `required_bytes` e `available_bytes`; em um banco, também `required_ram_mb`, o menor tamanho de memória cujo armazenamento comporta o snapshot.
  - `SNAPSHOT_NOT_FOUND`: o snapshot informado não foi encontrado.
  - `TEMPLATE_CLOSED`: o snapshot ou o destino pertence a um [template fechado](/pt-br/templates/use/closed-templates) e a restauração não é permitida (`403`).
  - `OPERATION_IN_PROGRESS`: outra operação no mesmo recurso está em execução (`409`). Aguarde alguns segundos e tente de novo.
  - `INTERNAL_SERVER_ERROR`: ocorreu um erro inesperado no servidor.

  Uma restauração que falha depois do `202` é informada pelo job, com o motivo em `reason`: `SNAPSHOT_CORRUPTED` (o snapshot não confere com o que foi registrado quando foi feito; nada mudou), `SNAPSHOT_EXCEEDS_STORAGE`, `SNAPSHOT_IMPORT_FAILED` (um banco não conseguiu carregar os dados; ele mantém os que tinha), `SNAPSHOT_TIMEOUT`, `SERVICE_UNAVAILABLE`, `SNAPSHOT_ENGINE_MISMATCH`, `SNAPSHOT_VERSION_NEWER`, `DATABASE_NOT_READY`, `OPERATION_IN_PROGRESS` e `SNAPSHOT_NOT_FOUND`.
</ResponseField>
