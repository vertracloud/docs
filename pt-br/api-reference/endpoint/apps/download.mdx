{/* @see binary zip — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  O ID da aplicação a baixar. Se a aplicação pertencer a um workspace, informe o ID dele no parâmetro de query `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Se a aplicação pertencer a um workspace, o ID do workspace. Obrigatório para membros do workspace que atuam em uma aplicação que não é deles.
</ParamField>

### Resposta

A resposta é um arquivo ZIP binário com os arquivos da aplicação, mais um `vertracloud.config` gerado a partir das configurações atuais (nome, arquivo principal, memória, versão, comando de start, reinício automático, subdomínio), para que o ZIP possa ser enviado novamente com a mesma configuração.

- **Content-Type**: `application/zip`
- **Content-Disposition**: `attachment; filename="app-{id}.zip"`
- **Content-Length**: o tamanho do arquivo ZIP em bytes.

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:

  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: o cabeçalho `Authorization` está ausente, a chave de API é inválida ou a sessão do painel foi revogada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: a chave de API está sendo usada a partir de um IP fora da sua lista de permissões, ou não tem o escopo que a rota exige (`403`).
  - `ACCESS_DENIED`: a aplicação pertence a outra conta, ou você não tem a permissão do workspace para baixar os seus arquivos (`403`).
  - `APP_NOT_FOUND`: a aplicação especificada não existe (`404`).
  - `INTERNAL_SERVER_ERROR`: não foi possível baixar os arquivos da aplicação (`500`).
</ResponseField>

<ResponseField name="message" type="string">
  Uma mensagem descritiva com detalhes adicionais sobre o erro.
</ResponseField>

<ResponseExample>

```json Error Response (404)
{
  "code": "APP_NOT_FOUND"
}
```

```json Error Response (403)

```

```json Error Response (500)

```

</ResponseExample>
