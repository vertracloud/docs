{/* @see RESTDeleteAPIStackBody, RESTDeleteAPIStackResponse — @vertracloud/api-types */}
Escolha entre dois modos. **`dissolve`** remove só a stack: os apps e bancos de dados ficam como recursos avulsos, sem as variáveis e os certificados gerenciados, e os arquivos do Blob são mantidos. **`delete_all`** apaga também todos os membros, na hora: os apps, os bancos de dados e a stack. Em ambos os casos, a chave de API que a plataforma criou para a pasta do Blob da stack é revogada.

<Warning>
  `delete_all` é imediato e não pode ser desfeito: apaga os apps e bancos de dados de forma definitiva. [Crie um snapshot da stack](/pt-br/api-reference/endpoint/stacks/snapshots/create) antes se puder precisar deles de novo, confirme o nome e confira os membros com [Obter stack](/pt-br/api-reference/endpoint/stacks/get).
</Warning>

Precisa do escopo `stacks:delete` quando chamado com uma chave de API. Com `delete_all`, a chave também precisa de `apps:delete` e `databases:delete`, e de `blob:write` quando você apaga os arquivos do Blob (`blob: "delete"`). Sem eles, a chamada falha com `API_KEY_SCOPE_DENIED`.

<ParamField path="stack_id" type="string" required>
  O ID da stack.
</ParamField>

<ParamField query="workspace_id" type="string">
  O workspace ao qual a stack pertence, quando você age sobre ela como dono do workspace.
</ParamField>

<ParamField body="mode" type="string" required>
  `dissolve` ou `delete_all`.
</ParamField>

<ParamField body="confirm_name" type="string" required>
  Deve ser igual ao nome da stack.
</ParamField>

<ParamField body="blob" type="string" default="keep">
  O que fazer com os arquivos da pasta do Blob da stack quando `mode` é `delete_all`: `keep` os deixa onde estão, `delete` os remove. `dissolve` sempre os mantém.
</ParamField>

### Resposta

Os dois modos respondem `200`. Com **`dissolve`**, `deleted_apps` e `deleted_databases` vêm sempre vazios; com **`delete_all`**, eles listam o que foi apagado.

<ResponseField name="response" type="object">
  <Expandable title="Mostrar objeto">

  <ResponseField name="deleted_apps" type="string[]">Os IDs dos apps que foram apagados. Sempre vazio com `dissolve`.</ResponseField>
  <ResponseField name="deleted_databases" type="string[]">Os IDs dos bancos de dados que foram apagados. Sempre vazio com `dissolve`.</ResponseField>
  <ResponseField name="deleted_blob" type="boolean">`true` quando os arquivos da pasta do Blob foram apagados (`delete_all` com `blob: "delete"`). Sempre `false` com `dissolve`, que mantém os arquivos do Blob.</ResponseField>

  </Expandable>
</ResponseField>

<RequestExample>

```bash cURL
curl -X DELETE https://api.vertracloud.app/v1/stacks/stk-abc123def456 \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "mode": "delete_all", "confirm_name": "shop", "blob": "keep" }'
```

</RequestExample>

### Erros

Antes de apagar qualquer coisa, todos os membros são conferidos: se um deles recusa a exclusão, a requisição responde com o erro desse membro e nada muda.

| Status | Código | Quando |
|---|---|---|
| 400 | `STACK_NAME_MISMATCH` | `confirm_name` não é o nome da stack. |
| 403 | `API_KEY_SCOPE_DENIED` | A chave não tem `stacks:delete`, ou, com `delete_all`, não tem `apps:delete`, `databases:delete` ou `blob:write`; `details.required` indica o escopo. |
| 403 | `WORKSPACE_OWNER_ONLY` | Você é membro do workspace, não o dono. |
| 403 | `STACK_SERVICE_LOCKED` | `dissolve` numa stack com aplicação de template fechado, que não pode sair da stack. Use `delete_all`. |
| 404 | `STACK_NOT_FOUND` | A stack não foi encontrada. |
| 409 | `OPERATION_IN_PROGRESS` | Outra operação na stack ou em um dos membros está em andamento. |
