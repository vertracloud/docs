Restaura todos os membros juntos: primeiro os bancos de dados, depois os apps. A restauração roda em segundo plano e a requisição responde **`202`** assim que é aceita; nada foi restaurado ainda. Precisa do escopo `stacks:write` quando chamado com uma chave de API.

<ParamField path="stack_id" type="string" required>
  O ID da stack.
</ParamField>

<ParamField path="snapshot_id" type="string" required>
  O ID do snapshot da stack.
</ParamField>

<ParamField query="workspace_id" type="string">
  O workspace ao qual a stack pertence, quando você age sobre ela como dono do workspace.
</ParamField>

<ParamField body="restore_image_version" type="boolean" default="false">
  Os apps que executam uma imagem personalizada também voltam para a versão da imagem do snapshot, se ela ainda existir.
</ParamField>

### Resposta

Diferente de [Restaurar snapshot da aplicação](/pt-br/api-reference/endpoint/apps/snapshots/restore), que restaura um recurso, esta rota inicia um job de restauração por membro que ainda está na stack. Acompanhe cada `job_id` em [Obter job de snapshot](/pt-br/api-reference/endpoint/apps/snapshots/jobs/get) (`GET /v1/users/{id}/snapshots/jobs/{job_id}`, onde `{id}` é o `resource_id` do job) até o `status` ser `ready` ou `failed`. A stack está restaurada quando todos os jobs estão `ready`.

Os membros são restaurados em ordem: primeiro os bancos, e cada aplicação só depois deles. Se um membro falha, os membros seguintes **não** são restaurados e os jobs deles falham com `STACK_RESTORE_MEMBER_FAILED`; o job que falhou traz o `reason` real. A restauração substitui os dados atuais de cada membro de forma definitiva: [crie um snapshot da stack](/pt-br/api-reference/endpoint/stacks/snapshots/create) antes se puder precisar deles de novo.

Só os dados dessa aplicação são restaurados.

### Erros

Se um membro não puder ser restaurado (por exemplo, ele tem uma restauração ou um deploy em andamento, ou o snapshot não cabe), a requisição responde com o erro desse membro e nada é iniciado. Veja [Restaurar snapshot da aplicação](/pt-br/api-reference/endpoint/apps/snapshots/restore) para esses códigos.

| Status | Código | Quando |
|---|---|---|
| 403 | `WORKSPACE_OWNER_ONLY` | Você é membro do workspace, não o dono. |
| 404 | `STACK_NOT_FOUND` | A stack não foi encontrada. |
| 404 | `SNAPSHOT_NOT_FOUND` | O snapshot não foi encontrado ou falhou. |
| 409 | `OPERATION_IN_PROGRESS` | O snapshot da stack ainda está `pending`: espere até ficar `ready`. |
| 404 | `STACK_MEMBER_NOT_FOUND` | Nenhum dos membros do snapshot continua na stack. |

Um job que termina `failed` depois do `202` informa `STACK_RESTORE_MEMBER_FAILED` no `reason` quando um membro anterior falhou, então este membro não foi restaurado.
