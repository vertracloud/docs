{/* @see RESTGetAPIBlobS3CredentialsResponse, APIBlobS3Credentials — @vertracloud/api-types */}

Retorna credenciais compatíveis com S3 para ferramentas como aws-cli, rclone e boto3. O par é derivado da chave de API que faz a chamada, então revogar essa chave corta o acesso S3 de imediato. Com uma chave de API que tem apenas `blob:read`, as credenciais são somente leitura (`access.write` é `false`). Trate `secret_access_key` como uma senha. Esta rota exige uma chave de API: uma sessão do dashboard é recusada. Ao rotacionar a chave de API, o par é substituído, então busque as credenciais de novo depois.

**Escopo:** `blob:read`.

<ParamField query="workspace_id" type="string">
  O ID do workspace, quando o blob pertence a um workspace. A chamada atua sobre o blob do proprietário do workspace e exige a permissão `blob:read` do workspace (`blob:manage` nas rotas que alteram dados). Deixe de fora para atuar sobre o seu próprio blob.
</ParamField>

### Exemplo de requisição

```bash
curl "https://blob.vertracloud.app/v1/s3/credentials" \
  -H "Authorization: Bearer $VERTRA_API_KEY"
```

### Resposta

<ResponseField name="response" type="object">
  As credenciais S3 da conta.
  <Expandable title="propriedades">
  <ResponseField name="access_key_id" type="string">ID da chave de acesso. Começa com `VCS3`.</ResponseField>
  <ResponseField name="secret_access_key" type="string">Chave secreta. Trate-a como uma senha.</ResponseField>
  <ResponseField name="endpoint" type="string">Endpoint S3 para configurar na sua ferramenta.</ResponseField>
  <ResponseField name="region" type="string">Sempre `auto`.</ResponseField>
  <ResponseField name="buckets" type="string[]">Os dois buckets: `public` e `private`.</ResponseField>
  <ResponseField name="access.read" type="boolean">Se as credenciais podem ler.</ResponseField>
  <ResponseField name="access.write" type="boolean">Se as credenciais podem gravar. `false` com uma chave de API que tem apenas `blob:read`.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "access_key_id": "VCS3K7P2M9X4QA",
    "secret_access_key": "<secret>",
    "endpoint": "https://s3.vertracloud.dev",
    "region": "auto",
    "buckets": [
      "public",
      "private"
    ],
    "access": {
      "read": true,
      "write": true
    }
  }
}
```

</ResponseExample>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING` (`401`): o cabeçalho `Authorization` não foi enviado.
  - `API_KEY_INVALID` (`401`): a chave de API não existe, foi revogada ou o segredo não confere.
  - `API_KEY_SCOPE_DENIED` (`403`): a chave não tem o escopo que esta rota exige (`blob:read` ou `blob:write`); `details.required` informa qual.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): somente com `workspace_id`: você não é membro, ou o seu papel não tem a permissão de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): somente com `workspace_id`: não existe workspace com esse ID, ou você não é membro.
  - `VALIDATION_ERROR` (`400`): a chamada não foi feita com uma chave de API; `details.reason` é `api_key_required`.
  - `RATE_LIMIT_EXCEEDED` (`429`): mais de 10 chamadas em uma hora. `details.retry_after` informa a espera em segundos.
</ResponseField>
