{/* @see RESTPatchAPIBlobObjectBody, RESTPatchAPIBlobObjectResponse, APIBlobObject — @vertracloud/api-types */}

Altera as configurações de um objeto sem tocar nos seus bytes. Envie somente os campos a alterar. Mudar `visibility` para `public` torna o objeto acessível pela sua `url` pública; mudar para `private` remove essa URL. Enviar `null` restaura o padrão de um campo.

**Escopo:** `blob:write`.

<ParamField path="object_id" type="string" required>
  O ID do objeto.
</ParamField>

<ParamField body="visibility" type="string">
  `public` ou `private`.
</ParamField>

<ParamField body="cache_control" type="string | null">
  `immutable`, `max-age=<seconds>` ou `no-cache` (Enterprise-26 ou superior). `null` restaura o padrão.
</ParamField>

<ParamField body="content_disposition" type="string | null">
  `inline` ou `attachment`. `null` restaura o padrão.
</ParamField>

<ParamField body="filename" type="string | null">
  Nome sugerido no download. `null` usa o último segmento de `path`.
</ParamField>

<ParamField body="expires_at" type="string | null">
  Timestamp ISO 8601 para a exclusão, com pelo menos o mínimo do plano a partir de agora. `null` remove a expiração.
</ParamField>

<ParamField body="metadata" type="object">
  Chaves a definir. Uma chave com o valor `null` é removida. Até 5 chaves no total, 512 bytes; Enterprise-12 ou superior.
</ParamField>

<ParamField query="workspace_id" type="string">
  O ID do workspace, quando o blob pertence a um workspace. A chamada atua sobre o blob do proprietário do workspace e exige a permissão `blob:read` do workspace (`blob:manage` nas rotas que alteram dados). Deixe de fora para atuar sobre o seu próprio blob.
</ParamField>

### Exemplo de requisição

```bash
curl -X PATCH "https://blob.vertracloud.app/v1/objects/0b6f7c1e-3d2a-4f5b-9a8c-1d2e3f4a5b6c" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"visibility":"private","metadata":{"owner":"joao","old-key":null}}'
```

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING` (`401`): o cabeçalho `Authorization` não foi enviado.
  - `API_KEY_INVALID` (`401`): a chave de API não existe, foi revogada ou o segredo não confere.
  - `API_KEY_SCOPE_DENIED` (`403`): a chave não tem o escopo que esta rota exige (`blob:read` ou `blob:write`); `details.required` informa qual.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): somente com `workspace_id`: você não é membro, ou o seu papel não tem a permissão de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): somente com `workspace_id`: não existe workspace com esse ID, ou você não é membro.
  - `BLOB_NAMESPACE_SUSPENDED` (`403`): o armazenamento de blob da conta está suspenso, ou o plano expirou. Uploads e outras gravações são recusados desde o início do período de carência de 72 horas.
  - `VALIDATION_ERROR` (`400`): um parâmetro ou campo do corpo falhou na validação. `details.path` informa o campo.
  - `BLOB_OBJECT_NOT_FOUND` (`404`): não existe objeto com esse ID nesta conta (ou no blob do workspace).
  - `PLAN_RESTRICTED_FEATURE` (`403`): o plano não inclui a configuração enviada, como `metadata` abaixo do Enterprise-12 ou `no-cache` abaixo do Enterprise-26.
</ResponseField>
