{/* @see RESTDeleteAPIBlobRuleResponse, APIBlobRules — @vertracloud/api-types */}

Remove a regra de um prefixo de pasta. Os objetos já armazenados na pasta não são alterados. A resposta é a lista restante com o seu novo `etag`. Excluir uma regra que não existe não é erro: a chamada responde `200` com a lista atual, então pode ser repetida com segurança.

**Escopo:** `blob:write`.

<ParamField path="prefix" type="string" required>
  Prefixo da pasta, codificado em URL.
</ParamField>

<ParamField query="workspace_id" type="string">
  O ID do workspace, quando o blob pertence a um workspace. A chamada atua sobre o blob do proprietário do workspace e exige a permissão `blob:read` do workspace (`blob:manage` nas rotas que alteram dados). Deixe de fora para atuar sobre o seu próprio blob.
</ParamField>

### Exemplo de requisição

```bash
curl -X DELETE "https://blob.vertracloud.app/v1/rules/tmp%2F" \
  -H "Authorization: Bearer $VERTRA_API_KEY"
```

### Resposta

<ResponseField name="response" type="object">
  As regras restantes e o seu novo etag.
  <Expandable title="propriedades">
  <ResponseField name="rules" type="object[]">Regras de pasta. Vale o prefixo correspondente mais longo.</ResponseField>
  <ResponseField name="rules[].prefix" type="string">Prefixo da pasta, sempre armazenado com `/` no fim.</ResponseField>
  <ResponseField name="rules[].visibility" type="string">Visibilidade padrão dos novos objetos da pasta.</ResponseField>
  <ResponseField name="rules[].expire_seconds" type="number">Expiração padrão de cada novo objeto, em segundos.</ResponseField>
  <ResponseField name="rules[].max_size" type="number">Maior arquivo aceito, em bytes, de 512 B a 10 GB.</ResponseField>
  <ResponseField name="rules[].extensions" type="string[]">Extensões aceitas, de 1 a 50, em minúsculas, sem o ponto.</ResponseField>
  <ResponseField name="rules[].cache_control" type="string">`cache_control` padrão dos novos objetos.</ResponseField>
  <ResponseField name="rules[].delete_after_days" type="number">Os objetos são excluídos esta quantidade de dias depois do upload, de 1 a 3650.</ResponseField>
  <ResponseField name="rules[].active_from" type="string">Quando `delete_after_days` passa a valer, definido pela plataforma (24 horas depois que a regra é salva).</ResponseField>
  <ResponseField name="rules[].created_at" type="string">Data em ISO 8601 em que a regra foi criada.</ResponseField>
  <ResponseField name="etag" type="string">Versão da lista inteira de regras. Envie-a de volta em `If-Match` quando substituir a lista.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "rules": [],
    "etag": "v4"
  }
}
```

</ResponseExample>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING` (`401`): o cabeçalho `Authorization` não foi enviado.
  - `API_KEY_INVALID` (`401`): a chave de API não existe, foi revogada ou o segredo não confere.
  - `API_KEY_SCOPE_DENIED` (`403`): a chave não tem o escopo que esta rota exige (`blob:read` ou `blob:write`); `details.required` informa qual.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): somente com `workspace_id`: você não é membro, ou o seu papel não tem a permissão de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): somente com `workspace_id`: não existe workspace com esse ID, ou você não é membro.
</ResponseField>
