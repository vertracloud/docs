{/* @see RESTPostAPIBlobUploadPartsBody, RESTPostAPIBlobUploadPartsResponse, APIBlobUploadPart — @vertracloud/api-types */}

Retorna uma URL de upload assinada para cada parte que você pedir. Envie os bytes de cada parte com um `PUT` para a `url` dela, usando exatamente os `headers` retornados. O tamanho das partes é o `part_size` do upload, exceto a última parte, que pode ser menor. Os limites de partes estão em `limits` em [uso e limites](/pt-br/api-reference/endpoint/blob/account/stats).

**Escopo:** `blob:write`. Aceita um token de upload.

**Token de upload:** esta rota também aceita um token de upload (`Authorization: Bearer vcup_...`) em vez de uma chave de API.

<ParamField path="upload_id" type="string" required>
  O ID do upload multipart.
</ParamField>

<ParamField body="part_numbers" type="number[]" required>
  Números das partes para obter URLs, começando em 1. Até 100 por chamada.
</ParamField>

<ParamField query="workspace_id" type="string">
  O ID do workspace, quando o blob pertence a um workspace. A chamada atua sobre o blob do dono do workspace e precisa da permissão de workspace `blob:read` (`blob:manage` nas rotas que alteram dados). Omita para atuar sobre o seu próprio blob.
</ParamField>

### Exemplo de requisição

```bash
curl -X POST "https://blob.vertracloud.app/v1/uploads/7c1d2e3f-4a5b-4c6d-8e7f-0a1b2c3d4e5f/parts" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"part_numbers":[1,2]}'
```

### Resposta

<ResponseField name="response" type="object[]">
  Uma URL por parte pedida.
  <Expandable title="propriedades">
  <ResponseField name="part_number" type="number">Número da parte, começando em 1.</ResponseField>
  <ResponseField name="url" type="string">URL para fazer `PUT` desta parte.</ResponseField>
  <ResponseField name="size" type="number">Tamanho exato desta parte em bytes.</ResponseField>
  <ResponseField name="headers" type="object">Headers que o `PUT` desta parte deve enviar exatamente como informados.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseExample>


### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `AUTH_TOKEN_MISSING` (`401`): Nenhum header `Authorization` foi enviado.
  - `API_KEY_INVALID` (`401`): A chave de API não existe, foi revogada ou o segredo não confere.
  - `API_KEY_SCOPE_DENIED` (`403`): A chave não tem o escopo que a rota exige (`blob:read` ou `blob:write`); `details.required` informa qual.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Somente com `workspace_id`: você não é membro, ou seu papel não tem a permissão de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): Somente com `workspace_id`: não existe workspace com esse ID, ou você não é membro.
  - `BLOB_UPLOAD_TOKEN_INVALID` (`401`): O token de upload não existe, expirou ou foi revogado (somente com token de upload).
  - `VALIDATION_ERROR` (`400`): Um parâmetro ou campo do body falhou na validação. `details.path` informa o campo.
  - `BLOB_UPLOAD_NOT_FOUND` (`404`): Nenhum upload com esse ID nesta conta, ou ele já foi concluído ou abortado.
  - `BLOB_UPLOAD_EXPIRED` (`410`): O prazo do upload passou.
</ResponseField>
