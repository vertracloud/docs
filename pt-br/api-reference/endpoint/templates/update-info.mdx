{/* @see APITemplateUpdateInfo, RESTGetAPITemplateUpdateInfoResponse — @vertracloud/api-types */}
Informa se existe uma versão mais nova do template para uma aplicação ou uma stack e o que a atualização mudaria. Nada é gravado. Há duas rotas com a mesma resposta: `GET /v1/apps/{id}/template/update` para uma aplicação e `GET /v1/stacks/{stack_id}/template/update` para uma stack. Com uma chave de API, o escopo é `templates:read`. Membros do workspace que podem ler o recurso podem chamá-la; atualizar é para o dono (veja [Atualizar template](/pt-br/api-reference/endpoint/templates/update)).

Uma aplicação que faz parte de uma stack criada a partir de um template responde pela **stack inteira**, com todos os serviços juntos. Uma aplicação avulsa, ou uma em uma stack montada à mão, responde sozinha. As atualizações nunca são automáticas: elas só rodam quando você pede. Veja [Atualizações e rollback](/pt-br/templates/use/updates-and-rollback).

<ParamField path="id" type="string" required>
  O ID da aplicação (na rota `/v1/apps/{id}/template/update`).
</ParamField>

<ParamField path="stack_id" type="string" required>
  O ID da stack (na rota `/v1/stacks/{stack_id}/template/update`).
</ParamField>

### Resposta

<ResponseField name="response" type="object">
  O que a atualização faria.

  <Expandable title="Mostrar objeto">

  <ResponseField name="update_available" type="boolean">
    `true` quando existe uma versão mais nova e nada estrutural bloqueia a atualização. Fica `false` quando `blocked` traz um motivo estrutural.
  </ResponseField>

  <ResponseField name="current_version" type="string">
    A versão que o recurso roda agora.
  </ResponseField>

  <ResponseField name="latest_version" type="string | null">
    A versão pronta mais nova, ou `null` quando não há uma mais nova ou a atualização está bloqueada estruturalmente.
  </ResponseField>

  <ResponseField name="security" type="boolean">
    `true` quando a nova versão, ou uma intermediária, é uma release de segurança.
  </ResponseField>

  <ResponseField name="changelog" type="object | null">
    O que mudou na nova versão, como um texto por idioma, ou `null`.
  </ResponseField>

  <ResponseField name="new_inputs" type="object[]">
    As perguntas obrigatórias que a nova versão acrescenta, no mesmo formato de `inputs` em [Obter template](/pt-br/api-reference/endpoint/templates/get). Apenas perguntas sem valor padrão que a plataforma não gera. Responda-as em `inputs` ao atualizar. Perguntas que você já respondeu não são feitas de novo.
  </ResponseField>

  <ResponseField name="added_services" type="object[]">
    Os serviços que a nova versão acrescenta, no formato usado em [Listar templates](/pt-br/api-reference/endpoint/templates/list). Eles são criados na mesma operação.
  </ResponseField>

  <ResponseField name="removed_services" type="string[]">
    Os IDs dos serviços que a nova versão remove e que existem na sua conta. Eles não são apagados: saem do template e você pode apagá-los por conta própria.
  </ResponseField>

  <ResponseField name="ram_changes" type="object[]">
    Serviços cuja memória mínima subiu acima do que eles têm. Cada um traz `service_id`, `current` e `required_min`, em MB. Envie a nova memória em `ram` ao atualizar.
  </ResponseField>

  <ResponseField name="free_ram" type="integer">
    A memória livre na sua conta, em MB.
  </ResponseField>

  <ResponseField name="opens_permissions" type="boolean">
    `true` quando a nova versão abre permissões que a aplicação tinha fechadas, por exemplo quando um template fechado passa a ser aberto. Permissões nunca são tornadas mais restritas por uma atualização.
  </ResponseField>

  <ResponseField name="rollback_with_data" type="boolean">
    `true` quando voltar da nova versão sempre leva os dados junto: o template migra os dados ao atualizar, então reverter só o código é recusado e você restaura o snapshot da atualização.
  </ResponseField>

  <ResponseField name="blocked" type="object | null">
    `null` quando a atualização pode seguir. Caso contrário, o motivo pelo qual não pode.

    <Expandable title="Mostrar objeto">

    <ResponseField name="reason" type="string">
      `no_new_version` (já está na versão mais recente), `detached` (saiu do template), `template_removed` (o autor removeu o template, ou ele está descontinuado), `link_revoked` (o link de compartilhamento de onde ele veio foi revogado), `app_building` (a aplicação está em build), `deploy_in_progress` (outro deploy ou atualização do mesmo alvo está rodando), `plan`, `ram` ou `image_slots`.
    </ResponseField>

    <ResponseField name="details" type="object">
      Números por trás do motivo. Para `plan`, `details.reason` é um de `no_plan`, `min_plan`, `web_publish`, `image_plan`, `blob_plan`, `max_apps` ou `max_databases`; para `ram` traz a memória necessária e a livre; para `template_removed`, `details.deprecated` diferencia um template descontinuado de um removido.
    </ResponseField>

    </Expandable>
  </ResponseField>

  </Expandable>
</ResponseField>

### Respostas de erro

<ResponseField name="code" type="string">
  O código de erro que indica o motivo da falha. Valores possíveis:
  - `VALIDATION_ERROR`: O ID não é válido (`400`).
  - `API_KEY_SCOPE_DENIED`: A chave de API não tem o escopo `templates:read` (`403`).
  - `APP_NOT_FOUND`: A aplicação não existe ou não é sua (`404`).
  - `STACK_NOT_FOUND`: A stack não existe ou não é sua (`404`).
  - `TEMPLATE_NOT_FOUND`: A aplicação ou a stack não veio de um template (`404`).
  - `INTERNAL_SERVER_ERROR`: Falha inesperada (`500`).
</ResponseField>

<ResponseExample>

```json Error Response
{
  "code": "APP_NOT_FOUND"
}
```

</ResponseExample>
