O Blob Storage é o armazenamento de objetos da Vertra Cloud para arquivos que sua aplicação manipula, mas não constrói: uploads de usuários, imagens, vídeos, exports e backups. Os arquivos são guardados uma vez, servidos por uma CDN global e gerenciados pela [API](/pt-br/api-reference/endpoint/blob/objects/list), pelos [SDKs](/pt-br/blob/sdk-javascript), pelo dashboard ou por qualquer ferramenta compatível com S3.

Ele é separado do disco da própria aplicação. Tudo o que você guarda aqui sobrevive a redeploys e não conta no armazenamento da aplicação.

## Como funciona

1. Seu código chama a API com uma [chave de API](/pt-br/blob/authentication) (ou um navegador usa um token de upload de vida curta).
2. Arquivos de até 100 MB podem ir em uma única requisição. Arquivos maiores, de até 10 GB, são enviados direto para o storage com uma URL assinada, então os bytes nunca passam pela API. Veja [Uploads](/pt-br/blob/uploads).
3. O arquivo é servido pela CDN global por meio de uma URL pública estável ou por um [link temporário](/pt-br/blob/links-and-visibility), quando ele é privado.

## Arquivos públicos e privados

Todo arquivo é **público** ou **privado**, e os arquivos novos são **privados**, a menos que você diga o contrário.

| | Público | Privado |
|---|---|---|
| Endereço | URL permanente em `blob.vertracloud.dev` | Nenhum; você cria um link temporário ou um compartilhamento |
| Quem pode ler | Qualquer um com a URL | Somente suas credenciais, ou um link que você emitiu |
| Cache na CDN | Sim | Não |
| Uso típico | Avatares, imagens do site, downloads | Faturas, backups, documentos de usuários |

Você pode alternar um arquivo entre os dois modos a qualquer momento sem mudar o `id` dele. Os detalhes estão em [Links e visibilidade](/pt-br/blob/links-and-visibility).

## Seguro por padrão

- **Tipos de arquivo bloqueados.** Executáveis e instaladores são recusados: `exe`, `msi`, `dll`, `bat`, `cmd`, `com`, `scr`, `ps1`, `apk`, `dmg`, `pkg`, `deb`, `rpm`, `appimage` e alguns outros. Arquivos que são executáveis de fato são rejeitados mesmo quando renomeados.
- **HTML, SVG e XML são sempre downloads.** Arquivos com extensão `.html`, `.htm`, `.svg`, `.xml` ou `.xhtml` são sempre servidos como download, nunca renderizados no navegador, então um upload de usuário não pode rodar como página web no endereço dos seus arquivos.
- **Content type pela extensão.** A plataforma define o content type sozinha, então ele não pode ser falsificado no momento do upload.
- **Arquivos de outras contas nunca vazam.** Pedir um ID de arquivo que não é seu responde "não encontrado".

## Cache

Arquivos públicos são guardados em cache pela CDN. Defina `cache_control` por arquivo ou por pasta como `immutable` ou `max-age=N`. O modo `no-cache` está disponível nos planos Enterprise mais altos; veja [Limites e cotas](/pt-br/blob/limits-and-quotas). Sobrescrever ou apagar um arquivo público limpa a cópia em cache dele.

## Perguntas frequentes

<AccordionGroup>
  <Accordion title="Quais planos incluem o Blob Storage?">
    Todo plano pago, a partir de 1 GB no Economy. A tabela completa está em [Limites e cotas](/pt-br/blob/limits-and-quotas).
  </Accordion>
  <Accordion title="Qual é o maior arquivo que posso guardar?">
    10 GB por arquivo. Arquivos acima de 100 MB usam o fluxo de upload direto.
  </Accordion>
  <Accordion title="Posso mudar a URL de um arquivo?">
    A URL pública é montada a partir do caminho do arquivo. Mover um arquivo muda o caminho (e a URL), mas mantém o `id`, então guarde o `id` se precisar de uma referência estável.
  </Accordion>
  <Accordion title="O que acontece com meus arquivos se meu plano expirar?">
    Eles ficam por 72 horas em período de carência e depois são apagados de forma definitiva, sem backup. Veja [Limites e cotas](/pt-br/blob/limits-and-quotas#expiração-e-exclusão).
  </Accordion>
</AccordionGroup>
