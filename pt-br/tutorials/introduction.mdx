## Estrutura comum

Independentemente do framework escolhido, todo deploy na Vertra Cloud segue a mesma estrutura:

<Steps>
  <Step title="Prepare o projeto">
    Garanta que as dependências estejam declaradas (`package.json`, `requirements.txt`, `go.mod`, `deno.json`, `.csproj`, `mix.exs`...) e, no caso de sites,
    que a aplicação escute na porta 80.
  </Step>
  <Step title="Envie o código">
    **Novo Projeto** no dashboard (ZIP ou GitHub), `vertra upload` na CLI (na primeira vez; `vertra deploy` nas atualizações seguintes), ou a
    extensão do VS Code. A plataforma detecta o runtime, o arquivo principal e os comandos; revise-os antes do deploy.
  </Step>
  <Step title="Verifique">
    Acompanhe os logs e o status da aplicação no dashboard.
  </Step>
</Steps>

## Arquivo `vertracloud.config`

Um arquivo `vertracloud.config` opcional na raiz do projeto preenche previamente o fluxo de criação:

```ini
MAIN=index.js
START=npm start
MEMORY=512
```

Cada chave e seus limites estão em [Configuração](/pt-br/configuration).

## Porta da aplicação

Aplicações web devem escutar na porta definida pela variável de ambiente `PORT`. A plataforma injeta essa variável automaticamente no container.

<Tabs>
  <Tab title="Node.js">
    ```javascript
    const port = process.env.PORT || 80;
    app.listen(port, '0.0.0.0', () => {
      console.log(`Server running on port ${port}`);
    });
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    port = int(os.environ.get('PORT', 80))
    app.run(host='0.0.0.0', port=port)
    ```
  </Tab>
  <Tab title="Go">
    ```go
    port := os.Getenv("PORT")
    if port == "" {
        port = "80"
    }
    http.ListenAndServe("0.0.0.0:"+port, nil)
    ```
  </Tab>
</Tabs>

<Warning>
  Sempre use `0.0.0.0` como host, e não `localhost` ou `127.0.0.1`. Dentro do container, o bind precisa ser em todas as interfaces para que o tráfego externo chegue à aplicação.
</Warning>
