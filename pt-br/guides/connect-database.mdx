Os bancos de dados na Vertra Cloud exigem TLS **e** um certificado de cliente: somente a senha nunca conecta.
Este guia leva uma aplicação de "sem banco de dados" até uma conexão verificada, com os segredos fora do seu código.

## Antes de começar

<Check>Um plano que comporte a aplicação e o banco: os 1.024 MB do Starter 1 bastam só para o banco, mas uma aplicação mais PostgreSQL, MongoDB ou MySQL precisa do Starter 2 ou superior. Com Redis, o Starter 1 basta.</Check>
<Check>RAM livre suficiente: 1.024 MB para PostgreSQL, MongoDB e MySQL; 512 MB para Redis. A memória da aplicação sai do mesmo total do plano.</Check>

## Passo a passo

<Steps>
  <Step title="Crie o banco de dados">
    No painel, clique em **Novo Projeto**, escolha **Banco de dados** e selecione o motor. Ele está pronto quando
    o status muda para **Online**.
  </Step>
  <Step title="Colete host, porta e senha">
    Os três estão na página do banco de dados. A porta é **única para cada banco**: nunca presuma 5432,
    27017, 6379 ou 3306.
  </Step>
  <Step title="Baixe os certificados">
    Na aba **Certificados**, baixe estes três arquivos e renomeie-os para nomes estáveis:

    | Baixado | Renomear para | Função |
    |---|---|---|
    | `certificate-<id>.ca.pem` | `certs/db.ca.pem` | arquivo da CA: verifica o certificado de servidor do banco |
    | `certificate-<id>.crt` | `certs/db.crt` | certificado do cliente (não é a CA) |
    | `certificate-<id>.key` | `certs/db.key` | chave do cliente |

    O `.pem` e o `.p12` são para o MongoDB e o Prisma 6; veja [o que é cada arquivo](/pt-br/databases#o-que-preciso-para-me-conectar).
    Se o seu banco não tiver `.ca.pem`, baixe o `.pem` e use-o como arquivo da CA.
  </Step>
  <Step title="Envie os certificados com a aplicação">
    Coloque a pasta `certs/` no projeto que você envia. Se você fizer deploy a partir do GitHub, adicione `certs/` ao
    `.gitignore` e envie a pasta pela aba **Arquivos** da aplicação: a chave autentica como você e nunca deve ficar em um repositório.

    Implantar um [template](/pt-br/templates/use/stacks) com banco de dados dispensa este passo: os certificados e as variáveis já são ligados à aplicação para você.
  </Step>
  <Step title="Guarde as credenciais como variáveis de ambiente">
    Na aba **Config → Variáveis de ambiente** da aplicação, adicione:

    ```ini
    DB_HOST=<host>
    DB_PORT=<port>
    DB_PASSWORD=<password>
    ```

    Reinicie a aplicação para que o processo enxergue as variáveis.
  </Step>
  <Step title="Conecte-se">
    Leia tudo a partir do ambiente. PostgreSQL com Node.js:

    ```javascript
    const fs = require('fs');
    const { Pool } = require('pg');

    const pool = new Pool({
      host: process.env.DB_HOST,
      port: Number(process.env.DB_PORT),
      user: 'vertracloud', // older databases: the user shown on the database page
      database: 'vertracloud',
      password: process.env.DB_PASSWORD,
      ssl: {
        ca: fs.readFileSync('certs/db.ca.pem'),
        cert: fs.readFileSync('certs/db.crt'),
        key: fs.readFileSync('certs/db.key'),
        rejectUnauthorized: true,
      },
    });

    pool.query('select 1').then(() => console.log('database ok'));
    ```

    O mesmo padrão para Python, MongoDB, Redis e MySQL está na página de
    [Bancos de dados](/pt-br/databases#como-me-conecto-a-cada-motor).
  </Step>
</Steps>

## Teste primeiro na sua máquina

A conexão funciona da mesma forma no seu computador, que é a maneira mais rápida de saber se o problema está no código
ou nas credenciais:

```bash
psql "host=<host> port=<port> dbname=vertracloud user=vertracloud password=<password> sslmode=verify-full sslrootcert=certs/db.ca.pem sslcert=certs/db.crt sslkey=certs/db.key"
```

## Use o Drizzle Kit e o Drizzle Studio

O Drizzle Kit se conecta com os mesmos três arquivos, mas o `drizzle.config.ts` só aceita o objeto `ssl`
junto com credenciais `host`/`port`, não com `url`. Mantenha a URL de conexão em `DATABASE_URL`,
aponte três variáveis para os arquivos de certificado e divida a URL na configuração:

```ini .env
DATABASE_URL=postgresql://vertracloud:<password>@<host>:<port>/vertracloud
DATABASE_SSL_CA=./certs/db.ca.pem
DATABASE_SSL_CERT=./certs/db.crt
DATABASE_SSL_KEY=./certs/db.key
```

```typescript drizzle.config.ts
import "dotenv/config";
import { readFileSync } from "node:fs";
import { defineConfig } from "drizzle-kit";

const url = process.env.DATABASE_URL;
if (!url) throw new Error("drizzle.config: set DATABASE_URL");

function readCert(name: string): string {
  const path = process.env[name];
  if (!path) throw new Error(`drizzle.config: set ${name}`);
  return readFileSync(path, "utf8");
}

const parsed = new URL(url);

export default defineConfig({
  out: "./drizzle",
  schema: "./src/db/schema/index.ts",
  dialect: "postgresql",
  dbCredentials: {
    host: parsed.hostname,
    port: Number(parsed.port),
    user: decodeURIComponent(parsed.username),
    password: decodeURIComponent(parsed.password),
    database: parsed.pathname.slice(1),
    ssl: {
      rejectUnauthorized: true,
      ca: readCert("DATABASE_SSL_CA"), // certificate-<id>.ca.pem
      cert: readCert("DATABASE_SSL_CERT"), // certificate-<id>.crt
      key: readCert("DATABASE_SSL_KEY"), // certificate-<id>.key
    },
  },
});
```

Instale `drizzle-kit`, `drizzle-orm`, `pg` e `dotenv` (o Drizzle Kit não carrega o `.env` sozinho,
por isso o `import "dotenv/config"`) e então abra o Drizzle Studio:

```bash
npx drizzle-kit studio
```

Ele imprime `https://local.drizzle.studio`; abra no navegador. A mesma configuração serve para
`drizzle-kit migrate`, `push` e `pull`.

<Warning>
  O Drizzle Studio se conecta como o dono do banco e pode editar e apagar linhas. Aponte-o para uma cópia, ou
  apenas navegue sem salvar, quando o banco atender uma aplicação em produção.
</Warning>

O que pode dar errado com o Drizzle:

- **A página fica em "Connecting to the Drizzle Kit on localhost:4983", ou mostra tabelas de exemplo que
  você nunca criou.** O navegador está impedindo a página de alcançar a sua máquina. O Safari e o Brave
  fazem isso por padrão: use outro navegador ou desligue o Brave Shields para a página. No Chrome, permita
  o acesso à rede local quando ele pedir. O banco de dados não tem relação com isso.
- **`self-signed certificate in certificate chain`.** O `ca` não é o `.ca.pem` (muitas vezes o `.crt`
  está no lugar dele), ou uma variável está vazia e a configuração recorreu a uma URL sem os arquivos. A
  configuração acima lança um erro em vez de recorrer a ela.
- **`key values mismatch`.** O `cert` e a `key` não formam um par: confira se o `cert` é o `.crt`
  e se os dois vêm do mesmo download.
- **O objeto `ssl` parece ignorado.** Foi passada uma `url` em vez de `host`/`port`, ou a URL tem
  `?sslmode=...`, que sobrescreve o objeto.

## Solução de problemas

<AccordionGroup>
  <Accordion title="Connection refused ou timeout">
    Confira a porta na página do banco de dados e se o banco está **Online**.
  </Accordion>
  <Accordion title="self-signed certificate in certificate chain">
    A CA está ausente ou é o arquivo errado. Passe `certs/db.ca.pem` como CA: o `.crt` é o seu
    certificado de cliente, não a CA. Se a string de conexão também tiver `?sslmode=require`, ela sobrescreve
    o objeto `ssl` no Node.js `pg`; tire-a da URL.
  </Accordion>
  <Accordion title="key values mismatch">
    O certificado de cliente e a chave não formam um par. Use o `.crt` como certificado (não o `.ca.pem`)
    e pegue os dois do mesmo download: depois de **Redefinir certificados**, os arquivos antigos deixam de funcionar,
    então baixe todos novamente e envie-os outra vez no deploy.
  </Accordion>
  <Accordion title="connection requires a valid client certificate">
    O TLS está ativo, mas o `.crt` e o `.key` não foram enviados. Passe os dois, além da CA.
  </Accordion>
  <Accordion title="Falha de autenticação">
    Copie a senha novamente; depois de **Redefinir senha**, atualize `DB_PASSWORD` e reinicie a aplicação.
    Um erro que menciona `user "postgres"` indica o usuário errado: bancos criados a partir da v26.4.8 usam
    `vertracloud`. O MongoDB também precisa de `authSource=admin` na URI. No Redis, envie também o usuário (`vertracloud`): somente a senha
    é rejeitada nos bancos criados a partir da v26.4.8. Confira o usuário no campo `username` do banco.
  </Accordion>
  <Accordion title="Hostname/IP does not match certificate's altnames">
    O certificado é emitido para o host do banco. Conecte-se pelo host da página do banco de dados, não por
    um endereço IP.
  </Accordion>
  <Accordion title="ENOENT: no such file certs/db.ca.pem">
    O caminho é relativo ao diretório de trabalho do processo, que é a raiz do projeto. Confira se a pasta existe na
    aba **Arquivos**.
  </Accordion>
</AccordionGroup>

Cada mensagem, com sua causa e correção, está em
[Por que a conexão com o meu banco de dados falha?](/pt-br/databases#por-que-a-conexão-com-o-meu-banco-de-dados-falha).
