title: Save a Stack as a Template
sidebarTitle: Create from Stack
api: POST https://api.vertracloud.app/v1/templates/from-stack/{stack_id}
authMethod: bearer
description: Saves one of your stacks as a private template with one service per member, choosing variables and files for each application.
---

{/* @see RESTPostAPITemplateFromStackBody, RESTPostAPITemplateFromStackResponse — @vertracloud/api-types */}
This call saves a stack as a private template with a first version and answers `201` with the template, one service per member you choose. The connection variables of the stack become placeholders that point at the other services (`{{services.db.url}}`, for example), and each Blob folder of the stack becomes a Blob service. A member left out of the template also leaves out the variables that pointed at it. Databases are recreated empty: their data is never copied.

Needs the `templates:write` scope when called with an API key. The plan, limit and workspace rules of [Create a Private Template](/api-reference/endpoint/templates/create) apply, the template is not verified by Vertra Cloud, and the refusals of [Create Template from App](/api-reference/endpoint/templates/create-from-app) apply to each application member. Read the proposal first with [Review Template Draft](/api-reference/endpoint/templates/draft).

<ParamField path="stack_id" type="string" required>
  The stack ID.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the stack belongs to a workspace, the workspace's ID.
</ParamField>

<ParamField body="id" type="string" required>
  The slug of the template, lowercase letters, digits and hyphens.
</ParamField>

<ParamField body="name" type="object" required>
  The name by language: `pt-br` (required), `en` and `es`, up to 50 characters each.
</ParamField>

<ParamField body="description" type="object" required>
  The description by language, same shape as `name`, up to 128 characters each.
</ParamField>

<ParamField body="category" type="string" required>
  `automation`, `ai-agents`, `bots`, `apis`, `cms`, `monitoring`, `starters`, `databases` or `other`.
</ParamField>

<ParamField body="tags" type="string[]">
  Up to 10 tags.
</ParamField>

<ParamField body="version" type="string">
  The first version, as a semantic version. Default `1.0.0`.
</ParamField>

<ParamField body="permissions" type="object">
  What users of the template may do, as in the [permissions](/templates/create/permissions) of the manifest.
</ParamField>

<ParamField body="members" type="object[]" required>
  What to save of each member of the stack, an application or a database.

  <Expandable title="member object">

  <ResponseField name="resource_id" type="string" required>
    The ID of the application or database to save.
  </ResponseField>

  <ResponseField name="service_id" type="string" required>
    The id the service gets in the manifest.
  </ResponseField>

  <ResponseField name="env" type="object[]">
    One review per variable of an application. A variable without a review is left out of the template. Each review has:

    - `key`: the variable name.
    - `mode`: `question` (becomes a question the user answers; the value is not copied), `keep` (the value is copied; refused when it looks like a credential), `generate` (becomes a secret the platform generates for each user, with `generate` set to `random:<n>` or `uuid`), `hidden` (copied but hidden from whoever uses the template; the value stays out of sight of whoever uses the template) or `omit` (left out).
    - `label` and `help`: texts by language (`pt-br`, `en`, `es`), used by `question` and `generate`.
    - `generate`: how the secret is generated, `random:<n>` or `uuid`.

    Read the suggestions first with [Review Template Draft](/api-reference/endpoint/templates/draft).
  </ResponseField>

  <ResponseField name="paths" type="string[]">
    The paths of the application's `/app` that go into the template, for applications with code. Without it, everything goes in except what the draft leaves unselected. `.env*` files, the platform folder and dependency folders can never be included.
  </ResponseField>

  <ResponseField name="ram" type="object">
    The memory of the service in MB: `min`, `recommended` and optional `max`.
  </ResponseField>

  </Expandable>
</ParamField>

<ParamField body="workspace_id" type="string">
  The workspace that will own the template. Without it, the template belongs to you.
</ParamField>

```bash cURL

  -d '{

    "members": [
      { "resource_id": "app-abc123def456", "service_id": "api" },

```

</RequestExample>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for the failure. Possible values:
  - `API_KEY_SCOPE_DENIED`: The API key does not have the `templates:write` scope (`403`).
  - `STACK_NOT_FOUND`: The stack does not exist or is not yours.
  - `APP_NOT_FOUND`: A member application does not exist.
  - `TEMPLATE_SAVE_NOT_ALLOWED`: A member application came from a share link, or runs a platform image (`403`).
  - `TEMPLATE_CLOSED`: A member comes from a closed template (`403`).
  - `TEMPLATE_MANIFEST_INVALID`: The result is not a valid manifest; `details.issues` lists the findings.
  - `TEMPLATE_SECRET_IN_SOURCE`: A selected file holds a secret; `details.files` lists the paths (`400`).
  - `TEMPLATE_SLUG_TAKEN`: The slug is already in use among your templates or is reserved.
  - `TEMPLATE_PRIVATE_LIMIT_REACHED`: The account already has 5 private templates.
  - `PLAN_DOES_NOT_SUPPORT_CUSTOM_IMAGES`: The plan cannot create templates.
  - `WORKSPACE_OWNER_ONLY`: Only the workspace owner saves templates in it.
</ResponseField>
