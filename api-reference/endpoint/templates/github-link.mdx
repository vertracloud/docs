{/* @see RESTPutAPITemplateGithubBody, RESTPutAPITemplateGithubResponse — @vertracloud/api-types */}
This call links a private template to a GitHub repository and answers with the template. The repository must have `vertracloud.template.yaml` at the root of the branch and be in one of your GitHub App installations; it cannot be linked to another owner's template. Every push to the branch then publishes one version, with the commit message as the changelog and the `README.md` of the root as the documentation. The code of a service comes from the folder in its `source.path`, or from the repository without the manifest.

A push does not raise the version by itself: raise the `version` of the manifest in the commit. A push that cannot become a version is skipped (the manifest has an older version, is invalid, or the code holds a secret). Fix it and push again. Pushes to other branches are ignored.

Needs the `templates:write` scope when called with an API key. Only the owner of the template can link it, because the link uses the owner's GitHub App installations; in a workspace, a member gets `403`.

<ParamField path="template_id" type="string" required>
  The template ID.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the template belongs to a workspace, the workspace's ID.
</ParamField>

<ParamField body="repository" type="string" required>
  The repository, as `owner/name`.
</ParamField>

<ParamField body="branch" type="string">
  The branch that publishes versions. Without it, the default branch of the repository.
</ParamField>

<RequestExample>

```bash cURL
curl -X PUT https://api.vertracloud.app/v1/templates/tpl-abc123def456/github \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "repository": "acme/support-bot-template", "branch": "main" }'
```

</RequestExample>

### Response

The template object of [Create a Private Template](/api-reference/endpoint/templates/create), now with `github` set to the linked repository.

<ResponseField name="response" type="object">
  The template.

  <ResponseField name="github" type="object | null">

  </ResponseField>

  <ResponseField name="id" type="string">

  </Expandable>
</ResponseField>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for the failure. Possible values:
  - `API_KEY_SCOPE_DENIED`: The API key does not have the `templates:write` scope (`403`).
  - `TEMPLATE_NOT_FOUND`: The template does not exist or is not yours (`404`).
  - `INSTALLATION_NOT_FOUND`: The repository or the branch is not in your GitHub App installations (`404`).
  - `TEMPLATE_GITHUB_MANIFEST_NOT_FOUND`: There is no `vertracloud.template.yaml` at the root of the branch.
  - `REPO_ALREADY_LINKED`: The repository is already linked to another owner's template, an image or an application (`409`).
  - `WORKSPACE_OWNER_ONLY`: Only the workspace owner links its templates.
</ResponseField>

<ResponseExample>

```json Error Response
{
  "code": "TEMPLATE_GITHUB_MANIFEST_NOT_FOUND"
}
```

</ResponseExample>
