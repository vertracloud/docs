description: "Changes an object's visibility, cache, download name, expiration or metadata without re-uploading the file."
---

{/* @see RESTPatchAPIBlobObjectBody, RESTPatchAPIBlobObjectResponse, APIBlobObject — @vertracloud/api-types */}

Changes the settings of one object without touching its bytes. Send only the fields to change. Changing `visibility` to `public` makes the object reachable at its public `url`; changing it to `private` removes that URL. Sending `null` restores the default of a field.

**Scope:** `blob:write`.

<ParamField path="object_id" type="string" required>
  The object ID.
</ParamField>

<ParamField body="visibility" type="string">
  `public` or `private`.
</ParamField>

<ParamField body="cache_control" type="string | null">
  `immutable`, `max-age=<seconds>` or `no-cache` (Enterprise-26 or higher). `null` restores the default.
</ParamField>

<ParamField body="content_disposition" type="string | null">
  `inline` or `attachment`. `null` restores the default.
</ParamField>

<ParamField body="filename" type="string | null">
  Name suggested on download. `null` uses the last segment of `path`.
</ParamField>

<ParamField body="expires_at" type="string | null">
  ISO 8601 timestamp for deletion, at least the plan's minimum from now. `null` removes the expiration.
</ParamField>

<ParamField body="metadata" type="object">
  Keys to set. A key with the value `null` is removed. Up to 5 keys in total, 512 bytes; Enterprise-12 or higher.
</ParamField>

<ParamField query="workspace_id" type="string">
  The workspace ID, when the blob belongs to a workspace. The call acts on the blob of the workspace owner and needs the `blob:read` workspace permission (`blob:manage` on routes that change data). Leave it out to act on your own blob.
</ParamField>

### Example request

```bash
curl -X PATCH "https://blob.vertracloud.app/v1/objects/0b6f7c1e-3d2a-4f5b-9a8c-1d2e3f4a5b6c" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"visibility":"private","metadata":{"owner":"joao","old-key":null}}'
```

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for failure. Possible values:
  - `AUTH_TOKEN_MISSING` (`401`): No `Authorization` header was sent.
  - `API_KEY_INVALID` (`401`): The API key doesn't exist, was revoked, or its secret doesn't match.
  - `API_KEY_SCOPE_DENIED` (`403`): The key lacks the scope this route needs (`blob:read` or `blob:write`); `details.required` names it.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Only with `workspace_id`: you're not a member, or your role lacks the blob permission.
  - `WORKSPACE_NOT_FOUND` (`404`): Only with `workspace_id`: no workspace with that ID, or you're not a member.
  - `BLOB_NAMESPACE_SUSPENDED` (`403`): The account's blob storage is suspended, or its plan expired. Uploads and other writes are refused from the start of the 72-hour grace period.
  - `VALIDATION_ERROR` (`400`): A parameter or body field failed validation. `details.path` names the field.
  - `BLOB_OBJECT_NOT_FOUND` (`404`): No object with that ID in this account (or the workspace's blob).
  - `PLAN_RESTRICTED_FEATURE` (`403`): The plan doesn't include the setting you sent, such as `metadata` below Enterprise-12 or `no-cache` below Enterprise-26.
</ResponseField>
