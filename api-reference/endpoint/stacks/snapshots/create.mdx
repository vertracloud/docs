{/* @see RESTPostAPIStackSnapshotResponse, APIStackSnapshotAccepted — @vertracloud/api-types */}
Takes a snapshot of each application and database of the stack and groups them. Each member is a regular manual snapshot: it appears in the snapshot list of its application or database, uses the account's manual snapshot quota and is kept for 30 days. The snapshot runs in the background and the request answers **`202`** as soon as it is accepted; nothing is taken yet. Needs the `stacks:write` scope when called with an API key.

<ParamField path="stack_id" type="string" required>
  The stack ID.
</ParamField>

<ParamField query="workspace_id" type="string">
  The workspace the stack belongs to, when you act on it as the workspace owner.
</ParamField>

### Response

The quota and the checks of **every** member are made before the `202`: if one member cannot be snapshotted (no quota, a plan without manual snapshots, a restore or a deploy in progress), the request answers with that member's error, nothing is started and the quota used is given back. See [Create Application Snapshot](/api-reference/endpoint/apps/snapshots/create) for those codes.

Follow each `job_id` on [Get Snapshot Job](/api-reference/endpoint/apps/snapshots/jobs/get) (`GET /v1/users/{id}/snapshots/jobs/{job_id}`, where `{id}` is the job's `resource_id`) until its `status` is `ready` or `failed`. The stack snapshot `id` is listed on [List Stack Snapshots](/api-reference/endpoint/stacks/snapshots/list) as `pending` and becomes `ready` when every job is `ready`; only then can it be restored. If a member fails, the stack snapshot is not listed, and the snapshots of the members that succeeded stay in their lists as regular snapshots.

<ResponseField name="response" type="object">
  <Expandable title="Toggle object">

  <ResponseField name="id" type="string">The stack snapshot ID, the one the list returns.</ResponseField>

  <ResponseField name="jobs" type="array">
    One snapshot job per member that has data, databases first. Each item has `resource_id`, `resource_type` (`application` or `database`) and `job_id`.
  </ResponseField>

  </Expandable>
</ResponseField>

### Errors

| Status | Code | When |
|---|---|---|
| 403 | `PLAN_NOT_ALLOWED` | The plan does not include manual snapshots. |
| 403 | `WORKSPACE_OWNER_ONLY` | You are a workspace member, not the owner. |
| 404 | `STACK_NOT_FOUND` | The stack was not found. |
| 404 | `STACK_MEMBER_NOT_FOUND` | The stack has no application or database. |
| 409 | `OPERATION_IN_PROGRESS` | A snapshot of this stack is already running. |
| 429 | `SNAPSHOT_RATE_LIMITED` | A member has no manual snapshot quota left, or was snapshotted less than 3 minutes ago. |
