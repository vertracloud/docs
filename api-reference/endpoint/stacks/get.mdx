{/* @see RESTGetAPIStackResponse, APIStack, APIStackMember, APIStackBinding — @vertracloud/api-types */}
Returns a stack and everything in it: applications, databases and Blob folders, the connections between them, the status of the members added up and, when the stack came from a template, the template and version. Needs the `stacks:read` scope when called with an API key.

<ParamField path="stack_id" type="string" required>
  The stack ID.
</ParamField>

<ParamField query="workspace_id" type="string">
  The workspace the stack belongs to. Required for a workspace member acting on a stack they do not own; the owner may omit it.
</ParamField>

### Response

<ResponseField name="response" type="object">
  The stack.

  <Expandable title="Toggle object">

  <ResponseField name="id" type="string">The stack ID.</ResponseField>
  <ResponseField name="name" type="string">The stack name.</ResponseField>
  <ResponseField name="description" type="string | null">Optional description, or `null`.</ResponseField>

  <ResponseField name="network_mode" type="string">
    How the members reach each other. The value is `public`: services use their public addresses and databases are reached with client certificates.
  </ResponseField>

  <ResponseField name="owner_id" type="string">The account that owns the stack.</ResponseField>
  <ResponseField name="workspace_id" type="string | null">The workspace the stack belongs to, or `null` when it belongs to you.</ResponseField>

  <ResponseField name="members" type="object[]">
    The members. Each has `resource_type` (`application`, `database` or `blob`), `resource_id`, `name`, `status` (`null` for a Blob folder), `ram` in MB (`0` for a Blob folder), `service_key` (the service id in the template, `null` for a member you added), `database_type` (the engine of a database, otherwise `null`), `closed` (`true` for an application of a [closed template](/templates/use/closed-templates): its code is not accessible) and `blob`.

    For a Blob member, `blob` has the folder `prefix`, `visibility` (`private` or `public`), `used_bytes` (or `null`) and `api_key_id`, the key the platform created for the stack and restricted to that folder. See [Add Blob Folder](/api-reference/endpoint/stacks/blob/create).
  </ResponseField>

  <ResponseField name="status" type="object">
    Members online, offline and building, added up: `up`, `down`, `building` and `total` (the members that have a status).
  </ResponseField>

  <ResponseField name="ram_total" type="integer">Memory of every member, in MB.</ResponseField>

  <ResponseField name="bindings" type="object[]">
    The connections between members. Each has `id`, `stack_id`, `app_id` (the application that receives the variables), exactly one of `database_id`, `blob_id` and `target_app_id`, `env_map` (variable name to what it receives), `certs_path` (the folder inside the application where the client certificates of a database are written, `null` without a database) and `created_at`. See [Create Connection](/api-reference/endpoint/stacks/bindings/create).
  </ResponseField>

  <ResponseField name="template" type="object | null">
    The template and version the stack came from, or `null` for a stack assembled by hand. It has the same fields as the `template` of an [application](/api-reference/endpoint/apps/get), including `icon_url`, the stable URL of the template icon (`null` when there is none).
  </ResponseField>

  <ResponseField name="update_available" type="boolean">`true` when the template has a newer version the stack can update to.</ResponseField>
  <ResponseField name="created_at" type="string" format="date-time">When the stack was created.</ResponseField>
  <ResponseField name="updated_at" type="string" format="date-time">When the stack was last updated.</ResponseField>

  </Expandable>
</ResponseField>

### Errors

| Status | Code | When |
|---|---|---|
| 403 | `API_KEY_SCOPE_DENIED` | The key does not have `stacks:read`. |
| 404 | `STACK_NOT_FOUND` | The stack does not exist or belongs to another account. |
