{/* @see RESTGetAPIApplicationAnalyticsErrorsQuery, APIApplicationAnalyticsErrors — @vertracloud/api-types */}
Returns the errors of the site of an application: the total and rate, a time series, the paths that fail the most and how the errors spread across status codes. By default only 5xx counts as an error, because 4xx is noisy (mostly bots and scanners); send `include_4xx=true` to count it too. It is the data of [Errors](/web-analytics/errors).

<ParamField path="id" type="string" required>
  The application ID. If the application belongs to a workspace, pass its ID in the `workspace_id` query parameter.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the application belongs to a workspace, the workspace's ID. Required for workspace members acting on an application they don't own.
</ParamField>

<ParamField query="start" type="string" format="date-time">
  Start of the window (ISO 8601). Default: 24 hours before `end`.
</ParamField>

<ParamField query="end" type="string" format="date-time">
  End of the window (ISO 8601). Default: now. It cannot be in the future.
</ParamField>

<ParamField query="compare" type="boolean" default="false">
  Also send the previous period, of the same length and right before the window, in `previous`. Default `false`.
</ParamField>

<ParamField query="compare_start" type="string" format="date-time">
  Start of the period to compare with (ISO 8601). The compared period has the same length as the window (`end` minus `start`) and starts here; `previous.start` and `previous.end` in the response show it. Implies `compare=true`, and it cannot be sent with `compare=false`. Without it, `compare=true` compares with the period right before the window.
</ParamField>

<ParamField query="include_4xx" type="boolean" default="false">
  Count 4xx as errors too, in `errors`, `error_rate`, `paths` and `statuses`. Default `false`.
</ParamField>

<ParamField query="limit" type="integer" default="10">
  Entries in `paths` and `statuses`, from 1 to 25. Default 10.
</ParamField>

The window is at most 30 days long and cannot start earlier than the history of the plan (7 or 30 days, see [Plans and limits](/plans-and-limits)).

### Filters

Every dimension below is also a filter, and all of them can be combined: each one narrows every part of the answer. Each takes **one value**, exactly as it appears in a breakdown entry or a request of the log, so a value you read in a response can be sent back unchanged. Send `(none)` to keep only the requests that have nothing for the dimension.

  <Expandable title="Toggle object">

  </ResponseField>

  <ResponseField name="include_4xx" type="boolean">
    Whether 4xx counted as an error in this answer.
  </ResponseField>

  <ResponseField name="summary" type="object | null">
    Totals of the window. `null` when there was no request in the window. `requests`, `errors`, `error_rate`, `errors_4xx`, `errors_5xx`.
  </ResponseField>

  <ResponseField name="series" type="object[]">
    Points of the time series; `time` is the start of each point, with `requests`, `errors_4xx` and `errors_5xx`.
  </ResponseField>

  <ResponseField name="previous" type="object | null">
    The previous period, only with `compare=true`; otherwise `null`. It has `start`, `end`, a `summary` (`null` when there was no request in it) and a `series` with the same `interval` and number of points as the current one, in the same order.
  </ResponseField>

  <ResponseField name="paths" type="object[]">
    Paths with the most errors, highest `errors` first. `value` is the path; send it as the `path` filter.
  </ResponseField>

  <ResponseField name="statuses" type="object[]">
    How the errors spread across status codes, highest `requests` first. `value` is the status, such as `502`.
  </ResponseField>

  Fields of `summary`:

  <ResponseField name="requests" type="integer">
    Requests answered.
  </ResponseField>
  <ResponseField name="errors" type="integer">
    `errors_5xx`, plus `errors_4xx` with `include_4xx=true`.
  </ResponseField>
  <ResponseField name="error_rate" type="number">
    `errors / requests`, from 0 to 1.
  </ResponseField>
  <ResponseField name="errors_4xx" type="integer">
    Requests answered with a 4xx status.
  </ResponseField>
  <ResponseField name="errors_5xx" type="integer">
    Requests answered with a 5xx status.
  </ResponseField>

  Entries of `paths`: `value`, `requests`, `errors` (counts 4xx only with `include_4xx=true`) and `error_rate`. Entries of `statuses`: `value`, `label`, `requests`, `visits` and `bytes`.

  </Expandable>
</ResponseField>

### Notes

- Requires the `apps:read` scope when called with an API key. Workspace members need permission to read the application.
- All plans.
- **Sampling.** When traffic is high the numbers are estimated from a sample and `sampled` is `true`. See [Sampling and delay](/web-analytics/sampling-and-delay).
- **Delay.** Data refreshes about every 5 minutes, so the newest requests can take a few minutes to show up. If the latest data cannot be read right now, an earlier answer may come back with `stale: true` (check `generated_at`); otherwise the call fails with `ANALYTICS_BUSY`.
- **Privacy.** Vertra Cloud stores nothing about visitors; it keeps only per-app totals (counts, visits, bytes, error rates and response times) for up to 31 days, deleted with the app. No IP, path, query string or user agent is kept. `ip` and `query` come back unmasked; masking is a choice of the client that shows them. See [Privacy](/web-analytics/privacy).

### Error Responses

| Status | Code | When |
|---|---|---|
| 401 | `AUTH_TOKEN_MISSING` / `API_KEY_INVALID` / `SESSION_REVOKED` | The `Authorization` header is missing, the API key is invalid or the dashboard session was revoked. |
| 403 | `API_KEY_IP_DENIED` / `API_KEY_SCOPE_DENIED` | The API key is used from an IP outside its allowlist, or it lacks the `apps:read` scope. |
| 403 | `ACCESS_DENIED` | The application belongs to another account, or you lack the workspace permission to read it. |
| 403 | `PLAN_REQUIRED` | The account has no active plan. |
| 404 | `APP_NOT_FOUND` | The application does not exist. |
| 400 | `VALIDATION_ERROR` | A parameter failed validation, such as `limit` out of range, an invalid `cursor` or a malformed `start`/`end` date; `details.path` names the field. Also when `compare_start` is malformed or is sent with `compare=false`. |
| 400 | `INVALID_RANGE` | `start` is after `end`, `end` is in the future or the window is longer than 30 days. Also when the period starting at `compare_start` ends after `start`, so it would overlap the window. |
| 400 | `ANALYTICS_RANGE_EXCEEDS_PLAN` | `start` is earlier than the plan can read. `details.history_days` has the limit in days and `details.earliest` the earliest `start` accepted right now. Also when `compare_start` is earlier than the plan can read. |
| 429 | `RATE_LIMIT_EXCEEDED` | Too many queries in a row. `details.retry_after` gives the wait in seconds; the `Retry-After` header always comes with it. |
| 503 | `ANALYTICS_BUSY` | High-demand moment and no recent answer available for the query. Wait `details.retry_after` seconds and try again. |
