{/* @see RESTPostAPIApplicationStartResponse — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  The application ID to start. If the application belongs to a workspace, pass its ID in the `workspace_id` query parameter.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the application belongs to a workspace, the workspace's ID. Required for workspace members acting on an application they don't own.
</ParamField>

### Response

  <Expandable title="Toggle object">

  <ResponseField name="status" type="string">

  </ResponseField>

  </Expandable>
</ResponseField>

```json Response
    "status": "success"
  }

```

</ResponseExample>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for the failure. Possible values:
  - `APP_NOT_FOUND`: The specified application was not found.
  - `ACCESS_DENIED`: You are a workspace member without the permission for this action, or you did not send the `workspace_id` (`403`).
  - `PLAN_REQUIRED`: The account that owns the application has no active plan (`403`). Subscribe to a plan to continue.
  - `APP_SHIELD_COOLDOWN`: Vertra Shield paused the application; this action is blocked until the pause ends (`403`). `details.until` says when.
- `VALIDATION_ERROR`: The application has a start or build command with a line break, saved before commands had to be a single line (`400`). `details.path` is `start_command` or `build_command`. Save a single-line command in [Update Application Configuration](/api-reference/endpoint/apps/updateconfig) and try again.
  - `OPERATION_IN_PROGRESS`: Another lifecycle operation on the same application is already running (`409`). The container was not touched — wait a few seconds and retry. See [Common Error Codes](/api-reference/introduction#what-error-codes-can-the-api-return).
</ResponseField>

<ResponseExample>

```json Error Response (409)
{
  "code": "OPERATION_IN_PROGRESS"
}
```

</ResponseExample>
