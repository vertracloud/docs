{/* @see binary zip — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  The application ID to download. If the application belongs to a workspace, pass its ID in the `workspace_id` query parameter.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the application belongs to a workspace, the workspace's ID. Required for workspace members acting on an application they don't own.
</ParamField>

### Response

The response is a binary ZIP file containing the application files plus a `vertracloud.config` generated from the current settings (name, main file, memory, version, start command, auto-restart, subdomain), so the ZIP can be uploaded again with the same configuration.

- **Content-Type**: `application/zip`
- **Content-Disposition**: `attachment; filename="app-{id}.zip"`
- **Content-Length**: The size of the ZIP file in bytes.

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for the failure. Possible values:

  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: The `Authorization` header is missing, the API key is invalid, or the dashboard session was revoked (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: The API key is used from an IP outside its allowlist, or it lacks the scope the route requires (`403`).
  - `ACCESS_DENIED`: The application belongs to another account, or you lack the workspace permission to download its files (`403`).
  - `APP_NOT_FOUND`: The specified application does not exist (`404`).
  - `INTERNAL_SERVER_ERROR`: The application files could not be downloaded (`500`).
</ResponseField>

<ResponseField name="message" type="string">
  A descriptive message providing additional details about the error.
</ResponseField>

<ResponseExample>

```json Error Response (404)

  "code": "APP_NOT_FOUND"
```


</ResponseExample>
