{/* @see success/error — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  The ID of the application or database to snapshot.
</ParamField>

<ParamField query="scope" type="string" required>
  The resource type. Possible values: `applications`, `databases`.
</ParamField>

<Note>
  **Three limits apply to manual snapshots.** Each user can request one every **5 seconds**; the same resource can be
  snapshotted once every **3 minutes**; and the account has a quota over any **24 hours**, counted from each snapshot
  (the slot frees up 24 hours after it was used, not at midnight): **8 per GB of the plan's RAM, at least 2**, across all
  its resources (8 on Starter 1, 16 on Starter 2, 32 to 64 on Pro, 96 to 192 on Business). There is no daily limit per resource. Asking
  again within 5 seconds answers the generic `429 RATE_LIMIT_EXCEEDED` with `retry_after`. Over the resource or the
  account limit the API answers `429 SNAPSHOT_RATE_LIMITED` with `details.scope` (`resource` or `account`) and
  `details.retry_after` in seconds; with `account`, `details` also has `resets_at`, the moment a slot frees up, in ISO 8601.
  The daily backup of your plan does not use the quota. See [Rate Limiting](/api-reference/introduction#how-is-the-api-rate-limited).
</Note>

While an application is being snapshotted, deploys, rollbacks, restarts, starts, stops, environment variable changes, restores and the file
manager's writes answer `409 OPERATION_IN_PROGRESS`; try again in a few moments.

### Response

The snapshot is ready within 90 seconds in most cases: the answer is **`201`** with the snapshot. When it takes longer, the
answer is **`202`** with a `job_id`: this is not an error and the snapshot keeps being taken. Follow
`response.job_id` on [Get Snapshot Job](/api-reference/endpoint/apps/snapshots/jobs/get); the snapshot shows up in the
[list](/api-reference/endpoint/apps/snapshots/getall) when it is ready. Clients must handle both answers.

  </ResponseField>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for failure. Possible values:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: The `Authorization` header is missing, the API key is invalid, or the dashboard session was revoked (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: The API key is used from an IP outside its allowlist, or it lacks the scope the route requires (`403`).
  - `USER_NOT_FOUND`: The authenticated user was not found.
  - `APP_NOT_FOUND`: The specified application was not found.
  - `DATABASE_NOT_FOUND`: The specified database was not found.
  - `ACCESS_DENIED`: You are a workspace member without the permission for this action, or you did not send the `workspace_id` (`403`).
  - `PLAN_NOT_ALLOWED`: The account's plan does not include manual snapshots (`403`).
  - `DATABASE_NOT_RUNNING`: The database must be running to take a snapshot (`409`). Redis has no such requirement.
  - `DATABASE_NOT_READY`: The database is not ready yet (`503`). Try again shortly; the quota slot is given back.
  - `APP_BUILDING`: The application is being built or deployed (`409`). Try again when it ends.
  - `RESTORE_IN_PROGRESS`: A restore is running on this resource (`409`).
  - `RATE_LIMIT_EXCEEDED`: The user asked again within 5 seconds (`429`). Comes with `retry_after`.
  - `SNAPSHOT_RATE_LIMITED`: The resource was snapshotted less than 3 minutes ago, or the account used its quota for the last 24 hours (`429`). Comes with `details.scope` (`resource` or `account`) and `details.retry_after`; with `account`, also `details.resets_at`.
  - `SNAPSHOT_TOO_LARGE`: The content is above the size a snapshot of this resource can hold (`413`). `details.max_bytes` has the limit.
  - `OPERATION_IN_PROGRESS`: Another operation on the same resource, or another snapshot of yours, is already running (`409`). Nothing new was snapshotted; the quota slot is given back.
  - `SNAPSHOT_FAILED`: The snapshot could not be taken. `422` for a database whose data could not be exported (for example, a database with no data yet): nothing was saved; add data or check the database, then try again. `500` in any other case: try again; if it keeps happening, contact support.
  - `SERVICE_UNAVAILABLE`: The service is temporarily unavailable (`503`). Try again shortly.
  - `SNAPSHOT_TIMEOUT`: The snapshot took too long and was cancelled (`504`).
  - `INTERNAL_SERVER_ERROR`: The snapshot could not be stored, or an unexpected failure occurred (`500`). Retry later.
</ResponseField>
