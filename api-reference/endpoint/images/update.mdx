description: Renames a custom Docker image and/or changes its description, without building anything.
---

{/* @see RESTPatchAPICustomImageBody, RESTPatchAPICustomImageResult — @vertracloud/api-types */}
Changes the image's `name` and/or `description`. Nothing is built or restarted: the image keeps its ID and versions, and the applications created from it keep running. Send only the fields you want to change; at least one is required. Platform images (`owner: "system"`) cannot be changed.

Needs the `images:write` scope when called with an API key. In a workspace, you need permission to manage the workspace's apps.

<ParamField path="image_id" type="string" required>
  The image ID.
</ParamField>

<ParamField query="workspace_id" type="string">
  If the image belongs to a workspace, the workspace's ID.
</ParamField>

<ParamField body="name" type="string">
  The new name: 1 to 50 characters, unique among the owner's images. Sending the current name is not an error. A name already used by another of your images fails with `VALIDATION_ERROR`, with `path` set to `name`.
</ParamField>

<ParamField body="description" type="string | null">
  The new description, up to 128 characters (free text). `null` or an empty string removes it.
</ParamField>

### Response

  The updated image.

  </ResponseField>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for the failure. Possible values:
  - `API_KEY_SCOPE_DENIED`: The API key does not have the required scope (`403`).
  - `VALIDATION_ERROR`: The body is empty, the name is not 1 to 50 characters, the name is already used by another of your images (`path` is `name`), the description is longer than 128 characters, or the name or description has control characters (`400`).
  - `ACCESS_DENIED`: The image is a platform image, which cannot be changed (`403`).
  - `IMAGE_NOT_FOUND`: The image does not exist or you cannot access it (`404`).
  - `INTERNAL_SERVER_ERROR`: Unexpected failure (`500`).
</ResponseField>
