{/* @see APIDatabase — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  The ID of the database to update.
</ParamField>


<ParamField query="workspace_id" type="string">
  If the database belongs to a workspace, the workspace's ID.
</ParamField>

<ParamField body="name" type="string">
  The new name for the database. 1 to 50 characters.
</ParamField>

<ParamField body="description" type="string | null">
  The new description, up to 128 characters. An empty string or `null` clears it.
</ParamField>

<ParamField body="ram" type="number">
  The new RAM in MB, a positive integer. It must fit in the plan's free memory and respect the
  engine's minimum (512 MB for Redis, 1024 MB for the others). Changing the memory applies right away, raising or lowering it. If the database is using more memory than the new limit at that moment, it is shut down for lack of memory; the dashboard warns you and asks you to confirm before saving. The database's storage follows its memory, so lowering the memory of a database that holds more data than the new storage allows is refused with `409` `STORAGE_ABOVE_NEW_LIMIT`.
</ParamField>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for failure. Possible values:
  - `VALIDATION_ERROR`: A body or query field failed validation (`400`).
  - `INVALID_RAM_LIMIT`: The requested RAM is outside what the engine and plan allow (`400`).
  - `MEMORY_LIMIT_EXCEEDED`: The plan doesn't have enough free memory for the new RAM (`400`).
  - `ACCESS_DENIED`: You are a workspace member without the permission for this action, or you did not send the `workspace_id` (`403`).
  - `DATABASE_NOT_FOUND`: The database was not found (`404`).
  - `OPERATION_IN_PROGRESS`: Another lifecycle operation is running on this database (`409`).
  - `STORAGE_ABOVE_NEW_LIMIT`: The database holds more data than the storage the new RAM allows (`409`). Nothing was changed.
</ResponseField>

<ResponseField name="details" type="object">
  Present on `STORAGE_ABOVE_NEW_LIMIT`. Carries `used_mb`, `limit_mb` and `free_mb`: how much the database holds, the storage the requested RAM would allow, and how much has to be deleted before the change is accepted.
</ResponseField>

```json Error Response (409)
  "code": "STORAGE_ABOVE_NEW_LIMIT",

  }
}
```

</ResponseExample>
