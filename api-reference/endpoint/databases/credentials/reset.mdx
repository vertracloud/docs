---
title: Reset Database Certificates
sidebarTitle: Reset Certificates
api: POST https://api.vertracloud.app/v1/databases/{id}/credentials/certificate/reset
authMethod: bearer
description: Resets the certificates for a specific database by its ID.
---

{/* @see success — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  The ID of the database to reset certificates for.
</ParamField>

### Response

<ResponseField name="response" type="object">
  The new certificate details for the database.

  <Expandable title="Toggle object">

  <ResponseField name="pem" type="string">
    The new PEM certificate.
  </ResponseField>

  <ResponseField name="crt" type="string">
    The new CRT certificate.
  </ResponseField>

  <ResponseField name="key" type="string">
    The new private key for the certificate.
  </ResponseField>

  <ResponseField name="ca" type="string">
    The CA certificate (PEM) that signs the database server certificate. Absent on older databases.
  </ResponseField>

  <ResponseField name="p12" type="string">
    The new client identity as PKCS#12, encoded in base64, with an empty password. Absent on older databases.
  </ResponseField>

  <ResponseField name="restart_required" type="boolean">
    `true` when at least one application of a connected stack must restart to read the new certificates.
  </ResponseField>

  <ResponseField name="apps_to_restart" type="string[]">
    The IDs of those applications. Empty when `restart_required` is `false`.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "pem": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "crt": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "key": "-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----",
    "ca": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "p12": "MIIJqQIBAzCCCW8GCSqGSIb3DQEHAaCCCWAEgglc...",
    "restart_required": false,
    "apps_to_restart": []
  }
}
```

</ResponseExample>

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for failure. Possible values:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: The `Authorization` header is missing, the API key is invalid, or the dashboard session was revoked (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: The API key is used from an IP outside its allowlist, or it lacks the scope the route requires (`403`).
  - `ACCESS_DENIED`: The resource belongs to another account, or you lack the workspace permission for it (`403`).
  - `DATABASE_NOT_FOUND_OR_FORBIDDEN`: The specified database does not exist or the user lacks access.
  - `FAILED_TO_RESET_CERTIFICATES`: Failed to reset the certificates.
</ResponseField>

<ResponseField name="message" type="string">
  A descriptive message providing additional details about the error.
</ResponseField>

```json Error Response (404)
}
```

```json Error Response (500)

}
```

</ResponseExample>
