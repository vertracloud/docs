{/* @see RESTPostAPIOrderQuoteBody, RESTPostAPIOrderQuoteResponse — @vertracloud/api-types */}
Returns the amount that an order for a plan and a billing period would charge your account, with the period discount and an optional coupon already applied. Nothing is created and the coupon is not used. Call it before [Create Order](/api-reference/endpoint/billing/create-order) to show the final price.

Needs the `billing:read` scope when called with an API key. It is limited to 10 requests per minute.

<ParamField body="plan" type="string" required>
  The plan name, such as `starter-1`, `pro-4` or `business-12`. The names and prices are in [List Plans](/api-reference/endpoint/plans/list).
</ParamField>

<ParamField body="months" type="integer" required>
  The billing period: `1`, `3`, `6` or `12`. A 3-month period gets 10% off the monthly price, 6 months get 15% off and 12 months get 25% off.
</ParamField>

<ParamField body="coupon" type="string">
  An optional discount coupon code. The quote checks the coupon the same way [Create Order](/api-reference/endpoint/billing/create-order) does.
</ParamField>

<Note>
  The price depends on the account. If the account has a plan from before the current grid and buys the equivalent of its own plan, `legacy_price` is `true` and `total` is the price it already pays, until `legacy_price_until`. Only the monthly period keeps that price. Longer periods use the current price with the period discount.
</Note>

### Response

<ResponseField name="response" type="object">
  <Expandable title="Toggle object">

  <ResponseField name="plan" type="string">
    The plan name.
  </ResponseField>

  <ResponseField name="months" type="integer">
    The billing period in months.
  </ResponseField>

  <ResponseField name="list_price" type="number">
    The monthly price of the plan times the months, in BRL, before any discount.
  </ResponseField>

  <ResponseField name="period_discount_percent" type="number">
    The discount of the billing period: 0, 10, 15 or 25.
  </ResponseField>

  <ResponseField name="coupon" type="object | null">
    The coupon applied, or `null` when you sent none or when the referral discount was larger (see `discount_source`).

    <Expandable title="Toggle object">
    <ResponseField name="code" type="string">The coupon code.</ResponseField>
    <ResponseField name="discount" type="number">The amount the coupon takes off, in BRL.</ResponseField>
    </Expandable>
  </ResponseField>

  <ResponseField name="referral_discount" type="number | null">
    The referral discount, in BRL, that the account is entitled to on its first paid purchase. `null` when it doesn't apply. It is returned even when a coupon is larger and wins: the two never add up, the larger one is used.
  </ResponseField>

  <ResponseField name="referral_balance_applied" type="number">
    Always `0` when you call the route with an API key.
  </ResponseField>

  <ResponseField name="discount_source" type="string | null">
    Which discount `total` applies: `coupon`, `referral` or `null` when none.
  </ResponseField>

  <ResponseField name="total" type="number">
    The final price in BRL: the amount an order for the same plan, period and coupon charges.
  </ResponseField>

  <ResponseField name="legacy_price" type="boolean">
    `true` when `total` is the price the account had before the current grid.
  </ResponseField>

  <ResponseField name="legacy_price_until" type="string | null" format="date-time">
    Until when the price of the previous grid applies, in ISO 8601. `null` when `legacy_price` is `false`.
  </ResponseField>

  <ResponseField name="payment_methods" type="string[]">
    The payment methods the plan accepts: `pix` and `card`.
  </ResponseField>

  </Expandable>
</ResponseField>

<RequestExample>

```bash cURL
curl -X POST https://api.vertracloud.app/v1/orders/quote \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \

```

### Error Responses

<ResponseField name="code" type="string">
  The error code indicating the reason for failure. Possible values:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: The `Authorization` header is missing, the API key is invalid, or the dashboard session was revoked (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: The API key is used from an IP outside its allowlist, or it lacks the `billing:read` scope (`403`).
  - `USER_NOT_FOUND`: The authenticated user was not found.
  - `INVALID_PAYLOAD`: The request body failed validation.
  - `INVALID_PLAN`: The plan name does not exist.
  - `INVALID_MONTHS`: `months` is not `1`, `3`, `6` or `12`.
  - `PLAN_NOT_FOR_SALE`: The plan is no longer sold (`400`).
  - `COUPON_INVALID`, `COUPON_INACTIVE`, `COUPON_NOT_STARTED`, `COUPON_EXPIRED`, `COUPON_EXHAUSTED`, `COUPON_USER_LIMIT`, `COUPON_AUDIENCE`, `COUPON_PLAN`, `COUPON_DURATION`: The coupon cannot be used for this account, plan or period (`400`). The codes are listed in [Errors](/api-reference/errors).
  - `RATE_LIMIT_EXCEEDED`: More than 10 requests in a minute (`429`).
  - `INTERNAL_SERVER_ERROR`: An unexpected server error occurred.
</ResponseField>

<ResponseExample>


</ResponseExample>
