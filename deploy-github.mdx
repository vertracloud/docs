A Vertra Cloud application can be created from a public or private GitHub repository, and updated
automatically on every push to the branch you choose. Creating from GitHub works on any plan; automatic
deploy requires the **Intermediary** plan or higher.

## Create the application from GitHub

<Steps>
  <Step title="Open New Project">
    In the dashboard, click **New Project** and choose **Import from GitHub**.
  </Step>
  <Step title="Provide the repository">
    Paste the repository URL (`https://github.com/owner/repository`) or use **choose from my
    repositories** to list your account's repositories. Private repositories require connecting
    your GitHub account, which installs the Vertra Cloud app on the repositories you authorize.
  </Step>
  <Step title="Choose the branch">
    The repository's default branch comes pre-selected. Pick another branch and the file tree and
    the imported code switch to it.
  </Step>
  <Step title="Follow the normal flow">
    From here the flow is the same as uploading a `.zip`: build, environment, network, review and
    deploy. See [First deploy](/how-to-host).
  </Step>
</Steps>

To push a new version later, enable automatic deploy below or use `vertra deploy` in the
[CLI](/cli).

## Enable automatic deploy

With automatic deploy on, every push to the chosen branch publishes the new version: the platform
downloads the code from that commit and deploys it. Without a chosen branch, a push to `main` or
`master` deploys.

1. On the application, open **Config** and go to **Automatic deploy**.
2. Choose the GitHub account and the repository.
3. Choose the branch. The repository's default branch comes pre-selected. If the branch list can't be loaded, the webhook follows `main` or `master`.
4. Click **Create Webhook**.

Vertra Cloud creates the webhook on the repository for you; nothing needs to be configured on
GitHub. The same section shows the current branch and lets you change it; linking again without a
branch goes back to `main` or `master`. To turn it off, use **Delete Webhook**. The webhook is also
removed when the application is deleted.

<Note>
  Pushes to other branches are ignored. Webhooks created before branch selection existed keep
  following `main` and `master`. Each push counts toward the plan's
  [deploys-per-hour limit](/plans-and-limits#deploys-per-hour-limit); a push that arrives once the
  limit is exceeded is dropped and logged in the **Activity** tab.
</Note>

## Via the API

Automatic deploy can also be created, checked and removed via the
[deploys API](/api-reference/endpoint/apps/deploys/webhookurl), with a key that has the
`apps:write` scope.
