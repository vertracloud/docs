Vertra does not store anything about your visitors for Web Analytics; it stores the totals of your site. Detailed views are read from our edge network when you open them.

## What is stored

- **Nothing about individual visitors.** No IP address, no path, no query string, no user agent, no profile, no cookie, no script and no fingerprint.
- **The totals of your site.** For each app, Vertra keeps counts of requests and visits, bytes served, error rates and response time. These are plain totals, not tied to any person. They are kept for up to 31 days and deleted when you delete the app.

## What you see

Requests contain information that can identify a person or carry secrets, so the panel hides it by default:

| Data | Default |
|---|---|
| **IP address** | Masked |
| **Query string** (the part after `?`) | Masked |
| Route and path, country, device, status, timing | Shown |

**Show data** reveals the two masked columns for the current screen session only. The choice is not saved, so the next visit starts masked again. The mask protects the screen, for example during a screen share. The API returns the same fields to your authenticated requests, so treat access to your account and tokens accordingly.

## Who can see it

Only accounts allowed to see an application can see its Analytics: the owner and workspace members with permission to view the app. The hostnames queried always come from your own application, never from the request, so one account cannot read another's traffic.

## Your visitors

Because Web Analytics sets no cookie and runs no script in the browser, it does not by itself add anything to your own cookie notice. If your site does collect personal data in other ways, your own obligations toward visitors still apply.

See [Introduction to Web Analytics](/web-analytics/overview) for how the data is measured.
