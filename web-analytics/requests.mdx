The Requests sub-tab is a log with one row per request, so you can inspect a single visit instead of totals. It is available on Pro and above.

Same data through the API: [Application requests](/api-reference/endpoint/apps/analytics/requests).

## Columns

| Column | Meaning |
|---|---|
| **Time** | When the request arrived. |
| **Request ID** | Each request has a unique identifier, shown as selectable text in the request detail. |
| **Method and route** | For example `GET /pricing`. |
| **Query** | The part after `?`. Masked by default. |
| **Status** | The status the visitor received, and the status your app returned when it answered. They differ when the edge answered by itself, such as a cached or blocked request. |
| **Cache** | Whether the answer came from the edge cache or from your app. |
| **Host** | Which hostname was requested: the subdomain or one of your custom domains. |
| **Edge time and container time** | The two clocks explained in [Performance](/web-analytics/performance). |
| **Country, data center, network** | Where the visitor connected from and which edge location answered. |
| **IP** | The visitor's address. Masked by default. |
| **Device, system, browser** | Taken from the visitor's user agent. |
| **Bot** | The category, when the visitor is a known automated client. |
| **Referrer, protocol, content type** | The remaining context of the request. |

## Filtering, sorting and paging

The table accepts the same [filters](/web-analytics/traffic#cross-filters) as the other sub-tabs, so a click on a status in Errors becomes a list of exactly those requests here. Sort from newest to oldest or the reverse, and page through the results.

## Masked IP and query

IP addresses and query strings can identify a person or carry tokens, so the panel **hides both by default**. Press **Show data** to reveal them. The choice lasts for the current screen session and is not saved. The route and path are never hidden. See [Privacy](/web-analytics/privacy).

## Sample and delay

Each row is a real request, but with high traffic the table is a **sample**, not every request. New rows can take a few minutes to appear. A notice appears in both cases; see [Sampling and delay](/web-analytics/sampling-and-delay).
