## Common Structure

Regardless of the framework chosen, every deployment on Vertra Cloud follows the same structure:

<Steps>
  <Step title="Prepare the project">
    Make sure dependencies are declared (`package.json`, `requirements.txt`, `go.mod`...) and, for
    websites, that the app listens on port 80.
  </Step>
  <Step title="Send the code">
    **New Project** in the dashboard (ZIP or GitHub), `vertra deploy` in the CLI, or the VS Code
    extension. The platform detects the runtime, main file and commands; review them before deploying.
  </Step>
  <Step title="Verify">
    Monitor logs and application status in the dashboard.
  </Step>
</Steps>

## `vertracloud.config` File

An optional `vertracloud.config` file at the project root pre-fills the creation flow:

```ini
MAIN=index.js
START=npm start
MEMORY=512
```

Every key and its limits are in [Configuration](/configuration).

## Application Port

Web applications must listen on the port defined by the `PORT` environment variable. The platform automatically injects this variable into the container.

<Tabs>
  <Tab title="Node.js">
    ```javascript
    const port = process.env.PORT || 80;
    app.listen(port, '0.0.0.0', () => {
      console.log(`Server running on port ${port}`);
    });
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    port = int(os.environ.get('PORT', 80))
    app.run(host='0.0.0.0', port=port)
    ```
  </Tab>
  <Tab title="Go">
    ```go
    port := os.Getenv("PORT")
    if port == "" {
        port = "80"
    }
    http.ListenAndServe("0.0.0.0:"+port, nil)
    ```
  </Tab>
</Tabs>

<Warning>
  Always use `0.0.0.0` as host instead of `localhost` or `127.0.0.1`. Inside the container, binding must be on all interfaces for external traffic to reach the application.
</Warning>
