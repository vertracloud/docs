## Hosting a Discord bot on Vertra Cloud

A Discord bot runs on Vertra Cloud as a **bot**-type application: a background process with no
exposed HTTP port, restarted automatically when it crashes and streamed live to the dashboard log.
Vertra Cloud is a Brazilian application hosting platform (PaaS), and Discord, WhatsApp and Telegram
bots are first-class workloads on it — the same containers, snapshots and metrics as any other
application.

This guide covers both `discord.js` (JavaScript) and `discord.py` (Python).

## Discord.js (JavaScript)

### Structure

```
my-bot-js/
├── src/
│   └── index.js
├── package.json
└── vertracloud.config
```

### package.json

```json
{
  "name": "my-bot-discord",
  "main": "src/index.js",
  "scripts": {
    "start": "node src/index.js"
  },
  "dependencies": {
    "discord.js": "^14.14.0"
  }
}
```

### vertracloud.config

```ini
MAIN=src/index.js
START=npm start
VERSION=recommended
```

### Example

```javascript
const { Client, GatewayIntentBits } = require('discord.js');

const client = new Client({
  intents: [
    GatewayIntentBits.Guilds,
    GatewayIntentBits.GuildMessages,
    GatewayIntentBits.MessageContent,
  ],
});

client.once('ready', () => {
  console.log(`Bot online as ${client.user.tag}`);
});

client.on('messageCreate', (message) => {
  if (message.author.bot) return;
  if (message.content === '!ping') {
    message.reply('Pong! ');
  }
});

client.login(process.env.DISCORD_TOKEN);
```

## Discord.py (Python)

### Structure

```
my-bot-py/
├── main.py
├── requirements.txt
└── vertracloud.config
```

### requirements.txt

```txt
discord.py==2.3.2
```

### vertracloud.config

```ini
MAIN=main.py
VERSION=recommended
```

### Example

```python
import discord
import os

intents = discord.Intents.default()
intents.message_content = True

client = discord.Client(intents=intents)

@client.event
async def on_ready():
    print(f'Bot online as {client.user}')

@client.event
async def on_message(message):
    if message.author == client.user:
        return
    if message.content == '!ping':
        await message.channel.send('Pong! ')

client.run(os.environ['DISCORD_TOKEN'])
```

## Deploy

<Tabs>
  <Tab title="Dashboard">
    1. Compress the project into a `.zip` (folders like `node_modules`, `venv` and `target` are removed automatically) or push it to GitHub.
    2. In the dashboard, click **New Project** and upload the `.zip` or paste the repository URL.
    3. In **Build**, check the runtime (**JavaScript or Python**), the main file (`index.js` or `main.py`) and the memory. Start and build commands are under **Advanced settings**.
    4. Add your environment variables in **Environment**.
    5. In **Network**, leave web publishing **off**: a bot doesn't receive incoming traffic and runs in the background on any plan.
    6. Review and deploy. Follow the output in the **Logs** tab.
  </Tab>
  <Tab title="CLI">
    ```bash
    vertra deploy
    vertra logs -f
    ```
    See [CLI](/cli) for installation and login.
  </Tab>
  <Tab title="VS Code">
    Open the folder with the Vertra Cloud extension installed and run **Deploy current project**. See [VS Code extension](/vscode-extension).
  </Tab>
</Tabs>

The full walkthrough is in [First deploy](/how-to-host).

## Notes

- **Bot Type**: Always select **Bot** when creating the application (not Website)
- **Environment variables**: Configure `DISCORD_TOKEN` in the application's variables
- **Auto-restart**: On by default, keeps the bot online in case of disconnection
- **Memory**: 256MB is enough for simple bots, 512MB+ for complex ones
- **Logs**: Use `console.log()` (JS) or `logging` (Python) to monitor in real-time
- **Polling**: Both libraries use polling, which is simpler but consumes more resources than webhooks
