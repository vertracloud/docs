## Estructura común

Independientemente del framework elegido, todo despliegue en Vertra Cloud sigue la misma estructura:

<Steps>
  <Step title="Prepara el proyecto">
    Asegúrate de que las dependencias estén declaradas (`package.json`, `requirements.txt`, `go.mod`, `deno.json`, `.csproj`, `mix.exs`...) y, en el caso de los sitios,
    de que la aplicación escuche en el puerto 80.
  </Step>
  <Step title="Envía el código">
    **Nuevo Proyecto** en el panel (ZIP o GitHub), `vertra upload` en la CLI (la primera vez; `vertra deploy` para las actualizaciones), o la
    extensión de VS Code. La plataforma detecta el runtime, el archivo principal y los comandos; revísalos antes de desplegar.
  </Step>
  <Step title="Verifica">
    Supervisa los logs y el estado de la aplicación en el panel.
  </Step>
</Steps>

## Archivo `vertracloud.config`

Un archivo `vertracloud.config` opcional en la raíz del proyecto rellena previamente el flujo de creación:

```ini
MAIN=index.js
START=npm start
MEMORY=512
```

Todas las claves y sus límites están en [Configuración](/es-es/configuration).

## Puerto de la aplicación

Las aplicaciones web deben escuchar en el puerto definido por la variable de entorno `PORT`. La plataforma inyecta esta variable automáticamente en el contenedor.

<Tabs>
  <Tab title="Node.js">
    ```javascript
    const port = process.env.PORT || 80;
    app.listen(port, '0.0.0.0', () => {
      console.log(`Server running on port ${port}`);
    });
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    port = int(os.environ.get('PORT', 80))
    app.run(host='0.0.0.0', port=port)
    ```
  </Tab>
  <Tab title="Go">
    ```go
    port := os.Getenv("PORT")
    if port == "" {
        port = "80"
    }
    http.ListenAndServe("0.0.0.0:"+port, nil)
    ```
  </Tab>
</Tabs>

<Warning>
  Usa siempre `0.0.0.0` como host en lugar de `localhost` o `127.0.0.1`. Dentro del contenedor, el enlace debe hacerse en todas las interfaces para que el tráfico externo llegue a la aplicación.
</Warning>
