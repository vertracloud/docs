## ¿Cómo es un error?

Todos los errores usan el mismo formato, descrito en la [introducción de la API](/es-es/api-reference/introduction#cómo-es-una-respuesta).
El estado HTTP indica la categoría, `code` es una cadena estable, segura para tomar decisiones en el código según su valor,
y `details` (cuando está presente) contiene los números que necesitas para actuar: un límite, un tiempo de espera o el scope que falta.

```json
{
  "code": "ERROR_CODE",
  "message": "Optional descriptive message",
  "details": { "retry_after": 30 }
}
```

`message` es para personas y puede cambiar; nunca decidas nada en tu código a partir de él. Para los problemas de despliegue
y de ejecución que no vienen de la propia API (bucles de caída, dependencias que faltan, OOMKilled), consulta
[Errores comunes](/es-es/common-errors); esta página solo cubre los valores `code` estables con los que responde la API.

<Note>
  `VALIDATION_ERROR` (`400`) cubre problemas de forma de la petición en todas las rutas: falta un campo obligatorio, el tipo
  es incorrecto o el valor está fuera de rango. `details.path` indica el campo afectado, por ejemplo `"memory"` o `"user.name"`.
</Note>

## Autenticación y claves de API

| Estado | Código | Significado y solución |
|---|---|---|
| 401 | `AUTH_TOKEN_MISSING` | No se envió la cabecera `Authorization`. Añade `Authorization: Bearer <key>`. |
| 401 | `API_KEY_INVALID` | La clave no existe o su secreto no coincide. Revisa el valor de la clave o crea una nueva en el panel. |
| 401 | `SESSION_REVOKED` | La sesión del panel detrás del token caducó o fue revocada (cerraste sesión o se cerró desde la lista de sesiones). Vuelve a iniciar sesión. |
| 401 | `USER_NOT_FOUND` | El usuario autenticado ya no existe (raro; normalmente es una cuenta eliminada). |
| 403 | `API_KEY_IP_DENIED` | La IP de la petición no está en `allowed_ips` de la clave. Añade la IP o el CIDR del cliente a la clave, o vacía la lista para permitir cualquier IP. |
| 403 | `API_KEY_MANAGED` | La plataforma creó la clave para un stack. No puede editarse; se revoca junto con el stack. |
| 403 | `API_KEY_SCOPE_DENIED` | A la clave le falta el scope que requiere la ruta (`details.required`), o la ruta es solo con sesión del panel. Ver [Scopes](/es-es/api-reference/introduction#scopes). |
| 403 | `WEBSITE_ONLY` | La ruta solo acepta una sesión del panel. Las claves de API suelen recibir primero `API_KEY_SCOPE_DENIED` en estas rutas; `WEBSITE_ONLY` es la segunda comprobación que viene después. Ningún scope desbloquea la acción: usa el panel. |
| 403 | `ACCESS_DENIED` | El recurso existe, pero tu cuenta no puede actuar sobre él. Confirma que eres el propietario del recurso o que tienes el permiso correcto del workspace. |
| 403 | `ACCOUNT_BANNED` | La cuenta fue bloqueada. Contacta con soporte. |
| 403 | `APP_BANNED` | La aplicación fue bloqueada. Contacta con soporte. |
| 403 | `DATABASE_BANNED` | La base de datos fue bloqueada. Contacta con soporte. |
| 403 | `APP_SHIELD_COOLDOWN` | Vertra Shield pausó la aplicación tras tráfico abusivo; `details` indica el motivo y el fin de la pausa. Espera a que termine y corrige el origen del tráfico; iniciar, reiniciar, desplegar, cambiar la configuración y eliminar siguen bloqueados hasta entonces. Ver [Errores comunes](/es-es/common-errors#protecciones-de-la-plataforma). |
| 404 | `USER_LIMITS_NOT_FOUND` | No se pudieron resolver los límites del plan de la cuenta. Contacta con soporte. |

### Códigos de fallo del build

Cuando un build o una instalación fallan, `GET /v1/apps/{id}` devuelve el código en `last_build_error` (`null` tras un build correcto); el detalle está en los logs de la aplicación.

| `last_build_error` | Qué hacer |
|---|---|
| `INSTALL_OUT_OF_MEMORY` | Aumenta la memoria de la aplicación y vuelve a intentarlo. |
| `BUILD_FAILED` / `INSTALL_FAILED` | Lee los logs y corrige el proyecto. |
| `BUILD_TIMEOUT` / `INSTALL_TIMEOUT` | Haz el build o la instalación más cortos. |
| `BUILD_INTERRUPTED` | Vuelve a intentarlo. |
| `INSTALL_SHIELD_BLOCKED` | La protección de red bloqueó el tráfico durante el build; reduce el tráfico que genera el build. |

| 401 | `BLOB_UPLOAD_TOKEN_INVALID` | El token de subida no existe, ha caducado o fue revocado. Crea un nuevo token. |

| 403 | `BLOB_UPLOAD_TOKEN_NOT_ALLOWED` | Se envió un token de subida a una ruta distinta de las rutas de subida. Usa una clave de API allí. |
| 403 | `BLOB_UPLOAD_TOKEN_CONSTRAINT` | La ruta, la carpeta u otra opción que fija el token de subida (visibilidad, caché, disposición, caducidad o metadatos) no coincide con la petición. | 404 | `BLOB_SHARE_NOT_FOUND` | El enlace para compartir no existe, fue revocado o caducó. |
| 410 | `BLOB_SHARE_EXHAUSTED` | El enlace para compartir agotó todas sus descargas. |
| 401 | `BLOB_SHARE_PASSWORD_INVALID` | La contraseña es incorrecta. Los intentos repetidos desde la misma IP tienen límite de peticiones. |
| 409 | `BLOB_RULES_CONFLICT` | El etag de `If-Match` está desactualizado porque las reglas se guardaron después de que las leyeras. Vuelve a leer las reglas y reintenta. |
| 409 | `BLOB_RULE_LIMIT` | La cuenta tiene más reglas de carpeta de las que permite su plan (5, 10 o 20). Elimina una regla primero. |
| 409 | `BLOB_CUSTOM_DOMAIN_LIMIT` | El plan incluye dominios personalizados y la cuenta ya tiene todos los que permite. Por debajo de Enterprise-4 la respuesta es `PLAN_RESTRICTED_FEATURE`. |

## General

| Estado | Código | Significado y solución |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Un parámetro, query o campo del body no superó la validación; `details.path` indica el campo. |
| 400 | `INVALID_PARAMS` / `INVALID_PAYLOAD` / `INVALID_RANGE` | La forma de la petición o un campo concreto no es válido para esta ruta. |
| 403 | `FORBIDDEN` | La cuenta no tiene permiso para realizar esta acción sobre este recurso. |
| 400 | `MISSING_HEADERS` | No se envió una cabecera que requiere la ruta. |
| 400 | `INVALID_JSON` | El body no es JSON válido (falta una comilla o una coma, sobra una coma al final o se usan comillas simples). Valida el JSON y envíalo con `content-type: application/json`. |
| 400 | `EMPTY_BODY` | La petición tiene `content-type: application/json` pero no tiene body. Envía un body JSON (`{}` si la ruta no tiene campos obligatorios), o quita la cabecera `content-type` en las peticiones sin body. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | El `content-type` no es uno que acepte la ruta. Envía JSON con `content-type: application/json`; las rutas de subida aceptan `multipart/form-data`. |
| 400 | `BAD_REQUEST` | La petición en sí está mal formada de una forma que ningún otro código cubre, por ejemplo un `Content-Length` que no coincide con el body. Corrige la petición y reintenta. |
| 408 | `REQUEST_TIMEOUT` | El body de la petición no llegó a tiempo. Reintenta, y revisa la conexión si vuelve a ocurrir. |
| 500 | `INTERNAL_SERVER_ERROR` | Algo falló en el lado de la plataforma. Reintenta; si persiste, contacta con soporte indicando la hora de la petición. |

<Note>
  Este catálogo recoge cada código del contrato público de la API. Una ruta todavía puede responder otros errores HTTP estándar (como un `404` genérico para una ruta desconocida) que no llevan ninguno de estos valores de `code`.
</Note>
