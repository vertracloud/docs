---
title: Actualizar imagen
sidebarTitle: Actualizar imagen
api: PATCH https://api.vertracloud.app/v1/images/{image_id}
authMethod: bearer
description: Renombra una imagen Docker personalizada o cambia su descripción, sin construir nada.
---

{/* @see RESTPatchAPICustomImageBody, RESTPatchAPICustomImageResult — @vertracloud/api-types */}
Cambia el `name` y/o la `description` de la imagen. No se construye ni se reinicia nada: la imagen conserva su ID y sus versiones, y las aplicaciones creadas a partir de ella siguen ejecutándose. Envía solo los campos que quieras cambiar; se necesita al menos uno. Las imágenes de la plataforma (`owner: "system"`) no se pueden modificar.

Requiere el scope `images:write` cuando se llama con una clave de API. En un workspace, necesitas permiso para gestionar las aplicaciones del workspace.

<ParamField path="image_id" type="string" required>
  El ID de la imagen.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la imagen pertenece a un workspace, el ID del workspace.
</ParamField>

<ParamField body="name" type="string">
  El nuevo nombre: de 1 a 50 caracteres, único entre las imágenes del propietario. Enviar el nombre actual no es un error. Un nombre que ya usa otra de tus imágenes falla con `VALIDATION_ERROR`, con `path` igual a `name`.
</ParamField>

<ParamField body="description" type="string | null">
  La nueva descripción, de hasta 128 caracteres (texto libre). `null` o una cadena vacía la elimina.
</ParamField>

### Response


<ResponseField name="response" type="object">
  La imagen actualizada.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    El ID de la imagen.
  </ResponseField>

  <ResponseField name="name" type="string">
    El nombre de la imagen.
  </ResponseField>

  <ResponseField name="description" type="string | null">
    La descripción de la imagen (texto libre, de hasta 128 caracteres), o `null` si no tiene ninguna.
  </ResponseField>

  <ResponseField name="owner" type="string">
    `account` para tus imágenes, `system` para las imágenes que proporciona la plataforma (estas no se pueden modificar ni eliminar).
  </ResponseField>

  <ResponseField name="status" type="string">
    Estado del último build: `building`, `success` o `failed`. Una reconstrucción fallida no cambia la versión actual: las aplicaciones siguen ejecutando la última que funcionó.
  </ResponseField>

  <ResponseField name="error" type="string | null">
    Motivo legible del último build fallido, o `null`.
  </ResponseField>

  <ResponseField name="digest" type="string | null">
    Digest (`sha256:...`) de la versión actual, o `null` mientras ningún build haya tenido éxito.
  </ResponseField>

  <ResponseField name="uncompressed_bytes" type="integer | null">
    Tamaño de la versión actual, sin comprimir, en bytes.
  </ResponseField>

  <ResponseField name="layer_count" type="integer | null">
    Número de capas de la versión actual.
  </ResponseField>

  <ResponseField name="apps" type="object[]">
    Las aplicaciones creadas a partir de esta imagen. Cada una tiene `id`, `name`, `version_id` (la versión de la imagen que ejecuta, o `null`) y `outdated` (`true` cuando la imagen tiene una versión más nueva; la aplicación pasa a ella en el siguiente reinicio o despliegue que pidas).
  </ResponseField>

  <ResponseField name="github" type="object | null">
    El repositorio y la rama de GitHub vinculados (`repository` como `owner/name`, `branch`), o `null` si la imagen no está vinculada.
  </ResponseField>

  <ResponseField name="current_version_id" type="string | null">
    La versión actual de la imagen, o `null` mientras ningún build haya tenido éxito.
  </ResponseField>

  <ResponseField name="created_at" type="string" format="date-time">
    Cuándo se creó la imagen.
  </ResponseField>

  <ResponseField name="updated_at" type="string" format="date-time">
    Cuándo se actualizó por última vez la imagen.
  </ResponseField>

  </Expandable>
</ResponseField>

### Error Responses

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `API_KEY_SCOPE_DENIED`: La clave de API no tiene el scope necesario (`403`).
  - `VALIDATION_ERROR`: El cuerpo está vacío, el nombre no tiene de 1 a 50 caracteres, el nombre ya lo usa otra de tus imágenes (`path` es `name`), la descripción supera los 128 caracteres, o el nombre o la descripción contienen caracteres de control (`400`).
  - `ACCESS_DENIED`: La imagen es una imagen de la plataforma, que no se puede modificar (`403`).
  - `IMAGE_NOT_FOUND`: La imagen no existe o no puedes acceder a ella (`404`).
  - `INTERNAL_SERVER_ERROR`: Fallo inesperado (`500`).
</ResponseField>

</ResponseExample>
