{/* @see RESTGetAPIBlobS3CredentialsResponse, APIBlobS3Credentials — @vertracloud/api-types */}

Devuelve credenciales compatibles con S3 para herramientas como aws-cli, rclone y boto3. El par se deriva de la clave de API
que hace la llamada, así que revocar esa clave corta el acceso S3 de inmediato. Con una clave de API que solo tiene
`blob:read`, las credenciales son de solo lectura (`access.write` es `false`). Trata `secret_access_key` como una
contraseña. Esta ruta requiere una clave de API: una sesión del panel se rechaza. Al rotar la clave de API el par se
reemplaza, así que vuelve a obtener las credenciales después.

**Ámbito:** `blob:read`.

<ParamField query="workspace_id" type="string">
  El ID del workspace, cuando el blob pertenece a un workspace. La petición actúa sobre el blob del propietario del
  workspace y necesita el permiso `blob:read` del workspace (`blob:manage` en las rutas que modifican datos). Omítelo
  para actuar sobre tu propio blob.
</ParamField>

### Ejemplo de petición

```bash
curl "https://blob.vertracloud.app/v1/s3/credentials" \
  -H "Authorization: Bearer $VERTRA_API_KEY"
```

### Respuesta

<ResponseField name="response" type="object">
  Las credenciales de S3 de la cuenta.
  <Expandable title="propiedades">
  <ResponseField name="access_key_id" type="string">ID de la clave de acceso. Empieza por `VCS3`.</ResponseField>
  <ResponseField name="secret_access_key" type="string">Clave secreta. Trátala como una contraseña.</ResponseField>
  <ResponseField name="endpoint" type="string">Endpoint de S3 que debes configurar en tu herramienta.</ResponseField>
  <ResponseField name="region" type="string">Siempre `auto`.</ResponseField>
  <ResponseField name="buckets" type="string[]">Los dos buckets: `public` y `private`.</ResponseField>
  <ResponseField name="access.read" type="boolean">Si las credenciales pueden leer.</ResponseField>
  <ResponseField name="access.write" type="boolean">Si las credenciales pueden escribir. `false` con una clave de API que solo tiene `blob:read`.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "access_key_id": "VCS3K7P2M9X4QA",
    "secret_access_key": "<secret>",
    "endpoint": "https://s3.vertracloud.dev",
    "region": "auto",
    "buckets": [
      "public",
      "private"
    ],
    "access": {
      "read": true,
      "write": true
    }
  }
}
```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING` (`401`): No se envió la cabecera `Authorization`.
  - `API_KEY_INVALID` (`401`): La clave de API no existe, fue revocada o su secreto no coincide.
  - `API_KEY_SCOPE_DENIED` (`403`): La clave no tiene el ámbito que necesita esta ruta (`blob:read` o `blob:write`); `details.required` lo indica.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Solo con `workspace_id`: no eres miembro, o tu rol no tiene el permiso de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): Solo con `workspace_id`: no existe un workspace con ese ID, o no eres miembro.
  - `VALIDATION_ERROR` (`400`): La llamada no se hizo con una clave de API; `details.reason` es `api_key_required`.
  - `RATE_LIMIT_EXCEEDED` (`429`): Más de 10 llamadas en una hora. `details.retry_after` indica la espera en segundos.
</ResponseField>
