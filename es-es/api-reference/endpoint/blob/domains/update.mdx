{/* @see RESTPatchAPIBlobDomainBody, RESTPatchAPIBlobDomainResponse, APIBlobCustomDomain — @vertracloud/api-types */}

Cambia `web_content` de un dominio personalizado y devuelve el dominio. Con `true`, el dominio sirve los archivos `.html`,
`.htm`, `.xhtml`, `.svg` y `.xml` en el navegador con su tipo real; las páginas ejecutan JavaScript en un entorno aislado
sin formularios, sin cookies y sin navegar en la pestaña superior. Con `false` (por defecto), esos tipos siempre se
descargan. El cambio surte efecto en aproximadamente un minuto. El enlace público por defecto siempre descarga estos
tipos, sin importar esta configuración. Consulta [Dominios personalizados](/es-es/blob/custom-domains#servir-páginas-web)
para ver los riesgos.

**Ámbito:** `blob:write`.

<ParamField path="domain_id" type="string" required>
  El ID del dominio.
</ParamField>

<ParamField body="web_content" type="boolean">
  Activa (`true`) o desactiva (`false`) el contenido web en este dominio.
</ParamField>

<ParamField query="workspace_id" type="string">
  El ID del workspace, cuando el blob pertenece a un workspace. La petición actúa sobre el blob del propietario del
  workspace y necesita el permiso `blob:read` del workspace (`blob:manage` en las rutas que modifican datos). Omítelo
  para actuar sobre tu propio blob.
</ParamField>

### Ejemplo de petición

```bash
curl -X PATCH "https://blob.vertracloud.app/v1/domains/9a8b7c6d-5e4f-4a3b-b2c1-d0e9f8a7b6c5" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"web_content":true}'
```

### Respuesta

<ResponseField name="response" type="object">
  El dominio actualizado.
  <Expandable title="propiedades">
  <ResponseField name="id" type="string">ID del dominio.</ResponseField>
  <ResponseField name="hostname" type="string">Solo el subdominio, por ejemplo `cdn.example.com`.</ResponseField>
  <ResponseField name="status" type="string">`pending`, `active`, `failed` o `suspended`. Solo `active` sirve archivos.</ResponseField>
  <ResponseField name="ssl_status" type="string">Estado del certificado TLS del nombre de host.</ResponseField>
  <ResponseField name="cname_target" type="string">Apunta un registro CNAME de `hostname` a este valor.</ResponseField>
  <ResponseField name="prefix" type="string | null">Si está definido, el dominio sirve solo esta carpeta.</ResponseField>
  <ResponseField name="web_content" type="boolean">`true` cuando el dominio sirve `.html`, `.htm`, `.xhtml`, `.svg` y `.xml` en el navegador (en entorno aislado); `false` cuando esos tipos siempre se descargan.</ResponseField>
  <ResponseField name="verification" type="object | null">
    El registro TXT que demuestra que eres dueño del nombre de host. Solo está presente mientras el dominio no esté

    <ResponseField name="value" type="string">Valor del registro TXT.</ResponseField>
    </Expandable>
  </ResponseField>
  <ResponseField name="created_at" type="string">Fecha de creación en ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING` (`401`): No se envió la cabecera `Authorization`.
  - `API_KEY_INVALID` (`401`): La clave de API no existe, fue revocada o su secreto no coincide.
  - `API_KEY_SCOPE_DENIED` (`403`): La clave no tiene el ámbito que necesita esta ruta (`blob:read` o `blob:write`); `details.required` lo indica.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Solo con `workspace_id`: no eres miembro, o tu rol no tiene el permiso de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): Solo con `workspace_id`: no existe un workspace con ese ID, o no eres miembro.
  - `VALIDATION_ERROR` (`400`): `web_content` falta o no es un booleano. `details.path` indica el campo.
  - `BLOB_CUSTOM_DOMAIN_NOT_FOUND` (`404`): No existe ningún dominio con ese ID en esta cuenta.
</ResponseField>
