{/* @see RESTPatchAPIBlobObjectsBody, RESTPatchAPIBlobObjectsResponse, APIBlobBatchResult — @vertracloud/api-types */}

Aplica los mismos `changes` a hasta 100 objetos en una sola llamada. La respuesta tiene un resultado por ID: `ok: true` con
el objeto actualizado, o `ok: false` con el `code` de error de ese objeto. Un fallo en un objeto no detiene a los demás.

**Ámbito:** `blob:write`.

<ParamField body="ids" type="string[]" required>
  IDs de objeto, de 1 a 100.
</ParamField>

<ParamField body="changes" type="object" required>
  Los campos que se van a cambiar, con el mismo significado que en
  [Actualizar un objeto blob](/es-es/api-reference/endpoint/blob/objects/update): `visibility`, `cache_control`,
  `content_disposition`, `filename`, `expires_at`, `metadata`.
</ParamField>

<ParamField query="workspace_id" type="string">
  El ID del workspace, cuando el blob pertenece a un workspace. La petición actúa sobre el blob del propietario del
  workspace y necesita el permiso `blob:read` del workspace (`blob:manage` en las rutas que modifican datos). Omítelo
  para actuar sobre tu propio blob.
</ParamField>

### Ejemplo de petición

```bash
curl -X PATCH "https://blob.vertracloud.app/v1/objects" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"ids":["0b6f7c1e-3d2a-4f5b-9a8c-1d2e3f4a5b6c","7c1d2e3f-4a5b-4c6d-8e7f-0a1b2c3d4e5f"],"changes":{"visibility":"private"}}'
```

### Respuesta

<ResponseField name="response" type="object[]">
  Un resultado por ID solicitado, en el mismo orden.
  <Expandable title="propiedades">
  <ResponseField name="id" type="string">El ID de objeto de este resultado.</ResponseField>
  <ResponseField name="ok" type="boolean">`true` cuando el cambio se aplicó.</ResponseField>
  <ResponseField name="code" type="string">Solo cuando `ok` es `false`: el código de error de este objeto, como `BLOB_OBJECT_NOT_FOUND`.</ResponseField>
  <ResponseField name="object" type="object">Solo cuando `ok` es `true`: el objeto blob actualizado, con los campos de [Obtener un objeto blob](/es-es/api-reference/endpoint/blob/objects/get).</ResponseField>
  </Expandable>
</ResponseField>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING` (`401`): No se envió la cabecera `Authorization`.
  - `API_KEY_INVALID` (`401`): La clave de API no existe, fue revocada o su secreto no coincide.
  - `API_KEY_SCOPE_DENIED` (`403`): La clave no tiene el ámbito que necesita esta ruta (`blob:read` o `blob:write`); `details.required` lo indica.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Solo con `workspace_id`: no eres miembro, o tu rol no tiene el permiso de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): Solo con `workspace_id`: no existe un workspace con ese ID, o no eres miembro.
  - `BLOB_NAMESPACE_SUSPENDED` (`403`): El almacenamiento de blob de la cuenta está suspendido, o su plan expiró. Las subidas y otras escrituras se rechazan desde el inicio del periodo de gracia de 72 horas.
  - `VALIDATION_ERROR` (`400`): Un parámetro o un campo del cuerpo no superó la validación. `details.path` indica el campo.
</ResponseField>
