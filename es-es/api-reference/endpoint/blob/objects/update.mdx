{/* @see RESTPatchAPIBlobObjectBody, RESTPatchAPIBlobObjectResponse, APIBlobObject — @vertracloud/api-types */}

Cambia los ajustes de un objeto sin tocar sus bytes. Envía solo los campos que quieres cambiar. Si cambias `visibility` a
`public`, el objeto queda accesible en su `url` pública; si lo cambias a `private`, esa URL deja de funcionar. Enviar
`null` restaura el valor por defecto de un campo.

**Ámbito:** `blob:write`.

<ParamField path="object_id" type="string" required>
  El ID del objeto.
</ParamField>

<ParamField body="visibility" type="string">
  `public` o `private`.
</ParamField>

<ParamField body="cache_control" type="string | null">
  `immutable`, `max-age=<seconds>` o `no-cache` (Enterprise-26 o superior). `null` restaura el valor por defecto.
</ParamField>

<ParamField body="content_disposition" type="string | null">
  `inline` o `attachment`. `null` restaura el valor por defecto.
</ParamField>

<ParamField body="filename" type="string | null">
  Nombre sugerido al descargar. `null` usa el último segmento de `path`.
</ParamField>

<ParamField body="expires_at" type="string | null">
  Marca de tiempo ISO 8601 para la eliminación, como mínimo el plazo mínimo del plan desde ahora. `null` elimina la caducidad.
</ParamField>

<ParamField body="metadata" type="object">
  Claves que se van a definir. Una clave con el valor `null` se elimina. Hasta 5 claves en total, 512 bytes; Enterprise-12 o superior.
</ParamField>

<ParamField query="workspace_id" type="string">
  El ID del workspace, cuando el blob pertenece a un workspace. La petición actúa sobre el blob del propietario del
  workspace y necesita el permiso `blob:read` del workspace (`blob:manage` en las rutas que modifican datos). Omítelo
  para actuar sobre tu propio blob.
</ParamField>

### Ejemplo de petición

```bash
curl -X PATCH "https://blob.vertracloud.app/v1/objects/0b6f7c1e-3d2a-4f5b-9a8c-1d2e3f4a5b6c" \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"visibility":"private","metadata":{"owner":"joao","old-key":null}}'
```

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING` (`401`): No se envió la cabecera `Authorization`.
  - `API_KEY_INVALID` (`401`): La clave de API no existe, fue revocada o su secreto no coincide.
  - `API_KEY_SCOPE_DENIED` (`403`): La clave no tiene el ámbito que necesita esta ruta (`blob:read` o `blob:write`); `details.required` lo indica.
  - `WORKSPACE_PERMISSION_DENIED` (`403`): Solo con `workspace_id`: no eres miembro, o tu rol no tiene el permiso de blob.
  - `WORKSPACE_NOT_FOUND` (`404`): Solo con `workspace_id`: no existe un workspace con ese ID, o no eres miembro.
  - `BLOB_NAMESPACE_SUSPENDED` (`403`): El almacenamiento de blob de la cuenta está suspendido, o su plan expiró. Las subidas y otras escrituras se rechazan desde el inicio del periodo de gracia de 72 horas.
  - `VALIDATION_ERROR` (`400`): Un parámetro o un campo del cuerpo no superó la validación. `details.path` indica el campo.
  - `BLOB_OBJECT_NOT_FOUND` (`404`): No existe ningún objeto con ese ID en esta cuenta (o en el blob del workspace).
  - `PLAN_RESTRICTED_FEATURE` (`403`): El plan no incluye el ajuste que enviaste, como `metadata` por debajo de Enterprise-12 o `no-cache` por debajo de Enterprise-26.
</ResponseField>
