---
title: Purgar caché
sidebarTitle: Purgar caché
api: POST https://api.vertracloud.app/v1/apps/{id}/network/purge-cache
authMethod: bearer
description: Purga la caché del subdominio o de los dominios personalizados de una aplicación, opcionalmente para rutas concretas.
---

{/* @see success/error — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la aplicación cuya caché quieres purgar.
</ParamField>

<ParamField body="hostnames" type="array">
  Los nombres de host que se van a purgar. **Opcional**: omítelo (un cuerpo vacío también vale) y se purga cada nombre de host que posee la
  aplicación, que es lo que se espera al pedir "purga la caché de esta aplicación". Si lo envías, cada entrada debe ser uno de los nombres de host propios de la aplicación: su `subdomain`,
  que ya es un host completo (`myapp.vertraweb.app`; no vuelvas a añadir la zona), o el nombre de host de uno de sus dominios personalizados.
  Cualquier otra cosa se rechaza con `INVALID_HOSTNAME_FOR_APP`.
</ParamField>

<ParamField body="paths" type="array">
  Un array opcional de URL completas que purgar (por ejemplo, `["https://example.com/path1", "https://example.com/path2"]`).
  Las URL cuyo host no esté entre los nombres de host que se purgan se descartan; si no queda ninguna, la
  petición falla con `NO_AUTHORIZED_PATHS`. Si se omite, se purga todo lo que haya bajo cada nombre de host.
</ParamField>

### Respuesta

Una respuesta correcta devuelve `200` con `{ "response": null }`.

<ResponseExample>

```json Response
{
  "response": null
}
```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `VALIDATION_ERROR`: El parámetro de ruta o el cuerpo no superaron la validación (`400`). La respuesta
    también incluye `message` y `path`.
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `USER_NOT_FOUND`: No se pudo resolver el usuario autenticado (`401`).
  - `ACCESS_DENIED`: El usuario no tiene permiso para actuar sobre la aplicación (`403`).
  - `INVALID_HOSTNAME_FOR_APP`: Uno de los `hostnames` no pertenece a la aplicación (`403`).
  - `APP_NOT_FOUND`: La aplicación indicada no existe (`404`).
  - `APP_NOT_PUBLISHED`: La aplicación no tiene subdominio ni dominio personalizado, así que no tiene caché de borde que purgar (`400`).
  - `NO_AUTHORIZED_PATHS`: Ninguno de los `paths` indicados pertenece a los nombres de host dados (`400`).
  - `INTERNAL_SERVER_ERROR`: El CDN rechazó la purga, o se produjo un fallo inesperado (`500`).
</ResponseField>

<ResponseField name="message" type="string">
  Un mensaje descriptivo con más detalles sobre el error.
</ResponseField>
