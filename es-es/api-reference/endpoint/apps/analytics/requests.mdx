{/* @see RESTGetAPIApplicationAnalyticsRequestsQuery, APIApplicationAnalyticsRequestList — @vertracloud/api-types */}
Devuelve una página del registro de peticiones del sitio de una aplicación, con una entrada por petición: estado, tiempos, origen, dispositivo y el ID de la petición. Úsala para inspeccionar una visita o para encontrar las peticiones exactas detrás de un número en [Errores](/es-es/web-analytics/errors) o [Rendimiento](/es-es/web-analytics/performance). Acepta los mismos filtros que las otras rutas de analytics y pagina con cursor. Son los datos de [Peticiones](/es-es/web-analytics/requests) y **requiere un plan con el registro de peticiones (Pro y superiores)**.

<ParamField path="id" type="string" required>
  El ID de la aplicación. Si pertenece a un workspace, pasa su ID en el query parameter `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la aplicación pertenece a un workspace, el ID del workspace. Obligatorio para miembros del workspace que actúan sobre una aplicación que no es suya.
</ParamField>

<ParamField query="start" type="string" format="date-time">
  Inicio de la ventana (ISO 8601). Por defecto: 24 horas antes de `end`.
</ParamField>

<ParamField query="end" type="string" format="date-time">
  Fin de la ventana (ISO 8601). Por defecto: ahora. No puede estar en el futuro.
</ParamField>

<ParamField query="cursor" type="string">
  `cursor` opaco de la página anterior. Envíalo con la misma ventana, los mismos filtros y el mismo orden; cualquier otro cursor se rechaza con `VALIDATION_ERROR`.
</ParamField>

<ParamField query="order" type="string" default="desc">
  Orden por hora: `desc` (más nuevas primero) o `asc`. Por defecto `desc`.
</ParamField>

<ParamField query="limit" type="integer" default="50">
  Peticiones por página, de 1 a 100. Por defecto 50.
</ParamField>

La ventana dura como máximo 30 días y no puede empezar antes del historial del plan (7 o 30 días, ver [Planes y límites](/es-es/plans-and-limits)).

### Filtros

Cada dimensión de abajo también es un filtro, y todos se pueden combinar: cada uno restringe todas las partes de la respuesta. Cada filtro recibe **un valor**, exactamente como aparece en una entrada de breakdown o en una petición del registro, así que un valor leído en una respuesta se puede reenviar sin cambios. Envía `(none)` para quedarte solo con las peticiones que no tienen nada en la dimensión.

<ParamField query="country" type="string">
  País del visitante, ISO 3166-1 alfa-2 (`BR`).
</ParamField>

<ParamField query="edge_location" type="string">
  Código IATA de la ubicación de borde que respondió (`GRU`).
</ParamField>

<ParamField query="host" type="string">
  Hostname que pidió el visitante: el subdominio de la aplicación o uno de sus dominios. Solo se aceptan hosts de la aplicación.
</ParamField>

<ParamField query="path" type="string">
  Ruta de la petición, sin la query string. Es un prefijo: `/api` coincide con `/api`, `/api/users` y `/apix`.
</ParamField>

<ParamField query="method" type="string">
  Método HTTP (`GET`, `POST`...).
</ParamField>

<ParamField query="status" type="string">
  Estado HTTP que recibió el visitante (`404`), o una clase: `2xx`, `3xx`, `4xx` o `5xx`.
</ParamField>

<ParamField query="protocol" type="string">
  Versión de HTTP: `HTTP/1.1`, `HTTP/2` o `HTTP/3`.
</ParamField>

<ParamField query="device" type="string">
  Tipo de dispositivo: `desktop`, `mobile` o `tablet`.
</ParamField>

<ParamField query="os" type="string">
  Sistema operativo del visitante (`Windows`, `iOS`...).
</ParamField>

<ParamField query="browser" type="string">
  Navegador del visitante (`Chrome`, `Safari`...).
</ParamField>

<ParamField query="referer" type="string">
  Host de la página que llevó a la petición (`google.com`). `(none)` es una visita directa, sin referer.
</ParamField>

<ParamField query="asn" type="string">
  Número del sistema autónomo de la red del visitante (`28573`).
</ParamField>

<ParamField query="ip" type="string">
  Dirección IP del visitante.
</ParamField>

<ParamField query="content_type" type="string">
  Tipo de contenido respondido (`html`, `json`, `css`, `js`, `png`...).
</ParamField>

<ParamField query="cache_status" type="string">
  Si la borde respondió desde su caché: `hit`, `miss`, `dynamic`, `bypass`, `expired`, `revalidated`...
</ParamField>

<ParamField query="bot" type="string">
  Categoría de un bot verificado (`Search Engine Crawler`...). `(none)` es un visitante que no es un bot verificado.
</ParamField>

### Paginación

Lee la primera página sin `cursor`. Mientras la respuesta tenga `cursor`, llama de nuevo con los mismos `start`, `end`, filtros y `order` más ese `cursor`. Fija `start` y `end` durante todo el recorrido: con el `end` por defecto (ahora) la ventana se mueve entre llamadas. La lectura termina cuando `cursor` es `null`.

### Notas

- Requiere el scope `apps:read` cuando se llama con una API key. Los miembros de un workspace necesitan permiso para leer la aplicación.
- **Pro y superiores.** En Starter la llamada falla con `PLAN_DOES_NOT_SUPPORT_WEB_ANALYTICS_REQUESTS`. El flag del plan es `features.web_analytics_requests` en [Listar planes](/es-es/api-reference/endpoint/plans/list).
- **Muestreo.** Con tráfico alto el registro es una **muestra** de las peticiones, no todas: `sampled` viene `true` y una petición concreta puede no estar.
- **Retraso.** Los datos se actualizan cada unos 5 minutos, así que las peticiones más nuevas pueden tardar unos minutos en aparecer. Si los datos más recientes no se pueden leer ahora, puede volver una respuesta anterior con `stale: true` (revisa `generated_at`); de lo contrario, la llamada falla con `ANALYTICS_BUSY`.
- **Privacidad.** Vertra Cloud no guarda nada de los visitantes; guarda solo totales por app (recuentos, visitas, bytes, tasas de error y tiempos de respuesta) hasta 31 días, borrados con la app. No se guarda ninguna IP, ruta, query string ni user agent. `ip` y `query` vuelven sin máscara; enmascararlos es decisión del cliente que los muestra. Ver [Privacidad](/es-es/web-analytics/privacy).

### Respuestas de error

| Status | Código | Cuándo |
|---|---|---|
| 401 | `AUTH_TOKEN_MISSING` / `API_KEY_INVALID` / `SESSION_REVOKED` | Falta el header `Authorization`, la API key es inválida o la sesión del panel fue revocada. |
| 403 | `API_KEY_IP_DENIED` / `API_KEY_SCOPE_DENIED` | La API key se usa desde una IP fuera de su lista permitida, o no tiene el scope `apps:read`. |
| 403 | `ACCESS_DENIED` | La aplicación pertenece a otra cuenta, o no tienes el permiso de workspace para leerla. |
| 403 | `PLAN_REQUIRED` | La cuenta no tiene plan activo. |
| 403 | `PLAN_DOES_NOT_SUPPORT_WEB_ANALYTICS_REQUESTS` | El plan no incluye el registro de peticiones (Starter). Pasa a Pro o superior. |
| 404 | `APP_NOT_FOUND` | La aplicación no existe. |
| 400 | `VALIDATION_ERROR` | Un parámetro falló la validación, como `limit` fuera de rango, un `cursor` inválido o una fecha `start`/`end` mal formada; `details.path` nombra el campo. |
| 400 | `INVALID_RANGE` | `start` es posterior a `end`, `end` está en el futuro o la ventana supera los 30 días. |
| 400 | `ANALYTICS_RANGE_EXCEEDS_PLAN` | `start` es anterior a lo que el plan puede leer. `details.history_days` trae el límite en días y `details.earliest` el `start` más antiguo aceptado ahora. |
| 429 | `RATE_LIMIT_EXCEEDED` | Demasiadas consultas seguidas. `details.retry_after` indica la espera en segundos; la cabecera `Retry-After` viene siempre con ella. |
| 503 | `ANALYTICS_BUSY` | Momento de alta demanda y sin respuesta reciente disponible para la consulta. Espera `details.retry_after` segundos e inténtalo de nuevo. |
