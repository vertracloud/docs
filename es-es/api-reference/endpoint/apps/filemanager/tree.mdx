---
title: Obtener árbol de archivos de la aplicación
sidebarTitle: Obtener árbol de archivos
api: GET https://api.vertracloud.app/v1/apps/{id}/files/tree
authMethod: bearer
description: Devuelve el árbol completo de archivos de una aplicación a partir de su ID, con las carpetas expandidas de forma recursiva.
---
<Note>
  El árbol llega hasta 6 niveles de profundidad y omite las carpetas de dependencias y de build (`node_modules`, `.git`,
  `vendor`, `__pycache__`, `target`, `.venv`, `venv`, `.next`, `.local`). Para explorar esas carpetas, usa
  [Listar archivos de la aplicación](/es-es/api-reference/endpoint/apps/filemanager/files) directamente sobre la carpeta.
</Note>

<ParamField path="id" type="string" required>
  El ID de la aplicación de la que se obtendrá el árbol de archivos. Si la aplicación pertenece a un workspace, pasa su ID en el parámetro de query `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la aplicación pertenece a un workspace, el ID de ese workspace. Los miembros con el rol Propietario, Administrador o Desarrollador pueden usar el gestor de archivos en una aplicación del workspace que no les pertenece; sin este parámetro, solo puede hacerlo el propietario de la aplicación.
</ParamField>

### Respuesta

<ResponseField name="response" type="object">
  La entrada raíz, con los elementos hijos anidados de forma recursiva.

  <Expandable title="Mostrar objeto">

  <ResponseField name="name" type="string">
    El nombre del archivo o de la carpeta.
  </ResponseField>

  <ResponseField name="path" type="string">
    La ruta completa del archivo o de la carpeta.
  </ResponseField>

  <ResponseField name="type" type="string">
    `"file"` o `"directory"`.
  </ResponseField>

  <ResponseField name="size" type="string">
    El tamaño del archivo, legible para personas (por ejemplo, `"12.34 KB"`). Solo aparece en las entradas de tipo `"file"`.
  </ResponseField>

  <ResponseField name="last_modified" type="string" format="date-time">
    La fecha y hora de la última modificación del archivo o de la carpeta.
  </ResponseField>

  <ResponseField name="children" type="array">
    Presente en las carpetas. Un array de entradas con esta misma forma.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "type": "directory",
    "name": "/",
    "path": "/",
    "last_modified": "2026-03-14T19:58:00Z",
    "children": [

        "name": "index.js",
        "path": "/index.js",

      {
        "type": "directory",

        "last_modified": "2026-03-14T19:58:00Z",

  }

```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `ACCESS_DENIED`: El recurso pertenece a otra cuenta, o no tienes el permiso de workspace necesario para él (`403`).
  - `FORBIDDEN`: El usuario no tiene permiso para acceder a la aplicación.
  - `APP_NOT_FOUND`: La aplicación indicada no existe.
  - `PLAN_RESTRICTED_FEATURE`: El plan del usuario no admite el acceso al gestor de archivos.
  - `INTERNAL_SERVER_ERROR`: No se pudo obtener el árbol de archivos.
</ResponseField>

<ResponseExample>

```json Error Response (403)
{
  "code": "ACCESS_DENIED"
}
```

```json Error Response (404)
{
  "code": "APP_NOT_FOUND"
}
```

</ResponseExample>
