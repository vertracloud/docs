---
title: Obtener contenido de un archivo de la aplicación
sidebarTitle: Obtener contenido de archivo
api: GET https://api.vertracloud.app/v1/apps/{id}/files/content
authMethod: bearer
description: Devuelve el contenido de un archivo concreto de una aplicación a partir de su ID.
---

{/* @see APIApplicationFileContent — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la aplicación de la que se obtendrá el contenido del archivo. Si la aplicación pertenece a un workspace, pasa su ID en el parámetro de query `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la aplicación pertenece a un workspace, el ID de ese workspace. Los miembros con el rol Propietario, Administrador o Desarrollador pueden usar el gestor de archivos en una aplicación del workspace que no les pertenece; sin este parámetro, solo puede hacerlo el propietario de la aplicación.
</ParamField>

<ParamField query="path" type="string" required>
  La ruta del archivo cuyo contenido se quiere obtener.
</ParamField>

### Respuesta

<ResponseField name="response" type="object">
  El contenido del archivo solicitado.

  <Expandable title="Mostrar objeto">

  <ResponseField name="type" type="string">
    Siempre `"base64"`.
  </ResponseField>

  <ResponseField name="data" type="string">
    El contenido del archivo, codificado en base64 estándar (con relleno).
  </ResponseField>

  <ResponseField name="size" type="number">
    El tamaño del archivo en bytes. Es el tamaño real del archivo, no la longitud de la cadena base64.
  </ResponseField>

  <ResponseField name="last_modified" type="string" format="date-time">
    La fecha de modificación (mtime) del archivo. Envía este valor de vuelta en el cuerpo de [`PUT /files`](/es-es/api-reference/endpoint/apps/filemanager/save) como `last_modified` para detectar conflictos de edición.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "type": "base64",
    "data": "SGVsbG8gV29ybGQ=",
    "size": 11,
    "last_modified": "2026-03-14T19:58:00Z"
  }
}
```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `FORBIDDEN` / `ACCESS_DENIED`: El usuario no tiene permiso para acceder a la aplicación.
  - `APP_NOT_FOUND`: La aplicación indicada no existe.
  - `PLAN_RESTRICTED_FEATURE`: El plan del usuario no admite el acceso al gestor de archivos.
  - `MISSING_PATH`: No se proporcionó el parámetro de query `path`.
  - `FILE_NOT_FOUND`: El archivo solicitado no existe.
  - `FILE_TOO_LARGE`: El archivo supera el límite de 10 MB para obtener su contenido.
  - `FILE_CONTENT_ERROR`: No se pudo obtener el contenido del archivo.
</ResponseField>

<ResponseField name="message" type="string">
  Una descripción detallada con información adicional sobre el error.
</ResponseField>

<ResponseExample>

```json Error Response (403)
{
  "code": "API_KEY_SCOPE_DENIED"
}
```

```json Error Response (404)
{
  "code": "FILE_NOT_FOUND"
}
```

```json Error Response (400)
{
  "code": "FILE_TOO_LARGE",
  "message": "File exceeds the 10 MB limit for content retrieval"
}
```

```json Error Response (400)
{
  "code": "MISSING_PATH",
  "message": "Path query parameter is required"
}
```

</ResponseExample>
