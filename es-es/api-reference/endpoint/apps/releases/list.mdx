title: Listar releases de la aplicación
sidebarTitle: Listar releases
api: GET https://api.vertracloud.app/v1/apps/{id}/releases
authMethod: bearer
description: Lista las versiones del código de una aplicación, de la más nueva a la más antigua, con su origen, estado, mensaje, autor y si se puede restaurar.
---

{/* @see APIApplicationRelease, RESTGetAPIApplicationReleasesQuery — @vertracloud/api-types */}
Devuelve el historial de releases de una aplicación: una entrada por cada versión de su código, de la más nueva a la más antigua. Cada entrada indica cómo se creó la versión, si es la que se está ejecutando ahora y si se puede restaurar.

<Note>
  El historial empieza con el primer envío de código hecho después de que se lanzara esta función. Las releases creadas a partir de un snapshot no aparecen en él.
</Note>

<ParamField path="id" type="string" required>
  El ID de la aplicación. Si la aplicación pertenece a un workspace, pasa su ID en el parámetro de consulta `workspace_id`.
</ParamField>

<ParamField query="page" type="integer" default="1">
  Número de página, empezando en `1`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  Releases por página. Máximo `50`; los valores mayores devuelven `400 VALIDATION_ERROR`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la aplicación pertenece a un workspace, el ID del workspace.
</ParamField>

Requiere el scope `apps:read` cuando se llama con una clave de API.

### Respuesta

<ResponseField name="response" type="object">
  Lista paginada, de la más nueva a la más antigua.

  <Expandable title="Mostrar objeto">

  <ResponseField name="data" type="APIApplicationRelease[]">
    <Expandable title="Mostrar objeto">

    <ResponseField name="id" type="string">
    El ID de la release. Pásalo al endpoint de [log de la release](/es-es/api-reference/endpoint/apps/releases/log).
    </ResponseField>

    <ResponseField name="app_id" type="string">
    El ID de la aplicación.
    </ResponseField>

    <ResponseField name="source" type="string">
    Cómo se creó la release: `github` (push al repositorio conectado), `cli` (la CLI de Vertra), `upload` (subida desde el panel, un SDK o una extensión), `editor` (edición hecha en el gestor de archivos), `rollback` (restaura una release anterior) o `env_change` (variables de entorno cambiadas, sin cambio de código).
    </ResponseField>

    <ResponseField name="status" type="string">
    En qué punto de su ciclo de vida está la release: `deploying` (en build y arranque), `active` (la versión que la aplicación ejecuta ahora; solo hay una), `superseded` (reemplazada por una release más nueva), `failed` (el despliegue no arrancó), `rolled_back` (reemplazada por un rollback) o `expired` (su código ya no se conserva).
    </ResponseField>

    <ResponseField name="message" type="string | null">
    El mensaje del commit o de la subida. `null` cuando no se indicó ninguno, y siempre `null` en las ediciones del gestor de archivos.
    </ResponseField>

    <ResponseField name="author" type="string">
    El usuario de GitHub que hizo el push, o el nombre del usuario que subió o editó los archivos.
    </ResponseField>

    <ResponseField name="github" type="object | null">
    El push de GitHub que produjo esta release, con `app_id`, `commit_id`, `message`, `pusher`, `branch` y `created_at`. `null` para cualquier otro origen.
    </ResponseField>

    <ResponseField name="files_changed" type="integer">
    Número de archivos modificados por la operación que produjo esta release.
    </ResponseField>

    <ResponseField name="rollback" type="object">
    Información de restauración de esta release.

    <Expandable title="Mostrar objeto">

    <ResponseField name="available" type="boolean">
    `true` cuando puedes hacer rollback de la aplicación a esta release. Es `false` para la release activa, para una release expirada y cuando tu plan no permite hacer rollback a ella.
    </ResponseField>

    <ResponseField name="expires_at" type="string | null">
    Cuándo deja de conservarse el código de esta release, contado desde el momento en que dejó de ser la release activa. `null` para la release activa y cuando no se conservó código.
    </ResponseField>

    <ResponseField name="from" type="string | null">
    La release que esta restaura, cuando `source` es `rollback`. `null` en los demás casos.
    </ResponseField>

    </Expandable>
    </ResponseField>

    <ResponseField name="has_log" type="boolean">
    `true` cuando se registró un log de fallo para esta release. El log todavía puede expirar; consulta el endpoint de log de la release.
    </ResponseField>

    <ResponseField name="build_duration_ms" type="integer | null">
    Tiempo, en milisegundos, invertido en instalar dependencias, hacer el build y arrancar esta release. `null` cuando no se desplegó con un build, por ejemplo, archivos confirmados sin reinicio.
    </ResponseField>

    <ResponseField name="first_started_at" type="string | null">
    Cuándo arrancó por primera vez la aplicación con el código de esta release. `null` mientras el código está en la carpeta de la aplicación pero la aplicación todavía no se ha reiniciado con él: los cambios solo surten efecto tras un reinicio.
    </ResponseField>

    <ResponseField name="created_at" type="string" format="date-time">
    Marca de tiempo ISO de cuándo se creó la release.
    </ResponseField>

    </Expandable>
  </ResponseField>

  <ResponseField name="total_count" type="integer">Total de releases en el historial.</ResponseField>
  <ResponseField name="page" type="integer">Página actual.</ResponseField>
  <ResponseField name="limit" type="integer">Releases por página.</ResponseField>
  <ResponseField name="total_pages" type="integer">Total de páginas.</ResponseField>
  <ResponseField name="has_next_page" type="boolean" />
  <ResponseField name="has_previous_page" type="boolean" />

  </Expandable>
</ResponseField>

### Respuestas de error

<ResponseField name="code" type="string">
Códigos de error posibles:
- `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
- `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
- `APP_NOT_FOUND`: La aplicación no existe, o no pertenece a esta cuenta ni a este workspace (`404`).
- `VALIDATION_ERROR`: El `page` o el `limit` no son válidos, por ejemplo un `limit` superior a `50` (`400`).
</ResponseField>

<ResponseField name="message" type="string">
  Un mensaje descriptivo con más detalles sobre el error.
</ResponseField>

<ResponseExample>
```json
{
  "code": "APP_NOT_FOUND"
}
```
</ResponseExample>

<Note>
  Las entradas de esta lista se conservan de forma permanente. Sin embargo, el código de las releases antiguas solo se conserva durante un periodo que depende de tu plan, y ese periodo empieza cuando una release deja de ser la activa, no cuando se creó. Una vez que el código expira, la entrada muestra `status: "expired"` y `rollback.available: false`.
</Note>
