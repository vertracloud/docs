authMethod: bearer
description: Descarga el archivo ZIP de un snapshot concreto de una aplicación o base de datos. La respuesta es el ZIP, sea cual sea su tamaño.
---

{/* @see binary — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la aplicación o de la base de datos.
</ParamField>

<ParamField path="snapshot_id" type="string" required>
  El ID del snapshot que quieres descargar.
</ParamField>

<ParamField query="scope" type="string" required>
  El tipo de recurso. Valores posibles: `applications`, `databases`.
</ParamField>

### Respuesta

La respuesta es el archivo ZIP: `200` con el ZIP en el cuerpo, para snapshots de cualquier tamaño.

```bash
curl -o snapshot.zip \
  -H "Authorization: Bearer $VERTRA_API_KEY" \
  "https://api.vertracloud.app/v1/users/{id}/snapshots/{snapshot_id}/download?scope=applications"
```

Requiere el scope `snapshots:read`.

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `USER_NOT_FOUND`: No se encontró el usuario autenticado.
  - `ACCESS_DENIED`: El snapshot no pertenece al usuario autenticado.
  - `TEMPLATE_CLOSED`: El snapshot es de una aplicación de una [plantilla cerrada](/es-es/templates/use/closed-templates) y no se puede descargar (`403`).
  - `SNAPSHOT_TYPE_MISMATCH`: El tipo de recurso del snapshot no coincide con el `scope` solicitado (`400`).
  - `SNAPSHOT_NOT_FOUND`: El snapshot indicado no existe.
  - `INTERNAL_SERVER_ERROR`: Se produjo un error inesperado en el servidor.
</ResponseField>
