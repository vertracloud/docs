---
title: Listar jobs de snapshot
sidebarTitle: Listar jobs de snapshot
api: GET https://api.vertracloud.app/v1/users/{id}/snapshots/jobs
authMethod: bearer
description: Lista los jobs de snapshot y de restauración de una aplicación o base de datos, del más reciente al más antiguo. Requiere el scope snapshots:read.
---

{/* @see APISnapshotJob[] — @vertracloud/api-types */}
Un snapshot o una restauración puede tardar más que una petición. Cada uno es un **job** que puedes seguir: un snapshot manual que
no termina en 90 segundos responde `202` con un `job_id`, y una [restauración](/es-es/api-reference/endpoint/apps/snapshots/restore)
responde siempre `202` con uno. Esta ruta lista los jobs de un recurso; [Obtener job de snapshot](/es-es/api-reference/endpoint/apps/snapshots/jobs/get) lee uno solo.

<ParamField path="id" type="string" required>
  El ID de la aplicación o de la base de datos.
</ParamField>

<ParamField query="scope" type="string" required>
  El tipo de recurso. Valores posibles: `applications`, `databases`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si el recurso pertenece a un workspace, el ID del workspace.
</ParamField>

<ParamField query="kind" type="string">
  Solo jobs de este tipo: `snapshot` o `restore`. Por defecto: ambos.
</ParamField>

<ParamField query="limit" type="number">
  Número máximo de jobs, de `1` a `50`. Por defecto `10`. Un valor fuera de ese rango responde `400 VALIDATION_ERROR`.
</ParamField>

### Respuesta

<ResponseField name="response" type="array">
  Los jobs, del más reciente al más antiguo.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    El ID del job.
  </ResponseField>

  <ResponseField name="kind" type="string">
    `snapshot` o `restore`.
  </ResponseField>

  <ResponseField name="resource_id" type="string">
    El recurso sobre el que actúa el job: el que recibe la copia o el destino de una restauración.
  </ResponseField>

  <ResponseField name="origin" type="string">
    Solo en los jobs de snapshot: qué pidió el snapshot, el mismo `origin` que recibe: `manual` (tú) o `automatic` (el backup diario del plan, o el snapshot que la plataforma hace antes de quitar un recurso, por ejemplo cuando vence el plan). Ausente en los jobs de restauración.
  </ResponseField>

  <ResponseField name="status" type="string">
    `queued` (esperando para empezar), `running`, `ready` (terminado), `skipped` (no se hizo nada porque el recurso dejó de existir o, en una base de datos, está detenida) o `failed`. `ready`, `skipped` y `failed` son finales: el job ya no cambia.
  </ResponseField>

  <ResponseField name="reason" type="string">
    Presente cuando el job está `failed` o `skipped`: el código de error que dice el motivo, como `SNAPSHOT_TIMEOUT` o `SNAPSHOT_CORRUPTED`. Consulta los [códigos de error](/es-es/api-reference/errors).
  </ResponseField>

  <ResponseField name="snapshot_id" type="string">
    En un job `snapshot`, el snapshot que produjo: siempre presente cuando el job está `ready`, así que puedes leer el snapshot justo después. En un job `restore`, el snapshot que se está restaurando, presente desde el principio.
  </ResponseField>

  <ResponseField name="details" type="object">
    Presente junto con `reason` cuando el error trae detalles: los mismos `details` que el error tendría en una respuesta directa. `max_bytes` para `SNAPSHOT_TOO_LARGE`; `required_bytes`, `available_bytes` y, en una base de datos, `required_ram_mb` para `SNAPSHOT_EXCEEDS_STORAGE`.
  </ResponseField>

  <ResponseField name="created_at" type="string">
    Cuándo se creó el job.
  </ResponseField>

  <ResponseField name="started_at" type="string">
    Cuándo empezó el job. Ausente mientras `queued`.
  </ResponseField>

  <ResponseField name="finished_at" type="string">
    Cuándo terminó el job. Ausente hasta entonces.
  </ResponseField>

  <ResponseField name="progress" type="object">
    Solo mientras el job está `running`, y puede faltar (por ejemplo justo al empezar, o cuando no se conoce el progreso). No se envía en ningún otro estado.

    <Expandable title="Mostrar objeto">

    <ResponseField name="phase" type="string">
      `preparing`, `copying` o `finishing`.
    </ResponseField>

    <ResponseField name="percent" type="number">
      Progreso general, de 0 a 100. Ausente cuando no se conoce el tamaño total.
    </ResponseField>

    <ResponseField name="done_bytes" type="number">
      Bytes procesados hasta ahora.
    </ResponseField>

    <ResponseField name="total_bytes" type="number">
      Total de bytes a procesar.
    </ResponseField>

    <ResponseField name="eta_seconds" type="number">
      Estimación de segundos restantes. Ausente hasta que la estimación es estable.
    </ResponseField>

    </Expandable>
  </ResponseField>

  </Expandable>
</ResponseField>

Los jobs de un recurso que se borró se siguen devolviendo a la cuenta que lo poseía. Para un recurso que no existe, la lista vuelve vacía. Esta ruta admite 120 peticiones por minuto.

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope `snapshots:read` (`403`).
  - `ACCESS_DENIED`: Eres miembro de un workspace sin el permiso para esta acción, o no enviaste el `workspace_id` (`403`).
  - `VALIDATION_ERROR`: `limit` no es un número de 1 a 50, o `scope` o `kind` tienen un valor que no existe (`400`).
  - `INTERNAL_SERVER_ERROR`: Ocurrió un error inesperado del servidor.
</ResponseField>
