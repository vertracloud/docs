---
title: Crear snapshot de la aplicación
sidebarTitle: Crear snapshot
api: POST https://api.vertracloud.app/v1/users/{id}/snapshots
authMethod: bearer
description: Toma ahora un snapshot del volumen de una aplicación o base de datos. Aparece en la lista y se puede restaurar o descargar como cualquier otro.
---

{/* @see success/error — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la aplicación o de la base de datos de la que tomar el snapshot.
</ParamField>

<ParamField query="scope" type="string" required>
  El tipo de recurso. Valores posibles: `applications`, `databases`.
</ParamField>

<Note>
  **Se aplican dos límites a los snapshots manuales, además de las 5 peticiones por minuto de la ruta.** El mismo
  recurso solo puede tener un snapshot cada **5 minutos**, y una cuenta puede crear como máximo **10
  snapshots por hora** entre todos sus recursos. Si se supera cualquiera de los dos límites, la API responde
  `429 SNAPSHOT_RATE_LIMITED` con `details.scope` (`resource` o `account`) y
  `details.retry_after` en segundos. Los snapshots que toma la plataforma por su cuenta (antes de un borrado o de un reset) no cuentan. Consulta [Límite de peticiones](/es-es/api-reference/introduction#cómo-se-aplican-los-límites-de-peticiones-a-la-api).
</Note>

### Respuesta

<ResponseField name="response" type="object">
  El snapshot que se creó.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    El ID del snapshot. Úsalo con [restaurar](/es-es/api-reference/endpoint/apps/snapshots/restore) y
    [descargar](/es-es/api-reference/endpoint/apps/snapshots/download).
  </ResponseField>

  <ResponseField name="resource_id" type="string">
    El ID del recurso al que pertenece este snapshot.
  </ResponseField>

  <ResponseField name="type" type="number">
    `1` para una aplicación, `2` para una base de datos.
  </ResponseField>

  <ResponseField name="size" type="number">
    Tamaño en kilobytes.
  </ResponseField>

  <ResponseField name="resource_name" type="string | null">
    El nombre que tenía el recurso en el momento en que se tomó el snapshot.
  </ResponseField>

  <ResponseField name="created_at" type="string">
    Cuándo se tomó el snapshot.
  </ResponseField>

  <ResponseField name="expires_at" type="string">
    Cuándo se eliminará automáticamente el snapshot.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `USER_NOT_FOUND`: No se encontró el usuario autenticado.
  - `APP_NOT_FOUND`: La aplicación indicada no existe.
  - `DATABASE_NOT_FOUND`: La base de datos indicada no existe.
  - `ACCESS_DENIED`: El usuario no es propietario del recurso.
  - `PLAN_NOT_ALLOWED`: El plan de la cuenta no incluye los snapshots manuales (`403`).
  - `DATABASE_NOT_RUNNING`: La base de datos debe estar en ejecución para tomar un snapshot (`409`). Redis no tiene este requisito.
  - `SNAPSHOT_RATE_LIMITED`: El recurso tiene un snapshot de hace menos de 5 minutos, o la cuenta ya creó 10 snapshots en esta hora (`429`). Viene con `details.scope` y `details.retry_after`.
  - `OPERATION_IN_PROGRESS`: Otra operación de ciclo de vida sobre el mismo recurso ya está en curso (`409`). No se tomó ningún snapshot; espera unos segundos y vuelve a intentarlo.
  - `INTERNAL_SERVER_ERROR`: No se pudo guardar el snapshot, o se produjo un fallo inesperado (`500`). Vuelve a intentarlo más tarde.
</ResponseField>
