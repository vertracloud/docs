---
title: Obtener una base de datos por ID
sidebarTitle: Obtener base de datos
api: GET https://api.vertracloud.app/v1/databases/{id}
authMethod: bearer
description: Obtiene los detalles de una base de datos concreta a partir de su ID.
---

{/* @see APIDatabase — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la base de datos que se va a obtener. Si la base de datos pertenece a un workspace, pasa su ID en el parámetro de consulta `workspace_id`.
</ParamField>

<ParamField query="workspace_id" type="string">
  Si la base de datos pertenece a un workspace, el ID del workspace. Es obligatorio para los miembros del workspace que actúan sobre una base de datos que no les pertenece.
</ParamField>

### Respuesta

<ResponseField name="response" type="object">
  Los detalles de la base de datos.

  <Expandable title="Mostrar objeto">

  <ResponseField name="id" type="string">
    El ID de la base de datos.
  </ResponseField>

  <ResponseField name="cluster" type="number">
    El ID del clúster de la base de datos.
  </ResponseField>

  <ResponseField name="type" type="number">
    El tipo de la base de datos.
  </ResponseField>

  <ResponseField name="name" type="string">
    El nombre de la base de datos.
  </ResponseField>

  <ResponseField name="description" type="string">
    La descripción de la base de datos.
  </ResponseField>

  <ResponseField name="owner_id" type="string">
    El ID del propietario de la base de datos.
  </ResponseField>

  <ResponseField name="owner_plan" type="string | null">
    El nombre del plan del propietario (por ejemplo, `pro` o `enterprise-8`), o `null` cuando el propietario no tiene plan.
  </ResponseField>

  <ResponseField name="status" type="string">
    El estado de la base de datos (por ejemplo, `up`).
  </ResponseField>

  <ResponseField name="ram" type="number">
    La RAM asignada a la base de datos, en MB.
  </ResponseField>

  <ResponseField name="host" type="string">
    La dirección del host de la base de datos.
  </ResponseField>

  <ResponseField name="port" type="number">
    El puerto que usa la base de datos.
  </ResponseField>

  <ResponseField name="username" type="string">
    El usuario con el que conectarse. Las bases de datos creadas desde la v26.4.8 usan `vertracloud` (base de datos por defecto `vertracloud`, sin ser superusuario); las bases de datos anteriores conservan el usuario del motor (`postgres`, `default` o `root`).
  </ResponseField>

  <ResponseField name="version" type="string">
    La versión mayor del motor, por ejemplo `"18"` u `"8.0"`. Las actualizaciones de seguridad se aplican al reiniciar sin cambiarla.
  </ResponseField>

  <ResponseField name="stack_id" type="string | null">
    El ID del [stack](/es-es/api-reference/endpoint/stacks/get) al que pertenece la base de datos, o `null` si no forma parte de ninguno.
  </ResponseField>

  <ResponseField name="stack_service_key" type="string | null">
    El ID del servicio de plantilla que corresponde a esta base de datos dentro del stack, o `null` si la añadiste tú.
  </ResponseField>

  <ResponseField name="created_at" type="string" format="date-time">
    La marca de tiempo en que se creó la base de datos.
  </ResponseField>

  <ResponseField name="updated_at" type="string" format="date-time">
    La marca de tiempo de la última actualización de la base de datos.
  </ResponseField>

  <ResponseField name="offline_since" type="string | null" format="date-time">
    La marca de tiempo desde la que la base de datos está fuera de línea, si procede.
  </ResponseField>

  <ResponseField name="last_snapshot" type="string | null" format="date-time">
    La marca de tiempo del último snapshot, si está disponible.
  </ResponseField>

  </Expandable>
</ResponseField>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP que no está en su lista de permitidas, o no tiene el ámbito que requiere la ruta (`403`).
  - `ACCESS_DENIED`: El recurso pertenece a otra cuenta, o no tienes el permiso de workspace necesario para él (`403`).
  - `DATABASE_NOT_FOUND`: La base de datos indicada no existe o el usuario no tiene acceso.
</ResponseField>

<ResponseField name="message" type="string">
  Un mensaje descriptivo con más detalles sobre el error.
</ResponseField>


</ResponseExample>
