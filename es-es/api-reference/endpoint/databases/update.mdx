---
title: Actualizar una base de datos
sidebarTitle: Actualizar base de datos
api: PUT https://api.vertracloud.app/v1/databases/{id}
authMethod: bearer
description: Actualiza el nombre, la descripción o la RAM de una base de datos por su ID.
---

{/* @see APIDatabase — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la base de datos que se va a actualizar.
</ParamField>


<ParamField query="workspace_id" type="string">
  Si la base de datos pertenece a un workspace, el ID del workspace.
</ParamField>

<ParamField body="name" type="string">
  El nuevo nombre de la base de datos. De 1 a 50 caracteres.
</ParamField>

<ParamField body="description" type="string | null">
  La nueva descripción, de hasta 128 caracteres. Una cadena vacía o `null` la borra.
</ParamField>

<ParamField body="ram" type="number">
  La nueva RAM en MB, un entero positivo. Debe caber en la memoria libre del plan y respetar el mínimo del motor (512 MB para Redis, 1024 MB para los demás). Cambiar la memoria se aplica al instante, al subirla o al bajarla. Si la base de datos está usando más memoria que el nuevo límite en ese momento, se cierra por falta de memoria; el panel te avisa y pide confirmación antes de guardar. El almacenamiento de la base de datos sigue a su memoria, así que bajar la memoria de una base de datos que guarda más datos de los que cabe en el nuevo almacenamiento se rechaza con `409` `STORAGE_ABOVE_NEW_LIMIT`.
</ParamField>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `VALIDATION_ERROR`: Un campo del cuerpo o de la consulta no superó la validación (`400`).
  - `INVALID_RAM_LIMIT`: La RAM solicitada está fuera de lo que permiten el motor y el plan (`400`).
  - `MEMORY_LIMIT_EXCEEDED`: El plan no tiene suficiente memoria libre para la nueva RAM (`400`).
  - `ACCESS_DENIED`: Eres miembro de un workspace sin el permiso para esta acción, o no enviaste el `workspace_id` (`403`).
  - `DATABASE_NOT_FOUND`: La base de datos no se encontró (`404`).
  - `OPERATION_IN_PROGRESS`: Hay otra operación del ciclo de vida en curso sobre esta base de datos (`409`).
  - `STORAGE_ABOVE_NEW_LIMIT`: La base de datos guarda más datos de los que permite el almacenamiento de la nueva RAM (`409`). No se cambió nada.
</ResponseField>

<ResponseField name="details" type="object">
  Presente en `STORAGE_ABOVE_NEW_LIMIT`. Incluye `used_mb`, `limit_mb` y `free_mb`: cuánto guarda la base de datos, el almacenamiento que permitiría la RAM solicitada y cuánto hay que borrar antes de que se acepte el cambio.
</ResponseField>

<ResponseExample>

```json Error Response (404)
{
  "code": "DATABASE_NOT_FOUND"
}
```

```json Error Response (409)
{
  "code": "STORAGE_ABOVE_NEW_LIMIT",
  "details": {
    "used_mb": 9216,
    "limit_mb": 8192,
    "free_mb": 1024
  }
}
```

</ResponseExample>
