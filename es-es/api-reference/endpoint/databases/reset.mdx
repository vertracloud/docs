---
title: Restablecer una base de datos
sidebarTitle: Restablecer base de datos
api: POST https://api.vertracloud.app/v1/databases/{id}/reset
authMethod: bearer
description: Restablece una base de datos por su ID y borra sus datos al momento y para siempre. Crea un snapshot antes si puedes necesitar los datos.
---

{/* @see success — @vertracloud/api-types */}
Borra todos los datos de la base de datos al momento. Es permanente: no hay vuelta atrás, así que [crea un snapshot](/es-es/api-reference/endpoint/apps/snapshots/create)
antes si puedes necesitar los datos. Los snapshots que ya tengas siguen disponibles. Una clave de API necesita el ámbito `databases:delete`, y en un workspace el miembro necesita el permiso `databases:delete`.

<ParamField path="id" type="string" required>
  El ID de la base de datos que se va a restablecer.
</ParamField>

### Respuesta

<ResponseField name="response" type="object">
  <Expandable title="Mostrar objeto">

  <ResponseField name="status" type="string">
    `success`, cuando la base de datos se restableció.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "status": "success"
  }
}
```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP que no está en su lista de permitidas, o no tiene el ámbito que requiere la ruta (`403`).
  - `ACCESS_DENIED`: Eres miembro de un workspace sin el permiso para esta acción, o no enviaste el `workspace_id` (`403`).
  - `DATABASE_NOT_FOUND`: La base de datos indicada no se encontró.
  - `DATABASE_ID_REQUIRED`: No se indicó el ID de la base de datos.
  - `INTERNAL_SERVER_ERROR`: No se pudo restablecer la base de datos.
</ResponseField>

<ResponseField name="message" type="string">
  Un mensaje descriptivo con más detalles sobre el error.
</ResponseField>

<ResponseExample>

</ResponseExample>
