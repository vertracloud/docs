---
title: Restablecer los certificados de una base de datos
sidebarTitle: Restablecer certificados
api: POST https://api.vertracloud.app/v1/databases/{id}/credentials/certificate/reset
authMethod: bearer
description: Restablece los certificados de una base de datos concreta a partir de su ID.
---

{/* @see success — @vertracloud/api-types */}
<ParamField path="id" type="string" required>
  El ID de la base de datos cuyos certificados se van a restablecer.
</ParamField>

### Respuesta

<ResponseField name="response" type="object">
  Los nuevos detalles del certificado de la base de datos.

  <Expandable title="Mostrar objeto">

  <ResponseField name="pem" type="string">
    El nuevo certificado PEM.
  </ResponseField>

  <ResponseField name="crt" type="string">
    El nuevo certificado CRT.
  </ResponseField>

  <ResponseField name="key" type="string">
    La nueva clave privada del certificado.
  </ResponseField>

  <ResponseField name="ca" type="string">
    El certificado de la CA (PEM) que firma el certificado del servidor de la base de datos. No aparece en bases de datos antiguas.
  </ResponseField>

  <ResponseField name="p12" type="string">
    La nueva identidad de cliente en PKCS#12, codificada en base64, con una contraseña vacía. No aparece en bases de datos antiguas.
  </ResponseField>

  <ResponseField name="restart_required" type="boolean">
    `true` cuando al menos una aplicación de un stack conectado debe reiniciarse para leer los nuevos certificados.
  </ResponseField>

  <ResponseField name="apps_to_restart" type="string[]">
    Los IDs de esas aplicaciones. Vacío cuando `restart_required` es `false`.
  </ResponseField>

  </Expandable>
</ResponseField>

<ResponseExample>

```json Response
{
  "response": {
    "pem": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "crt": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "key": "-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----",
    "ca": "-----BEGIN CERTIFICATE-----\nMIID...\n-----END CERTIFICATE-----",
    "p12": "MIIJqQIBAzCCCW8GCSqGSIb3DQEHAaCCCWAEgglc...",
    "restart_required": false,
    "apps_to_restart": []
  }
}
```

</ResponseExample>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP que no está en su lista de permitidas, o no tiene el ámbito que requiere la ruta (`403`).
  - `ACCESS_DENIED`: El recurso pertenece a otra cuenta, o no tienes el permiso de workspace necesario para él (`403`).
  - `DATABASE_NOT_FOUND_OR_FORBIDDEN`: La base de datos indicada no existe o el usuario no tiene acceso.
  - `FAILED_TO_RESET_CERTIFICATES`: No se pudieron restablecer los certificados.
</ResponseField>

<ResponseField name="message" type="string">
  Un mensaje descriptivo con más detalles sobre el error.
</ResponseField>

<ResponseExample>

```json Error Response (403)
{
  "code": "ACCESS_DENIED"
}
```

```json Error Response (404)
{
  "code": "DATABASE_NOT_FOUND_OR_FORBIDDEN"
}
```

```json Error Response (500)
{
  "code": "FAILED_TO_RESET_CERTIFICATES"
}
```

</ResponseExample>
