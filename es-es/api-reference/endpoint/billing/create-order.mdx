---
title: Crear pedido
sidebarTitle: Crear pedido
api: POST https://api.vertracloud.app/v1/orders
authMethod: bearer
description: Crea un pedido para comprar, renovar o actualizar un plan.
---
<ParamField body="type" type="string" default="purchase">
  Para qué es el pedido. Valores posibles: `purchase`, `renew`, `upgrade`.
</ParamField>

<ParamField body="plan" type="string" required>
  El nombre del plan que se compra, renueva o al que se actualiza, como `starter-1` o `pro-4`. Los nombres están en [Listar planes](/es-es/api-reference/endpoint/plans/list). Un plan que ya no se vende devuelve `PLAN_NOT_FOR_SALE`.
</ParamField>

<ParamField body="months" type="integer" required>
  Cuántos meses comprar: `1`, `3`, `6` o `12`. Cualquier otro valor devuelve `INVALID_MONTHS`. Un pedido de
  3 meses tiene un 10% de descuento, uno de 6 meses un 15% y uno de 12 meses un 25% sobre el precio mensual;
  `price` y `discount` ya lo incluyen. [Cotizar pedido](/es-es/api-reference/endpoint/billing/quote-order)
  devuelve el importe exacto antes de crear el pedido. Se ignora cuando el upgrade cobra solo la diferencia (consulta la nota de abajo): se usa el ciclo de facturación de la cuenta.
</ParamField>

<ParamField body="coupon" type="string">
  Un código de cupón de descuento opcional.
</ParamField>

<Note>
  El pedido necesita datos de facturación completos: comprueba `complete` en [Obtener los datos de facturación](/es-es/api-reference/endpoint/billing/get-billing-details).
</Note>

<Note>
  Un pedido `renew` requiere que el plan indicado coincida con el plan actual de la cuenta; un pedido `upgrade`
  requiere que sea estrictamente superior. Usa `type: "purchase"` cuando todavía no exista un plan activo de ese tipo.
</Note>

<Note>
  **Upgrade que cobra solo la diferencia.** Cuando la cuenta tiene un plan activo pagado con Pix o tarjeta con **más de 14 días**
  restantes y el pedido es para un plan mayor, pagas solo la diferencia entre el precio del plan nuevo y el del plan
  actual, en el ciclo de facturación de la cuenta y de forma proporcional a los días restantes. El vencimiento no cambia
  y la siguiente renovación ya sale en el plan nuevo, en el mismo ciclo. La respuesta incluye `proration`. Un cupón se
  aplica sobre la diferencia con sus reglas habituales, y el periodo es el ciclo de la cuenta; el descuento de primera
  compra de referidos no se aplica a ella. Con **14 días o menos** restantes, o cuando el periodo actual no se pagó con Pix o tarjeta (código canjeado, cortesía o pedido de valor cero), el pedido es una compra normal del plan nuevo por `months`, y el valor de los días
  restantes se convierte en tiempo adicional. La plataforma lo decide al crear el pedido: la misma petición se
  calcula como compra normal cuando la cuenta no cumple las condiciones.
</Note>

### Respuestas de error

<ResponseField name="code" type="string">
  El código de error que indica el motivo del fallo. Valores posibles:
  - `AUTH_TOKEN_MISSING`, `API_KEY_INVALID`, `SESSION_REVOKED`: Falta la cabecera `Authorization`, la clave de API no es válida o la sesión del panel fue revocada (`401`).
  - `API_KEY_IP_DENIED`, `API_KEY_SCOPE_DENIED`: La clave de API se usa desde una IP fuera de su lista de permitidas, o no tiene el scope que requiere la ruta (`403`).
  - `USER_NOT_FOUND`: No se encontró el usuario autenticado.
  - `INVALID_PAYLOAD`: El cuerpo de la petición no superó la validación.
  - `BILLING_DETAILS_INCOMPLETE`: Los datos de facturación no están completos (nombre, dirección y, en Brasil, CPF/CNPJ). Guárdalos con [Actualizar los datos de facturación](/es-es/api-reference/endpoint/billing/update-billing-details) y vuelve a intentarlo.
  - `MISSING_PLAN_OR_MONTHS`: Falta `plan` o `months`.
  - `INVALID_MONTHS`: `months` no es `1`, `3`, `6` o `12`.
  - `INVALID_PLAN`: El nombre del plan no existe.
  - `PLAN_NOT_FOR_SALE`: El plan ya no se vende (`400`).
  - `NOT_AN_UPGRADE`: Para `type: "upgrade"`, el plan indicado no es superior al actual.
  - `PLAN_MISMATCH_FOR_RENEWAL`: Para `type: "renew"`, el plan indicado no coincide con el actual.
  - `PENDING_ORDER_LIMIT_REACHED`: Ya hay demasiados pedidos pendientes de pago abiertos.
  - `INTERNAL_SERVER_ERROR`: Se produjo un error inesperado en el servidor.
</ResponseField>
