{/* @see RESTPostAPIStackSnapshotRestoreBody, RESTPostAPIStackSnapshotRestoreResponse — @vertracloud/api-types */}
Restaura todos los miembros juntos: primero las bases de datos y después las aplicaciones. Se detiene en el primer error e informa de lo que ya se restauró en `details.restored`. Requiere el scope `stacks:write` cuando se llama con una clave de API.

<ParamField path="stack_id" type="string" required>
  El ID del stack.
</ParamField>

<ParamField path="snapshot_id" type="string" required>
  El ID de la snapshot del stack.
</ParamField>

<ParamField query="workspace_id" type="string">
  El workspace al que pertenece el stack, cuando actúas sobre él como propietario del workspace.
</ParamField>

<ParamField body="restore_image_version" type="boolean" default="false">
  Las aplicaciones que ejecutan una imagen personalizada también vuelven a la versión de imagen de la snapshot, si todavía existe.
</ParamField>

### Response

El resultado de la restauración, como en [Restaurar snapshot de aplicación](/es-es/api-reference/endpoint/apps/snapshots/restore).

### Errores

| Estado | Código | Cuándo |
|---|---|---|
| 403 | `WORKSPACE_OWNER_ONLY` | Eres miembro del workspace, no su propietario. |
| 404 | `STACK_NOT_FOUND` | El stack no existe o pertenece a otra cuenta. |
