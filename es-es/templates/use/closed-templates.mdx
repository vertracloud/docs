Una plantilla cerrada es una plantilla privada cuyo autor decidió no mostrar el código. El código permanece dentro de la aplicación, pero quienes usan la plantilla no pueden leerlo, descargarlo ni cambiarlo. Aun así puedes ejecutar la aplicación, leer sus logs y métricas, crear y restaurar snapshots, hacer rollback, actualizarla y usar sus bases de datos sin ninguna restricción.

Solo las plantillas privadas pueden cerrarse. Las plantillas públicas (Vertra y Community) siempre muestran su código.

## Qué puedes y qué no puedes hacer

| Puedes | No puedes |
|---|---|
| Iniciar, detener y reiniciar la aplicación, leer logs y métricas | Usar el gestor de archivos (ver, subir, mover, eliminar) |
| Crear un snapshot y **restaurarlo** | **Descargar** un snapshot |
| Hacer **rollback** | Descargar la aplicación |
| Responder a las preguntas de la plantilla y cambiar la memoria, si la plantilla lo permite | Crear variables libres (como `NODE_OPTIONS`) |
| Actualizar a una versión nueva | Editar los comandos de inicio y de build |
| Mover la aplicación a otra carpeta o workspace | Usar un terminal |
| Usar las **bases de datos** del stack sin restricción | Desplegar por GitHub o subiendo código |
| | Guardar como plantilla, desvincular de la plantilla o crear un enlace de copia completa |

El bloqueo lo aplica la API en cada ruta de archivos y de código, no solo el panel, así que un script o una clave de API se topa con el mismo muro. El rechazo es `TEMPLATE_CLOSED`. Las variables que el autor marcó como ocultas se inyectan en la aplicación y nunca las devuelve la API ni las muestra el panel. Los valores ocultos existen solo en plantillas cerradas y, si la aplicación o el stack se desvincula alguna vez de la plantilla, se eliminan.

## Las bases de datos nunca están cerradas

Las bases de datos de un stack están siempre abiertas para ti: puedes conectarte, hacer copias de seguridad e inspeccionarlas. Se aconseja a los autores guardar los datos de sus usuarios en estas bases de datos, porque todo lo que se almacena en el `/app` de una plantilla cerrada es responsabilidad del autor.

## Snapshots de una aplicación cerrada

Un snapshot de una aplicación cerrada recuerda que está cerrada, aunque la aplicación se elimine más tarde.

- **Nunca se puede descargar**.
- Solo se puede restaurar en una aplicación **de la misma plantilla**, que sigue cerrada.
- Crear una aplicación a partir de él crea una aplicación con la misma política de cierre.
- Restaurarlo en una aplicación normal se rechaza.

## En quién estás confiando

La plataforma no te da ningún camino al código y no garantiza el código propio del autor. Si el código del autor expone archivos o envía tus datos a otro sitio, es responsabilidad del autor, y Vertra Cloud puede actuar ante denuncias. Los valores que rellenas en el asistente (por ejemplo, una clave de API de un proveedor de modelos) van a código que no puedes leer, así que estás confiando en el autor. La página de la plantilla y la vista previa del enlace para compartir lo advierten antes de que crees nada.

Si algo parece sospechoso, [denúncialo](/es-es/templates/use/receive-a-link#denunciar-una-plantilla).

## Actualizaciones y política de cierre

Una aplicación conserva la política con la que se creó. Si una nueva versión abre la plantilla, la aplicación se abre con la actualización; si una nueva versión lo cierra, solo se cierran las aplicaciones creadas después. Consulta [Actualizar y hacer rollback](/es-es/templates/use/updates-and-rollback).

Para crear tu propia plantilla cerrada, consulta [Permisos](/es-es/templates/create/permissions) y el [tutorial para un cliente](/es-es/templates/tutorials/closed-template-for-client).
