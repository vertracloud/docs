Es un bot mínimo de Discord en Python con discord.py 2.7.1 y un comando `/ping`. Es una **plantilla de código**: el código es tuyo, abierto y editable, y Vertra Cloud ejecuta lo que hay en `src/`.

## Qué crea

Una aplicación (código) en el runtime de Python, **sin dirección web**: el bot solo hace conexiones salientes. Necesita al menos **100 MB** de memoria (256 MB recomendados) y **ningún cupo de imagen**, así que cualquier plan puede ejecutarlo. Consulta [Qué son las plantillas](/es-es/templates/overview).

- Inicia sesión con el token del bot, registra el comando slash `/ping` en cada arranque y responde con la latencia del gateway.
- Usa solo el intent `Guilds`, así que no hay ningún intent privilegiado que activar.
- Sin token o con un token incorrecto el proceso termina con el código 1 y un mensaje claro en el log de la aplicación.
- Código fuente en `src/main.py`; dependencias en `src/requirements.txt`.

## Qué pregunta el asistente

| Pregunta | Qué hace |
|---|---|
| Bot token | Se convierte en la variable cifrada `DISCORD_TOKEN`. |

## Primeros pasos

<Steps>
  <Step title="Crea el bot y obtén el token">
    En el [Discord Developer Portal](https://discord.com/developers/applications) crea una **New Application**, abre **Bot** y haz clic en **Reset Token**. Copia el valor: se muestra una sola vez.
  </Step>
  <Step title="Pégalo en el asistente">
    Pega el token cuando el asistente lo pida. Se guarda cifrado y nunca va en el código.
  </Step>
  <Step title="Invita al bot">
    En **OAuth2 > URL Generator** marca los scopes `bot` y `applications.commands`, abre la URL generada y elige tu servidor.
  </Step>
  <Step title="Comprueba">
    Tras el despliegue el log de la aplicación muestra `Logged in as <bot name>`. En Discord, escribe `/ping`: el bot responde `Pong!` con la latencia. El comando global puede tardar unos minutos en aparecer la primera vez.
  </Step>
</Steps>

## Hazla tuya

Abre `src/main.py`, añade tus comandos y despliega de nuevo, o reinicia si editaste en el editor de la aplicación. Para añadir librerías, indícalas en `requirements.txt` con una versión fijada: la plataforma instala las dependencias en cada despliegue.

Editar el código desvincula la aplicación de la plantilla, así que deja de recibir nuevas versiones de ella. Consulta [Actualizar y revertir](/es-es/templates/use/updates-and-rollback#aplicaciones-desvinculadas-y-plantillas-retiradas).

## Referencia

| Elemento | Valor |
|---|---|
| Variable | `DISCORD_TOKEN` (cifrada, desde el asistente) |
| Comando de inicio | `python3 -u main.py` |
| Archivo principal | `main.py` |
| Memoria | 100 MB (mínimo), 256 MB (recomendado) |
| Web | Ninguna |
| Despliegue sin caída | Desactivado (un token es una copia) |

## Límites y problemas comunes

- Dos copias con el mismo token responderían dos veces, por eso el despliegue sin caída está desactivado.
- El mínimo es 100 MB, y 256 MB (lo recomendado) bastan para un bot sencillo. Un bot en muchos servidores o con una caché grande necesita más; puedes subir la memoria.
- Los comandos globales de Discord tardan en propagarse. Para pruebas, registra comandos de servidor (guild) en tu código.
- **`Login failed` en el log.** `DISCORD_TOKEN` no es el token del bot. Restablécelo en el Portal, actualiza la variable y reinicia.
- **`/ping` no aparece.** Espera unos minutos y comprueba que la invitación tenía el scope `applications.commands`.
- **La aplicación no se mantiene en pie.** Sin un token válido el proceso termina con el código 1. Corrige el token y reinicia.
