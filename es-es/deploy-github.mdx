Una aplicación de Vertra Cloud se puede crear desde un repositorio de GitHub público o privado y actualizarse
automáticamente en cada push a la rama que elijas. Crear desde GitHub funciona en cualquier plan; el despliegue
automático requiere el plan **Intermediary** o superior.

## Crear la aplicación desde GitHub

<Steps>
  <Step title="Abrir Nuevo Proyecto">
    En el panel, haz clic en **Nuevo Proyecto** y elige **Importar desde GitHub**.
  </Step>
  <Step title="Indicar el repositorio">
    Pega la URL del repositorio (`https://github.com/owner/repository`) o usa **Elegir entre mis
    repositorios** para listar los repositorios de tu cuenta. Los repositorios privados requieren conectar
    tu cuenta de GitHub, lo que instala la app de Vertra Cloud en los repositorios que autorices.
  </Step>
  <Step title="Elegir la rama">
    La rama por defecto del repositorio viene preseleccionada. Elige otra y el árbol de archivos y el código importado cambian a ella.
  </Step>
  <Step title="Seguir el flujo normal">
    A partir de aquí el flujo es el mismo que al subir un `.zip`: build, entorno, red, revisión y
    despliegue. Consulta [Primer despliegue](/es-es/how-to-host).
  </Step>
</Steps>

Para subir una versión nueva más adelante, activa el despliegue automático que se describe a continuación o usa `vertra deploy` en la
[CLI](/es-es/cli).

## Activar el despliegue automático

Con el despliegue automático activado, cada push a la rama elegida publica la nueva versión: la plataforma
descarga el código de ese commit y lo despliega. Sin rama elegida, un push a `main` o `master` despliega.

1. En la aplicación, abre **Ajustes → Deploy** y ve a **Deploy automático**.
2. Elige la cuenta de GitHub y el repositorio.
3. Elige la rama. La rama por defecto del repositorio viene preseleccionada. Si no se puede cargar la lista de ramas, el webhook sigue `main` o `master`.
4. Haz clic en **Activar deploy automático**.

Vertra Cloud crea el webhook en el repositorio por ti; no hace falta configurar nada en
GitHub. La misma sección muestra la rama actual y permite cambiarla; volver a vincular sin rama vuelve a `main` o `master`.
Para desactivarlo, usa **Desactivar**. El webhook también se elimina cuando se borra la aplicación.

<Note>
  Los push a otras ramas se ignoran. Los webhooks creados antes de poder elegir rama siguen con `main` y `master`. Cada push cuenta para el
  [límite de despliegues por hora](/es-es/plans-and-limits#límite-de-despliegues-por-hora) del plan; un push que llega una vez superado el
  límite se descarta y se registra en la pestaña **Actividad**.
</Note>

## Mediante la API

El despliegue automático también se puede crear, consultar y eliminar mediante la
[API de despliegues](/es-es/api-reference/endpoint/apps/deploys/webhookurl), con una clave que tenga el
alcance `apps:write`.
