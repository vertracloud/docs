A chat interface with AI for your team. The template runs Open WebUI v0.12.4 (`slim` variant). **You bring the model key**: Vertra Cloud does not host a model.

## What it creates

One app (image), plus a managed Postgres database if you choose it for storage.

| | |
|---|---|
| Memory | App 512 MB (1024 MB recommended); Postgres 1024 MB when chosen. |
| Plan | A plan with Docker images and one free [image slot](/templates/overview#image-slots). See [Plans and limits](/plans-and-limits). |

## What the wizard asks

| Question | What it does |
|---|---|
| Model provider | OpenAI, OpenRouter, Anthropic, Google Gemini (all through the OpenAI-compatible API) or another address. |
| API address | Only with "Other"; ends in `/v1`. |
| Provider API key | Kept only in the app's encrypted variables. |
| Administrator email and password | The administrator is created for you. Open sign-up is off. |
| Where does Open WebUI store its data? | **SQLite** on the app's disk (default; personal use or a small team) or **managed Postgres** (1 GB more memory). |

## First steps

<Steps>
  <Step title="Sign in">
    Open the address and sign in with the administrator email and password you typed. The password only creates the account while no user exists; afterwards change it in **Profile > Password**.
  </Step>
  <Step title="Chat">
    The provider's models appear in the selector at the top of the chat.
  </Step>
  <Step title="Invite the team">
    Open sign-up is off. Create accounts in **Admin panel > Users > Add**.
  </Step>
  <Step title="Add or switch providers">
    In **Admin settings > Connections** add any OpenAI-compatible API (OpenRouter, Anthropic and Gemini through their compatible routes, or your own server).
  </Step>
</Steps>

## Variables

| Variable | What it does |
|---|---|
| `WEBUI_SECRET_KEY` | Signs the logins; changing it signs everyone out. |
| `WEBUI_ADMIN_EMAIL`, `WEBUI_ADMIN_PASSWORD` | Create the administrator if no user exists. |
| `ENABLE_SIGNUP` | `false`: open sign-up off. |
| `OPENAI_API_BASE_URL`, `OPENAI_API_KEY` | The provider's address and key. |
| `DATABASE_URL` | Only with Postgres. |
| `DATA_DIR` | `/app/data`: data on the app's disk. |

## Limits and good practice

- The `slim` variant has no local embeddings model: semantic-search retrieval is not available and attached files go whole into the model's context. Use small files or long-context models.
- With SQLite the data is `/app/data/webui.db`, part of the app's snapshots. With Postgres it lives in the stack's database.
- Zero-downtime deploy is off; a rollback returns **with the data**.
- Memory: 512 MB is the minimum (about 300 MiB in use); 1 GB gives room for attachments and several people.

## Common problems

- **No model shows up.** The key or the address is wrong: check **Connections** and the `OPENAI_API_*` variables.
- **I cannot create an account.** Open sign-up is off on purpose; ask the administrator.
