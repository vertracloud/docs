### Web Analytics

Every web application now has an **Analytics** tab with the traffic measured by Vertra's edge network: how many people visit, how fast the site answers, where the errors are and what each request looked like. There is nothing to install and nothing to turn on. See [Web Analytics](/web-analytics/overview).

- **Summary:** a plain sentence about how the site is doing, plus visitors, requests, response time (p95) and error rate, the traffic chart and the slowest pages.
- **Traffic:** requests, visits and bytes over time, broken down by country, path, referer, device, operating system, browser, HTTP status, method, protocol, network, content type, cache result and verified bots. Click any value to filter every panel at once.
- **Errors:** 5xx errors over time, the paths with the most errors and the status codes behind them. 4xx can be included with one switch.
- **Performance:** the time the visitor waited and the time your application took, at p50, p75, p90, p95, p99 and p99.9, per country, per edge location, the slowest paths and errors and time per path.
- **Requests:** the request log with time, path, status, times, country, device and request ID. IP addresses and URL parameters are masked until you choose to show them.
- **Periods and comparison:** pick 5 minutes up to 30 days, or a custom range, and compare it with the period right before, the same time the week before, or a start date you choose. The compared period always has the same length.
- **Plans:** Summary, Traffic, Errors and comparison are on every plan. Performance and the request log are available from Pro. History goes back 7 days on Starter and Pro and 30 days on Business and Enterprise. See [History and plans](/web-analytics/history-and-plans).
- **Privacy:** Vertra keeps no data that identifies your visitors. Only each application's totals (requests, visits, bytes, error rates and response time) are kept, for up to 31 days, and they are deleted with the application. The [Privacy Policy](https://vertracloud.app/privacy) describes this. See [Privacy](/web-analytics/privacy).

#### API, SDKs, CLI, MCP and VS Code extension

- **New routes** under the `apps:read` scope: [`GET /v1/apps/:id/analytics`](/api-reference/endpoint/apps/analytics/traffic), [`/analytics/errors`](/api-reference/endpoint/apps/analytics/errors), [`/analytics/performance`](/api-reference/endpoint/apps/analytics/performance) and [`/analytics/requests`](/api-reference/endpoint/apps/analytics/requests). They take `start`, `end`, one filter per dimension, `compare` and `compare_start`.
- **New error codes:** `PLAN_DOES_NOT_SUPPORT_WEB_ANALYTICS_PERFORMANCE`, `PLAN_DOES_NOT_SUPPORT_WEB_ANALYTICS_REQUESTS`, `ANALYTICS_RANGE_EXCEEDS_PLAN` and `ANALYTICS_BUSY`. See [Errors](/api-reference/errors).
- **`GET /v1/plans`** gains `features.web_analytics_performance`, `features.web_analytics_requests` and `limits.web_analytics_history_days`.
- **`@vertracloud/api-types` 0.6.1** has the new types. The JavaScript, Python and Go SDKs (0.4.1), the CLI (`vertra app analytics`, `errors`, `performance` and `requests`, v0.3.6), the MCP server (four read tools, 0.3.4) and the VS Code extension (0.3.4) read Web Analytics.
