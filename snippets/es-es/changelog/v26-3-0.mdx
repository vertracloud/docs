- **La barra lateral muestra Docs, Tutoriales, `llms.txt` y MCP Server por encima del separador de la cuenta.** Docs, los tutoriales (YouTube `@vertracloud`) y `llms.txt` se abren en una pestaña nueva. MCP Server está bloqueado por ahora.

Las cifras de peticiones y conexiones marcadas como "vista previa" son marcadores de posición hasta que la API las exponga.

Al abrir un archivo se muestra el marcador del editor (no la lista de carpetas), y volver a una carpeta ya abierta ya no parpadea vacía.

"Hoy" y "mañana" siguen el calendario de Brasilia, y la hora se muestra en formato de 24 horas, en la hora de Fortaleza, con el momento del día ("02:14 de la madrugada", no un "02:14" de 12 horas que podría leerse como de la tarde). La pequeña línea "expira en N días" junto al nombre del plan desaparece.
- **El selector de proyectos muestra primero el proyecto abierto**, luego los que están en ejecución y después los detenidos.
- **La sección Recursos del menú móvil del sitio ahora se abre al tocarla.** Antes se cerraba con el mismo gesto.
- **El soporte es una página, no una tarjeta de FAQ apretada.** Discord, correo y documentación aparecen como tres enlaces; las preguntas usan el mismo acordeón de dos columnas que la página de planes; las guías de abajo llevan a desplegar, errores comunes, cambio a un plan inferior y facturación. Se eliminó el texto antiguo que mencionaba los tickets y el chat en vivo como un producto aparte.

El tipo y el origen comparten el primer paso. Tras elegir un ZIP o un repositorio de GitHub, puedes dar nombre al proyecto y añadir una descripción opcional antes de continuar. Una aplicación pasa luego por build, variables de entorno y red como pasos separados antes de la revisión; una base de datos pasa por motor y almacenamiento y después por la revisión. Atrás y Continuar quedan fijados en la parte inferior de esa tarjeta tras salir de la primera elección. Si el plan no tiene RAM suficiente para la memoria elegida, el paso de build lo indica y Continuar sigue deshabilitado. La importación desde GitHub empieza con la URL de un repositorio, o eliges entre los repositorios de tu cuenta. Las variables de entorno usan el mismo panel lateral que la pestaña Entorno de una aplicación.
- **Los nombres de proyecto respetan el límite de la API de 50 caracteres.** Una importación de ZIP o de GitHub mantenía antes el nombre completo del archivo o del repositorio (a menudo una marca de tiempo más un UUID) y luego fallaba al crear. El asistente recorta ahora ese nombre derivado, y el campo de nombre de la base de datos se detiene en 50.

El botón de crear tiene el mismo tamaño que Nuevo Proyecto, sin el relleno de acento.
- **Cambiar la memoria de un proyecto aparece ahora de inmediato en la lista de proyectos.** La cantidad asignada se quedaba en la cifra antigua hasta volver a cargar la lista.
- **El menú de desbordamiento de una fila de proyecto empieza con Detalles y Configuración.** Logs y terminal conservan su lugar debajo, sin repetir "Abrir" en cada línea. Cuando el menú no cabe en la ventana, se desplaza para que Eliminar siga siendo accesible.

Indica que puedes crear un proyecto —no una aplicación y una base de datos, porque Free no puede crear bases de datos. La acción lleva a Revisar pedido para Economy (mensual, Pix), no a la página de planes. Descartarlo lo oculta durante la sesión; un aviso en la superficie permanece encima de la lista. La cabecera se tiñe con el color del siguiente plan (dorado para Economy), en lugar de rayada.

Tras un canje correcto, la misma tarjeta de plan usada en los avisos de actualización da las gracias y enumera lo que añade el nuevo plan frente al anterior. La hoja de navegación móvil muestra Docs, Tutoriales, `llms.txt` y MCP Server por encima de la fila de la cuenta, igual que la barra lateral de escritorio; crear un proyecto sigue en la página de Proyectos, no en ese menú.
- **Cambiar la RAM de una aplicación ya no trata la memoria sobrante del plan como el presupuesto total.** Los 448 MB no usados del plan son lo que queda tras esta aplicación; la aplicación puede seguir conservando o reducir su propia asignación hasta 512 MB sin una actualización. El campo describe la RAM del contenedor, y "¿Necesitas más RAM en el plan?" abre el diálogo de actualización; no cita el máximo de esta aplicación.
- **La CPU, la memoria, el almacenamiento y la red en vivo siguen en la visión general incluso por debajo de 512 MB**, incluidos los gráficos: dos muestras en vivo bastan para trazar la línea. El suelo de 512 MB solo limita las métricas avanzadas (el historial de 10 m / 30 m / 24 h). El título del aviso lo dice. Ampliar RAM lleva a la configuración del proyecto cuando el plan todavía tiene 512 MB que dar a este proyecto, o abre el mismo diálogo de actualización usado en Proyectos (`?upgrade=pro&upgrade_for=advancedMetrics`) para el siguiente plan que de verdad tiene 512 MB: Pro, no Economy (256 MB). La página antes sustituía toda la sección de telemetría por una tarjeta vacía de "hardware insuficiente".

El gestor de archivos y la pestaña de datos de las bases de datos usan el mismo diseño vacío que Snapshots. Crear un snapshot en un plan sin copias de seguridad (por debajo de Scale) abre el diálogo de actualización a Scale, en lugar de un aviso de error. El título y la descripción siguen la función que lo abrió (snapshot, archivos, reinicio automático, despliegue, métricas, etc.): ya no reutilizan el texto de "la memoria llegó al máximo" salvo que la RAM misma haya sido el desencadenante. El botón "Actualizar a …" de la barra lateral tras la guía de inicio usa el mismo diálogo (`?upgrade=`), no un segundo popup. Al refrescar el panel ya no parpadea Economy antes del siguiente plan real.

Guardar una nueva cantidad de memoria sigue preguntando si reiniciar ahora, como en Configuración. Tras guardar, el encabezado se actualiza de inmediato; antes conservaba el nombre antiguo hasta recargar.

### Workspaces

- **Un workspace ya no se oculta cuando termina tu plan.** Cuando un plan de pago expira, la cuenta vuelve a Free, que no puede crear workspaces, y la página de Workspaces ocultaba los que ya tenías tras el aviso de actualización. Cualquiera en Free que perteneciera al workspace de otra persona veía la misma puerta vacía. La lista se muestra ahora siempre; solo el botón de crear depende del plan.
- **Un workspace cuyo plan del propietario expiró queda congelado, no eliminado.** No se borra nada: los miembros, los proyectos y el propio workspace se conservan. Lo que se detiene es la escritura: renombrar, invitar, cambiar un rol y vincular un proyecto se rechazan mientras falte el plan, y la fila se marca como **Congelado**. Ver, eliminar un miembro o un proyecto, salir y borrar siguen disponibles, y todo vuelve a funcionar en cuanto se renueva el plan. El plan que cuenta es el del **propietario**: un miembro de Free de un workspace de pago no se ve afectado.
- **Los roles ahora coinciden con lo que dice la tabla.** **Operador** puede iniciar, detener y reiniciar aplicaciones y bases de datos, que es el sentido del rol y hasta ahora se rechazaba con un error de acceso. Y **Desarrollador** ya no puede eliminar una aplicación ni una base de datos: la eliminación es irreversible, y la tabla de permisos nunca la concedió. Eliminar es solo para Propietario y Admin. Todo lo demás no cambia: Desarrollador sigue desplegando, editando archivos, variables de entorno, red y configuración.

### Workspaces v2

- **Los códigos de invitación desaparecen.** Trae a personas por **correo electrónico** (una invitación real enviada a una dirección, válida 7 días) o por **enlace** (una URL compartible, válida 24 horas, opcionalmente limitada a un número de usos); ambas asignan un rol de antemano, desde la pestaña Invitaciones del workspace.
- **Los miembros pueden tener fecha de caducidad.** Ponla al invitar o después, y el acceso termina solo en esa fecha. Es útil para un contratista o un colaborador temporal, sin que nadie tenga que acordarse de quitarlo.
- **Las actividades y los registros de auditoría ahora son por workspace**, no solo de tus propias acciones dentro de él: ve todo lo que hizo cualquiera del equipo, con la misma exportación CSV que facturación.
- **La configuración del workspace está en la barra lateral, no en una fila de pestañas.** Al abrir un workspace se listan General, Notas, Miembros, Roles, Invitaciones, Proyectos, Actividad, Facturación, Solicitudes y Zona de peligro, en la misma navegación que el resto del panel. La lista de workspaces usa la misma búsqueda, los mismos filtros y la misma alternancia de lista y tarjetas que Proyectos.
- **Un tablón de notas compartido** para el contexto rápido del equipo: notas adhesivas en siete colores, visibles para todos en el workspace, ahora en su propia pestaña Notas en lugar de mezcladas en General.
- **Los enlaces de invitación se pueden copiar después de crearlos.** Una invitación por enlace mostraba antes la URL una sola vez y después solo un botón de revocar; la acción de copiar permanece en esa fila durante toda la sesión, y crear un enlace lo copia por ti.
- **La pestaña Proyectos es la misma lista que la visión general del panel**: búsqueda, filtros, tarjetas y apertura de un proyecto, no una lista simplificada de nombres.
- **Alcanzar el límite de roles abre el diálogo de actualización** para el siguiente plan que realmente tenga más roles, en lugar de un aviso de error de plan en la hoja de crear rol.
- **Las acciones sensibles se pueden solicitar en lugar de rechazarse.** Un miembro sin permiso para eliminar un proyecto o gestionar un snapshot ahora puede pedirlo; quien sí tiene ese permiso aprueba o rechaza la solicitud desde una nueva pestaña Solicitudes, y al aprobarla la acción se ejecuta de verdad.
- **Un correo semanal de resumen** recoge lo que pasó en los proyectos de un workspace durante la última semana.
- **Puedes salir de un workspace, y un propietario puede transferirlo** a otro miembro, ambas cosas desde la configuración del workspace.
- **Guardar una nota en un workspace congelado abre la actualización a Enterprise.** Puedes seguir rellenando el editor; Crear nota lo cierra y muestra qué plan desbloquea las notas del workspace, en lugar de un aviso de error de plan.

### Red

- **Crear una aplicación dentro de un workspace ya no bloquea la publicación web como una función exclusiva de un plan** cuando el plan del propietario del workspace ya la incluye. El asistente buscaba el plan de una aplicación que todavía no existe, así que Enterprise (y Pro o superiores) se veía como Free en ese paso.
- **La publicación web se puede activar y desactivar después de crear la aplicación.** Una aplicación creada sin subdominio se quedaba privada para siempre; la única salida era volver a crearla. Desde la configuración **Red** de la aplicación ahora puedes publicarla y volver a dejarla sin publicar cuando quieras. Publicar sin un plan que te permita elegir el nombre te asigna un subdominio por la plataforma; con uno, lo eliges tú.
- **Al dejar de publicar, la dirección aparece en negrita**, y escribes `EXCLUIR` (o `DELETE` / `ELIMINAR`) en lugar del nombre del proyecto para confirmar. Elegir un subdominio personalizado en vertraweb.app se indica como la función de Scale en la configuración de Red: el aviso de bloqueo antes parecía bloquear toda la tarjeta de dirección.
- **Dos cosas que conviene saber antes de hacerlo.** Activar o desactivar la publicación **recrea el contenedor, así que la aplicación se reinicia**: cuenta con un breve tiempo de inactividad. Y dejar de publicar **libera el subdominio**: no se reserva para ti, así que otra persona puede registrarlo. Cualquier dominio personalizado asociado a la aplicación se desvincula al mismo tiempo.
- **Publicar necesita 512 MB de RAM**, el mismo mínimo que tiene un sitio creado como sitio. Si la aplicación tiene menos, la petición lo indica y muestra cuánta tiene y cuánta necesita, para que la subas y lo intentes de nuevo.
- **Purgar la caché de edge vuelve a funcionar.** El botón de la configuración **Red** nunca llegaba realmente a la CDN: la petición se rechazaba antes; y la versión de la CLI informaba de éxito mientras purgaba un nombre de host que no existe. Ahora la purga limpia los hosts reales de la aplicación, y aún puedes indicar nombres de host o URL concretos si quieres una purga más acotada.
- **Reemplazar un dominio personalizado ahora desvincula el anterior.** Asociar un segundo dominio dejaba antes el anterior, todavía apuntando a la plataforma y sin nada que lo gestionara. El reemplazo solo desvincula el antiguo cuando el nuevo ya está en su sitio, así que un fallo nunca deja la aplicación sin dominio.

Traductores, lectores de pantalla y buscadores recibían el idioma equivocado.

Las páginas que sí tienen imagen propia, como Precios y Enterprise, la generaban con la clave de texto sin traducir impresa en lugar del título real.

Producto y CLI/VS Code usan el mismo tamaño de tarjeta.

### Despliegues

- **Las dependencias ahora se instalan fuera de la memoria de tu plan.** Instalar y compilar se ejecutaba antes dentro del contenedor de tu aplicación, con un techo de memoria dimensionado para *ejecutar* tu app, no para construirla; `npm` por sí solo ya ocupa de 60 a 100 MB en reposo. Ahora la instalación ocurre en un contenedor de vida corta con memoria de la plataforma, y tu aplicación solo arranca cuando termina con éxito. Si falla, falla una vez con un motivo en lugar de entrar en bucle.
- **La consola muestra la instalación mientras ocurre.** Mientras se instalan las dependencias, el contenedor de la aplicación todavía no existe: antes la consola quedaba vacía y el proyecto parecía detenido. Ahora transmite en vivo la salida de la instalación, así que ver a `pip` compilar un paquete desde el código fuente es algo que puedes observar en lugar de adivinar.
- **Una instalación se puede interrumpir.** Mientras se instalan las dependencias, la única acción disponible es *Detener*: cancela la instalación en lugar de dejar un botón "Iniciar" para algo que ya está en marcha.
- **Guardar `requirements.txt` o `package.json` ya no congela el diálogo de reinstalación.** Confirma y se cierra; la carpeta se vacía y el reinicio reinstala en segundo plano, con la consola mostrando lo que ocurre. La carpeta que se vacía es ahora la correcta para el lenguaje: el paso posterior al guardado solo conocía Python y Node, así que pedir reinstalar en un proyecto de Go, PHP, Ruby o Rust no borraba nada. Editar `go.mod`, `composer.json`, `Gemfile` o `Cargo.toml` ahora también ofrece la reinstalación, y un `package.json` que está en un proyecto de Python ya no la ofrece por error.
- **Reiniciar una aplicación ahora conserva su log.** Los registros guardados solo contenían caídas: detener o eliminar una aplicación guardaba su log, pero reiniciar lo descartaba, y reiniciar es el gesto habitual. Lo que la aplicación dijo antes de un reinicio normal ahora se conserva como cualquier otra ejecución.
- **La instalación permanece en el log una vez terminada.** El contenedor de instalación se descarta al terminar, y su salida se perdía con él; ahora se añade al propio log de la aplicación y se reproduce con el historial, así que al recargar la página o reabrir la consola sigue viéndose qué hizo la instalación y, si falló, por qué.
- **Un proyecto que instala dependencias ya no aparece como "detenido".** El panel y la cabecera del proyecto muestran *instalando dependencias* mientras se ejecuta, tanto en la lista como dentro del proyecto.

### Ciclo de vida y API

- **Un proyecto detenido ya no aparece como roto.** Una aplicación o base de datos detenida no tiene contenedor, que es precisamente lo que hace detenerla, y pedir su estado respondía antes con un error de servidor. El panel lo trataba como una petición fallida y seguía mostrando la última lectura buena, así que un proyecto que acababas de detener seguía en pantalla como en ejecución, con el tiempo de actividad congelado, hasta recargar la página. El estado ahora responde con normalidad para un recurso detenido, con todo en cero.
- **Detener algo que ya estaba detenido ya no es un error.** Se confirma, y el estado registrado se corrige a detenido. Antes, una aplicación cuyo contenedor había muerto por su cuenta seguía marcada como en ejecución para siempre: el botón Detener fallaba siempre y no había forma de devolver el proyecto a un estado coherente.
- **Dos operaciones a la vez sobre el mismo proyecto ahora lo indican.** Iniciar, reiniciar, detener, eliminar, las instalaciones de dependencias, los despliegues y las restauraciones de snapshots se hacen de una en una por proyecto. Pedir una segunda mientras la primera sigue en marcha responde *hay otra operación en curso* y no cambia nada, en lugar de un fallo genérico que parecía que tu app se había roto. Espera unos segundos e inténtalo de nuevo. Por la API esto es HTTP `409 OPERATION_IN_PROGRESS`.
- **Pulsar Iniciar dos veces en una aplicación detenida (dos pestañas abiertas, un doble clic) ya no la reinicia dos veces en silencio.** Si la aplicación ya está en ejecución o arrancando, Iniciar responde *este proyecto ya está en ejecución o arrancando* en lugar de repetir en silencio todo el arranque. Por la API esto es HTTP `409 CONTAINER_ALREADY_RUNNING`. Pulsar Reiniciar dos veces seguidas también está cubierto: el segundo clic responde *hay otra operación en curso* en lugar de reiniciar la aplicación una segunda vez en silencio.
- **Reducir la memoria de una aplicación se rechaza cuando los archivos ya no caben.** El espacio en disco sigue a la memoria que asignas, así que bajar la memoria baja el techo. Aplicar un techo por debajo de lo que el volumen ya contiene no borra nada, pero hace que cada escritura posterior falle: la app se rompe al instante, por un motivo que nada en el panel explica. El cambio ahora se rechaza de antemano, indicando cuánto tienes que liberar primero.
- **Los botones de ciclo de vida comparten un solo presupuesto por aplicación.** Iniciar, reiniciar, detener e instalar dependencias permiten ahora diez peticiones por minuto y por aplicación entre todas ellas, en lugar de una cuota separada para cada una. El uso normal nunca se acerca a ese límite; un script en bucle se detiene antes de dañar el proyecto.

### Bases de datos

- **Las bases de datos tienen una pestaña Datos**, desde el plan **Intermediary**. Explora y edita lo que está realmente almacenado, sin salir del panel y sin pegar una cadena de conexión en ningún sitio. PostgreSQL y MySQL muestran esquemas, tablas, columnas, índices y un explorador de filas paginado; MongoDB muestra colecciones, índices y documentos; Redis muestra el espacio de claves, el valor de cada clave según su tipo, y su TTL. El plan que cuenta es el del **propietario de la base de datos**: los miembros del workspace usan la pestaña en una base de datos cuyo propietario tiene el plan.
- **Hay una consola SQL.** Se ejecuta contra tu propia base de datos con tu propio usuario, así que nada se filtra ni se reescribe. Lo que se aplica son los límites: 10 segundos por sentencia (aplicados por el propio motor), 200 filas por defecto y 1000 como máximo, 64 KB de SQL, 5 MB de resultado y una sola consulta de consola a la vez por base de datos.
- **Editar una fila siempre pasa por su clave primaria**, la completa, incluidas las claves compuestas, y nunca por su posición en la página. Lo mismo se aplica a los documentos (`_id`) y a las claves (la clave indicada en la URL).
- **Leer está abierto a todos los miembros del workspace; escribir y la consola SQL no.** Eso requiere ser propietario o admin, y cada cambio queda registrado en el log de actividad de la base de datos con la operación y el objeto, nunca con el contenido.
- La API expone la misma superficie bajo `/v1/databases/{id}/data/*`, con códigos de error estables documentados junto a ella.
- **Una base de datos en un workspace ahora muestra su RAM asignada.** Abrir una desde un equipo solía bloquear la visión general y dejaba vacío el campo de memoria, aunque la base de datos tuviera RAM asignada: a la lista de workspaces le faltaban esos campos. El desglose de RAM de Proyectos también la incluye.
- **Eliminar o restablecer una base de datos ahora toma primero un snapshot de seguridad, automáticamente.** Si la copia falla, la acción se bloquea y la base de datos no se destruye ni se vacía; antes, eliminar o restablecer no dejaba ninguna copia de seguridad.

### Checkout

- **Cambiar de plan en el checkout es un catálogo, no un desplegable.** El plan seleccionado sigue en el formulario; al abrirlo se muestran Economy, Pro, Scale e Intermediary como tarjetas (RAM, vCPU, límite de aplicaciones) y Enterprise como lista: el mismo catálogo de la página de precios, sin salir del pago.
