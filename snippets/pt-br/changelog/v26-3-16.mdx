### Campos de reinício automático removidos da API

O reinício automático está ativo para toda aplicação, em todos os planos, desde 17 de setembro. Os campos que restavam agora foram removidos:

- **Respostas:** as aplicações não incluem mais `auto_restart`. Se a sua integração lê esse campo, trate o reinício automático como sempre ativo.
- **Requisições:** `autorestart` em `POST /v1/apps` e `auto_restart` em `PATCH /v1/apps/{id}/config` não fazem mais parte da API. Clientes que ainda os enviam continuam funcionando, pois o campo é simplesmente ignorado.
- **SDKs e CLI:** os SDKs de JavaScript, Python e Go removem o campo, e a CLI remove a flag `--autorestart`.
- **`vertracloud.config`:** uma linha `AUTORESTART` antiga é ignorada e não bloqueia o upload.

### A versão de runtime escolhida é a que roda

A versão do runtime escolhida no assistente, em Configurações → Geral, em `VERSION` ou pela API é agora a versão que a aplicação executa.

- **Escolher a versão mais recente roda a versão mais recente.** Antes, escolher Node.js 24.5.0 ou Ruby 3.4 (o `latest` de cada um) podia, sem aviso, fazer a aplicação ser construída na versão recomendada.
- **A versão que você confirma prevalece.** Quando um `.zip` tem um `VERSION` em `vertracloud.config`, o assistente o preenche; se você escolher outra antes de criar, a aplicação agora roda a que você escolheu. Antes, o valor do arquivo podia sobrescrever a sua escolha.
- **Versões desconhecidas são recusadas.** Uma versão que não existe para a linguagem da aplicação responde `400 INVALID_VERSION`, em vez de cair silenciosamente em outra. Veja [Listar runtimes](/pt-br/api-reference/endpoint/apps/runtimes) para os valores válidos.

<Warning>
  Uma aplicação criada com Node.js 24.5.0 ou Ruby 3.4 que estava rodando na versão recomendada passa para a versão que escolheu no **próximo deploy, rebuild ou restart**. Se ela depende do runtime mais antigo, defina a versão como `recommended` em Configurações → Geral antes de reiniciar.
</Warning>
