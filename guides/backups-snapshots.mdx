A snapshot is a copy of an application or database at a given moment. You can restore it later or
download it as a `.zip`. Manual snapshots are available on every plan, with a daily limit per account that depends on the plan.

## When to take one

- Before a deploy that changes data formats or runs migrations.
- Before a database **Reset**, a large import or a bulk delete.
- On a regular schedule, if the data matters to you.

## Take a snapshot

<Steps>
  <Step title="Open the resource">
    Open the application or database and go to **Snapshots**.
  </Step>
  <Step title="Create it">
    Click **Create snapshot**. You can take one every 5 minutes per resource, and a number of them per day across the
    account that grows with the plan (8 on Starter 1, up to 200 on Enterprise); above that the request is refused with `SNAPSHOT_RATE_LIMITED`. Daily backups are automatic and don't count.
  </Step>
</Steps>

## Restore

Pick a snapshot in the list and click **Restore**. The resource goes back to the content it had at
that moment, so anything written after it is lost: take a fresh snapshot first if you may need the
current state. Restores have a 30-second cooldown between them. A damaged snapshot file is refused before anything
changes (`INVALID_ZIP_STRUCTURE`): the application's files and the running database stay as they were.

## Keep a copy outside the platform

**Download** any snapshot as a `.zip` and store it somewhere else. A download of an application
includes a `vertracloud.config` with its current settings, so it can be uploaded again as a new
project exactly as it was. Snapshots of any size can be downloaded. Downloading a very large project directly is refused with a clear message (`DOWNLOAD_TOO_LARGE`, above 300 MB of files): take a snapshot and download that instead.

## Automatic safety snapshot before deleting

Deleting or resetting a database always takes a snapshot first, and so does deleting an application,
on every plan. If that snapshot fails, the delete or reset is blocked (`SNAPSHOT_FAILED`)
and nothing is lost. The snapshot is kept for 30 days and can be downloaded from **Snapshots**.

## Automate it

Snapshots are also available through the [API](/api-reference/introduction), the [SDKs](/sdks) and
the [CLI](/cli), so a scheduled job (for example a [GitHub Actions](/github-actions) workflow with a
`schedule` trigger) can take them on a routine.
