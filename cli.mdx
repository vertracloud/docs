## Installation

The CLI is a single binary with no dependencies — no Node.js required.

<Tabs>
  <Tab title="macOS and Linux">
    ```bash
    curl -fsSL https://cli.vertracloud.app/install | sh
    ```
  </Tab>
  <Tab title="Windows">
    In PowerShell:

    ```powershell
    irm https://cli.vertracloud.app/install | iex
    ```
  </Tab>
</Tabs>

The installer downloads the latest release for your system and processor (x64 or ARM), verifies its
SHA-256 checksum and adds the `vertra` command to your `PATH`. Open a new terminal and check it:

```bash
vertra --version
```

To update, run the install command again. To install a specific version, set `VERTRA_VERSION`
(for example `VERTRA_VERSION=v0.2.0`) before running it. `VERTRA_INSTALL_DIR` changes where the
binary goes (default `~/.vertracloud/bin`, or `%USERPROFILE%\.vertracloud\bin` on Windows).

You can also download the binary for your platform directly from the
[releases page](https://github.com/vertracloud/cli/releases).

## Connecting your account

```bash
vertra auth login
```

Paste an API key created on the API keys page of the dashboard. In CI and scripts, set the
`VERTRA_API_KEY` environment variable instead — it takes priority over the saved key.

## First deploy

```bash
vertra doctor   # checks the project for problems before sending it
vertra deploy   # sends the current directory
vertra logs -f  # follows the application output live
```

Creating an application is asynchronous: when `vertra app create` (or `vertra app upload`) makes a new
application, the CLI waits for the build to finish and shows its result. Add `--no-wait` to return right after
the upload; the application keeps building in the background.

Add `--json` to any command for structured output ready for automation.

To give a deploy a message in the [deploy history](/guides/rollback-and-zero-downtime-deploys#what-a-release-is),
use `vertra app commit -m "fix login"`. Without `-m`, inside a git repository, the CLI uses the subject of
the latest commit.

## Releases and rollback

```bash
vertra app releases                      # versions of the linked application, newest first
vertra app releases log <release-id>     # log of a version that failed
vertra app rollback <release-id>         # go back to that version and restart
vertra app rollback <release-id> --env   # also restore its environment variables
```

Each command takes an optional application ID before the release ID; without it, the CLI uses the linked
application or lets you pick one. `releases` accepts `--page` and `--limit`, and shows which versions can still
be restored.

`rollback` is available from the Pro plan. Before it runs, the CLI shows what will happen and asks you to
confirm. With `--env`, it lists only the **names** of the variables that would be added, changed or removed,
never their values. Without `--env`, your current variables stay as they are. In CI, or anywhere without a
terminal, pass `--yes` (`-y`); without it the command fails instead of rolling back unasked.

Listing and reading logs need an API key with the `apps:read` scope. Rolling back needs `apps:write`, plus
`apps:envs` for `--env`.

## Blob Storage

```bash
vertra blob ls photos/                       # files and folders under a prefix
vertra blob put ./logo.png images/logo.png   # private by default; --public for a public URL
vertra blob put ./logo.png --rename          # if the name is taken, saves as logo-1.png, logo-2.png, ...
vertra blob put ./logo.png --overwrite       # replace the file already at that path
vertra blob get images/logo.png ./logo.png   # downloads through a temporary link; never overwrites
vertra blob link <object-id> --expires 600   # temporary download link (60 to 86400 seconds)
vertra blob rm <object-id> --yes             # delete by ID
vertra blob stats                            # usage against the plan quota
```

`get` accepts an object ID or the exact path. Large files are sent in parts automatically, with a progress bar.
Listing, downloading, links and usage need an API key with the `blob:read` scope; uploading and deleting need
`blob:write`. See [Blob Storage](/blob/overview).

## Deploy behavior

```bash
vertra app config <id> --zero-downtime auto    # auto | on | off
vertra app config <id> --auto-rollback on      # on | off
vertra app config <id> --health-path /health   # or --clear-health-path
```

- `--zero-downtime`: `on` needs the Enterprise plan.
- `--auto-rollback`: needs Intermediary or above.
- `--health-path`: starts with `/`, no spaces, up to 200 characters. `vertra app info` shows the current values.

See [Roll back and deploy without downtime](/guides/rollback-and-zero-downtime-deploys) for what each setting
does.
